Privacy & Data

What it does on your machine

Eas-Term is desktop software installed on your own computer. It doesn't require an Eas-Term account; AI and plugin services may require their own accounts and receive whatever content you hand them to process. It writes files to your machine, reads a few things you might not expect, and since 0.4.3 it also sends anonymous usage statistics (usage time and feature counts only, and you can turn it off). This page lists every one of those, including how to undo all of it.

The short version

  • No account, no device identifiers or user IDs of any kind, no crash reporting. Since 0.4.3 there is one anonymous usage statistic (usage time + feature counts, on by default, one click to turn off in Settings). It contains no identifier that could recognize you from one day to the next.
  • Local features and online services are kept separate. Speech recognition runs on your machine; AI chat, AI summaries and any plugins you enable may send relevant content to the service you chose. See the sections on networking and plugins.
  • It writes to your home directory, mainly so Claude Code / Codex know about the canvas. All of it can be undone in one click, and a backup is made before anything is written.
  • There is one thing it does without asking: registering itself as an MCP server. This is the only place it touches your global configuration without asking first, so we call it out separately.

1. Files it writes on your machine

1.1 Registering itself as an MCP server (the one thing it does without asking)

So that Claude Code / Codex can drive the canvas, the app adds an entry to these two files when it starts:

  • mcpServers["eas-term"] in ~/.claude.json
  • [mcp_servers.eas-term] in ~/.codex/config.toml

This step is silent. No dialog asks you first. We think that's an acceptable design, provided the following hold, and they do:

  • Visible: the app's "Extensions" panel lists every location it has written to.
  • Reversible: click "Remove" in that panel to uninstall it cleanly. Only our own entry is deleted; not a single character of your other MCP configuration is touched.
  • Backed up: before rewriting either file, it saves a .eas-backup copy.
  • Only written if you already have the CLI: if Claude Code isn't installed, ~/.claude.json is left alone; if there's no ~/.codex directory, Codex's config is left alone.

Also: the communication port and access token are not written into these config files. They are passed only through environment variables of terminals that Eas-Term itself opens, so the config entry contains no secrets, and the server only listens on the local loopback address (127.0.0.1), never on the open network.

1.2 Usage guide (written only when you click "Install")

The first time you open the app, it asks whether you want to install the "usage guide", a short set of instructions telling the AI "you're running inside a canvas, and here's when to open your output as a preview". It's written only if you click "Install". Click "Later" or "Never remind me" and nothing happens. If you install it, it writes to three places:

LocationContents
~/.claude/skills/eas-term/ (the whole directory)The guide: an always-loaded entry note plus several topic files (canvas operations, image generation, secrets, knowledge base). The AI reads a topic file only when it needs it
~/.codex/AGENTS.mdOnly a short routing section (a few hundred characters), wrapped in eas-term:begin/end markers. Anything you wrote outside the markers is left untouched
~/.eas/agent/ (the whole directory)Copies of the topic files above. Codex has no skills mechanism, so the content has to live here, with the routing in AGENTS.md pointing to it by path

Click "Uninstall" in the panel to delete all of it. A .eas-backup is kept before AGENTS.md is rewritten, too.

1.3 The "review on commit" hook (off by default, you have to turn it on)

This is the most invasive item, so it is not installed by default. You have to click "Enable" in the "Extensions" panel yourself. Once enabled, it adds an entry to hooks.PostToolUse in ~/.claude/settings.json and to ~/.codex/hooks.json.

About how often it fires, we need to be more precise than "it runs on commit":

It hooks into the Bash tool call. In other words, every time you have the AI run a shell command, in any project, our script is launched. Not just on git commits, and not just while you're using Eas-Term, until you uninstall it.

In practice it exits within a few milliseconds almost every time: the first thing the script does is check whether the command contains git commit, and if not, it stops right there. But you have a right to know it is invoked every time.

When it really is a git commit, here's what it does:

  • Reads: the code diff of that commit (added lines only), the glossary bundled with the app, and your own glossary.
  • Writes: docs/knowledge-data.json in the project (progress records) and docs/knowledge-manual.html (a glossary manual you can open directly).
  • No network: the script contains no network requests at all. Your code never leaves this computer because of it.

Only one sentence makes it into the AI conversation, something like "3 new terms added" or "found 2 terms not yet in the glossary". The raw code diff is never injected into the conversation, so it is never sent upstream to the model provider along with it either.

About cost: scanning and building the manual are purely local and use no tokens. But "let the AI fill in term explanations" needs the model to do work, which costs you money, so it's a separate switch, off by default. Installing the hook does not mean agreeing to spend money. We deliberately kept those two apart.

1.4 The app's own config directory ~/.eas/

  • dict-user.json: glossary entries you created yourself
  • dict-pending.json: terms found by the hook and waiting to be filled in (includes project folder names)
  • dict-sink.json: the fill-in switch mentioned above
  • roles.json: AI role configuration
  • agent/canvas.md: see 1.2

1.5 The secrets vault (if you enable it)

The secrets vault is meant for things like API keys and access credentials. It is not ordinary configuration, so we spell out separately where it's stored, how it's protected, and what it can't do.

  • <app data directory>/secrets.json: the encrypted secrets, their names, notes, variable names, and an scrypt hash of the six-digit code. File permissions 0600, directory 0700. It is not in ~/.eas/, because that directory is 0755 (readable by other users on the same machine).
  • The master encryption key lives in the system keychain (on macOS, the Keychain item Eas-Term Safe Storage; on Windows it goes through DPAPI, with the other half of the key in the Local State file in the same directory). So copying secrets.json to another machine won't decrypt it. We've tested and verified this.

What it promises: secrets won't appear in your conversations with the AI, won't be written to session logs (~/.claude/projects/*.jsonl), won't be uploaded to model providers, and won't end up in your shell history. When used, they're injected directly into the terminal's environment variables on your machine.

What it doesn't promise: "the AI can't read it". Once a secret is injected into a terminal, an AI running commands in that terminal can see it with echo $KEY. Nothing inside a process can be hidden from that same process. What we can do is not hand it over proactively, and explicitly forbid printing it in the rules we give the AI. We won't pretend to do what we can't.

A secret's value leaves the app's process on your machine in only two ways: injected into a terminal's environment variables, and copied to the system clipboard when you click "Copy" yourself. Neither goes over the network. Nowhere in the app is a secret's value ever sent to the internet.

1.6 Inside your project folders

The range of files the app can modify has a clear boundary: only project folders you've added to the sidebar yourself, and the knowledge base folder you've chosen yourself. Everything else (including your home directory, system directories, and sibling directories of other projects) is refused.

This boundary is enforced on real paths (symlinks are resolved), so dropping a shortcut inside a project that points elsewhere won't get around it.

Deleting a file always means "move to Trash", never permanent deletion (using the system Trash, so you can always get it back). Nowhere in the app is a file of yours truly erased.

2. What data of yours it reads

All of the following are read locally, discarded after use, never uploaded, and never cached to disk. But since they're not obvious, they have to be listed.

What it readsWhat for
~/.claude/projects/**/*.jsonl
(your full conversation history with Claude Code)		 The app's "conversation navigator" view, which lets you look back at what was discussed in this project. This includes images you've sent.
The file headers of ~/.codex/sessions/**/*.jsonl Only the first few KB are read, to get the session id and bind each terminal to its own session (so "resume last conversation" never picks up another terminal's)

This local history reading does not upload the original text to Eas-Term's servers; when you use content in an AI conversation or a plugin tool, the relevant content may be sent to the model or third-party service you chose. Either way, you should know about it, rather than find out on your own one day.

3. When it goes online

The app has no crash reporting. Network requests happen only in these cases:

Every 5 minutes, and on quit (anonymous usage stats) eas.biily.top Usage time and feature counts, with no identifiers. Turn it off in Settings and nothing is sent. Details in section 4.
The first time you click the microphone, if the speech model hasn't been downloaded yet hf-mirror.com Only downloads the model files; nothing is uploaded. If you never use voice, this never happens.

When the AI decides mid-answer that it needs to look something up (when using the built-in AI engine) The web pages it searches The search keywords. We don't handle it, keep it, or relay it. Once the data is there, Anthropic's terms apply. If you don't click that button, it never happens.

4. Anonymous usage statistics (on by default, can be turned off)

This section covers anonymous usage statistics, which are separate from the model requests, plugin calls and web browsing described above. There's only one goal: to know whether anyone is using it, and which features nobody touches at all.

What is sent

  • Usage time (a heartbeat every 5 minutes, plus one on quit) and launch count
  • The "active" portion of that time: every 15 seconds it checks "is the Eas-Term window in the foreground, and has there been any keyboard or mouse input system-wide in the last 60 seconds". If both are true, those 15 seconds count as active; the heartbeat carries only the number of active seconds for that period. It doesn't send "how long since the last input" itself, and it doesn't look at what you're doing in other apps. It only asks whether its own window is in the foreground. The point is to tell "open but idle" apart from "actually in use"
  • Version number, OS family (macOS / Windows / Linux), CPU architecture
  • Feature counts: how many terminals and canvas nodes were created, how many times voice was used, how many images were pasted, how many jumps from the Island, how many approvals were handled in the Island, how many view switches, and how many AI chat panels were created
  • A coarse usage-age bucket (first day / 2–3 days / 4–7 days / 8–30 days / 30+ days). The tally of "which day of use you're on" exists only on your machine (telemetry-age.json, which holds just three numbers: first day of use, number of active days, last active day). This file is never uploaded; only the bucket is sent. A bucket is not an identifier. Lots of people share the same bucket, so the server can't pick out any individual from it, and can't match someone today with someone yesterday.

What is never sent (not a single byte)

  • Any characters from the terminal: commands, output, errors
  • File paths, file names, project names, directory structure
  • Conversations with AI, prompts, model responses
  • Anything in the secrets vault, the clipboard, images you paste
  • Any identifier that could recognize you across days. The app generates no device ID and writes no cookies. Active user counts are estimated server-side from a "same-day IP + UA hash", which no longer matches the next day.
    The retention breakdown is obtained through the "compute locally, report only the bucket" approach above, and this rule hasn't been relaxed one bit: the server never has anything that could link you across days. It can see "how many returning users there are today", but not who they are.

How to turn it off

Settings at the far right of the title bar → Privacy → uncheck "Send anonymous usage statistics to help improve the app". Once turned off, no more anonymous usage statistics requests are sent (this doesn't affect your use of online features), and any counts collected but not yet sent are discarded on the spot.

This one is new: 0.4.2 and earlier had no such statistics, and this page said "no usage statistics" at the time. 0.4.3 added them, on by default. If you don't accept that, turn it off with the switch above. The changelog also calls this out on its own line; we don't intend to let it slip by quietly.

5. Knowledge base: will the AI touch your files?

Yes, but within a very narrow scope, and every time it needs your OK.

  • It only ever "moves"; it never deletes or rewrites your originals. Material in the inbox gets moved into sources/YYYY-MM/ for archiving. Name clashes get a suffix automatically; nothing is overwritten.
  • You have to confirm each item. The AI can only propose an archiving plan. The app then stops and waits for you to review it in the UI; only when you approve does anything actually happen. If you cancel, nothing is done.
  • It can be rolled back. If you've clicked "Manage with git", each archiving batch is a single commit and can be undone as a whole. Before rolling back, the current state is committed first, so nothing you've newly written gets lost. This git repository is never created automatically; you have to click it yourself.
  • Putting things into the inbox copies them by default rather than moving them, so your original file stays where it was.
  • How knowledge base content reaches the AI: only through one dedicated tool built into the app, and that tool is only visible in terminals Eas-Term itself opens. If you start Claude in the system terminal or another app, it can't even discover the tool exists, let alone read your knowledge base.
  • If you're done with it, "Unbind" just makes the app forget the location. None of your files are deleted.

5a. Third-party programs bundled with the installer

The app includes a ready-to-use built-in AI engine, Oh My Pi (open source, MIT licensed), so you can start chatting without installing anything. It ships with the installer and won't quietly download anything while you use it.

  • Its configuration, session history and credentials are all kept inside the app's own directory (app data directory/omp), and it doesn't touch any copy you may have installed yourself.
  • Login and keys are left entirely to it: when you click log in in the UI, it stores the credentials in its own database (in the app's own directory mentioned above), and renews them itself when they expire. We don't handle them, copy them, or write them anywhere else.
  • It connects to two places: the model provider you chose yourself (including checking your own account's quota), and, if the AI decides mid-answer that it needs to look something up, the web pages it searches. The latter is the AI's own decision, not something that happens because you clicked something. If you don't want that, turn on approvals in Settings (under "AI Chat") and it will stop and wait for your click before acting.
  • A quota snapshot is stored locally to show the progress bar. It does not contain your account email.
  • Its full third-party license notices ship with the installer, at Eas-Term.app/Contents/Resources/omp/THIRD-PARTY-NOTICES.txt.

6. Voice input and audio/video transcription

This is the part most easily misunderstood, so here's more detail.

  • Recognition runs entirely on your computer, using an open-source model that comes with the app. Audio is never uploaded and never written to disk. The recording exists in memory for a few seconds and is discarded after recognition; only the recognized text remains.
  • But the first use needs the network. The model files (about 300 MB) don't ship with the installer; they're downloaded the first time you click the microphone. After that it's fully offline. "Local recognition" and "never goes online" are two different things, and we want to be clear about that.
  • Audio and video dropped into the knowledge base inbox are transcribed automatically. It starts as soon as you drop them in, without asking again. It's likewise recognized locally, free, and offline. The transcript is stored in a hidden folder under the inbox and won't get mixed into your notes. In other words: the meeting recording you drag in really does get turned into text and saved by the app, but that text lives only on your own drive.
  • Microphone access goes through macOS system permissions, and you can revoke it any time in System Settings.

7. How to undo everything it wrote

The app has an "Extensions" panel (the one in the title bar) that lists every location it has written to on your machine, each with an uninstall button next to it:

  • Usage guide: click "Uninstall" to delete the three locations described in 1.2
  • MCP integration: click "Remove" to take our entry out of both CLI configs
  • Review-on-commit hook: click "Disable" to remove the hook entries
  • Knowledge base: shows the current location; "Unbind" doesn't delete files

Every operation that rewrites global config keeps a .eas-backup first. If you're really not sure, you can simply copy it back over the original.

What's left is deleting the ~/.eas/ directory and the app itself. Note: if you've used the secrets vault, deleting ~/.eas/ won't reach it. It lives in the app data directory (see 1.5), and the master encryption key is stored separately in the system keychain. Wiping it completely takes two more steps:

  • Delete secrets.json in the app data directory (on Windows, along with Local State)
  • Delete the Eas-Term Safe Storage item from the keychain (search for that name in macOS's Keychain Access)

The order doesn't matter, but it's only clean once both are gone. Delete just one, and the remaining half is undecryptable junk.

This page was written by checking each item against the code, not from a template. If you find anything here that doesn't match what the app actually does, that's our oversight, so please let us know. The app is open source, and you can verify every item in the code yourself.

9. About this website (separate from the app)

Everything above is about the app installed on your machine. It has no account, and local content is not uploaded as part of anonymous usage statistics; when you use AI or plugins, relevant content is sent to the services you chose, as described in section 3 and the plugin notes below.

But the website you're reading right now (eas.biily.top) keeps anonymous visit statistics, to know how many people have come by and which version they downloaded. This section spells out what it records and what it doesn't.

What it records

  • Page path and time on page, e.g. "someone spent 40 seconds on the download page"
  • Referring domain: the domain only; paths and query parameters are always dropped
  • OS family: at the level of macOS / Windows / Linux
  • Clicks on download buttons, and downloads that actually completed according to the server logs (which version, which platform)

What it doesn't do

  • No cookies, and no localStorage either. The session number lives only in sessionStorage and is gone when you close the tab
  • No persistent or cross-day identifiers of any kind. Unique visitors are computed on the fly on the server from a hash of "that day's IP + browser identifier", so the same person no longer matches the next day. There's no way to track whether you came by yesterday
  • No third-party scripts are loaded. The analytics code is a single file of a few KB on this site; there's no external analytics service
  • No collection of form input, no clipboard reading, no browser fingerprinting (no screen resolution, fonts, canvas and the like)
  • The statistics written to disk contain no raw IP addresses or browser identifiers, only aggregated counts

How to opt out

Turn on Do Not Track or Global Privacy Control (GPC) in your browser, and the analytics script does nothing at all. Not fewer fields; not a single request. Blocking /analytics.js with an ad blocker works too, and none of the website's features depend on it.

The server's raw access logs are deleted automatically after 90 days.

Remote plugins (integration capability in development)

Once you install and enable a remote plugin, that plugin's tool arguments and the necessary protocol messages are sent to the third-party service confirmed in its manifest, and its responses are received. Browsing the marketplace by itself does not call plugin tools or log in automatically. Don't pass data to a tool that you aren't willing to disclose to that service.

Remote networking uses the system proxy and checks HTTPS targets. Login credentials are not copied from other AI CLIs, and browser cookies are not forwarded to plugins. Cancelling or timing out only stops the local wait and does not guarantee the third party has stopped the operation, so tool requests that may perform writes are never replayed automatically.

Plugin-specific authorization storage uses system encryption and is subject to the local secrets vault lock; it is not written to AI CLI/PTY environment variables. For how configuration is injected into stdio plugin processes, see the next section. Access-token plugins send the token you configured in the app only to the exact confirmed service address; credentials from other clients are not copied. The target of the GitHub candidate connection is api.githubcopilot.com; it has not yet launched or passed real-account acceptance testing. Account authorization and the individual platform integrations are still in development and acceptance testing; seeing a marketplace entry does not mean that service is supported, logged in, or has passed real-account testing.

Wikipedia connector in development (not yet listed): only when you call its query tool does it send the query terms, article titles and language to Chinese or English Wikipedia. It does not send account credentials, cookies or project files. Direct connection and real upstream verification are not yet fully complete, and this does not mean it is live.

Web, weather and map plugins (in local development and acceptance testing, not yet released)

Once installed and enabled, you or the AI can call the plugin tools. Don't take this to mean a separate confirmation pops up every time it goes online. Merely browsing the marketplace does not run these queries. Real-account, vendor-response and cross-platform verification are not yet fully complete.

  • Web fetch (web-fetch): requests the public HTTPS URL in the tool arguments, including its path and query parameters, and follows at most 5 redirects, re-running the safety checks on each. It sends no browser cookies or login state, doesn't run page scripts, and is limited to 15 seconds and 2 MB. Don't put secrets in URLs; the target website can see the request.
  • Weather (weather): sends the city adcode, current-conditions or forecast type, and the AMap key you configured to https://restapi.amap.com/v3/weather/weatherInfo.
  • Maps (amap): sends addresses, keywords, GCJ-02 coordinates, query options and your AMap key to /v3/geocode/geo, /v3/place/around, /v3/direction/walking or /v3/direction/driving on https://restapi.amap.com.

Weather and maps do not fetch your device location automatically. As AMap's API requires, the key is placed in the HTTPS query parameters and sent only to the fixed endpoints above; redirects are not followed, and requests are limited to 15 seconds and 1 MB. Quotas, authorization and terms are determined by your account with the provider.

These three stdio connectors currently connect over HTTPS directly only and are not yet wired to the system PAC/proxy, unlike the proxy support of the main-process remote MCP described in the previous section. Non-public DNS results (including fake-IP reserved addresses) are rejected; connection failures can't be worked around by loosening the private-network guard.

The encrypted configuration is stored in plugin-credentials in the app data directory, subject to system encryption and the secrets vault lock. At startup, stdio configuration is injected into the corresponding plugin subprocess via EAS_PLUGIN_CONFIG, not into the AI CLI/PTY. The connector deletes the environment variable after reading it, but the required configuration still stays in memory at runtime. Plugins are local code you've allowed to run, not an OS sandbox, and cannot defend against malicious programs running with the same user's privileges.

Clearing the configuration or locking the vault closes the local connection. It is not the same as revoking your AMap key, and does not guarantee that queries already sent will stop. To revoke the key, do it in your account with the provider. The local file and Office document tools do not upload files themselves, but content returned to the AI may still be sent to the model service you chose.
