Why This App

先天优势：上下文不用问，环境变量直接给

一般 MCP 工具的痛点是"AI 不知道该操作哪个对象"，需要先 list 再 pick。这个 app 不用。

Eas-Term 的终端是自己 spawn 的（src/main/pty.ts），已经有成熟的环境注入机制——之前做 open 劫持时就用它把 shim 目录塞进了 PATH。同样的位置可以再塞几个变量：

PTY 创建时注入：
  EAS_TERM_PORT   = 43xxx        ← app 本地接口端口
  EAS_TERM_TOKEN  = <随机 token>  ← 防止别的进程乱调
  EAS_FRAME_ID    = frame-4-xxx  ← 这个终端属于哪个 Frame
  EAS_NODE_ID     = cnode-11-xxx ← 这个终端是哪个节点
  EAS_PROJECT     = /path/to/project

于是 AI 调用 open_html("./docs/report.html") 时，MCP Server 从自己进程的 env 里就知道该开在哪个 Frame、相对路径该按哪个项目根解析——零额外交互。

前提
这个优势只在「AI 跑在 Eas-Term 的终端里」时成立。如果你在外部 iTerm 里跑 Claude Code，它拿不到这些变量 —— 那时工具要退化成「开在最近活动的 Frame」或要求显式传 frame_id。

Architecture

架构：三种传输的取舍

核心难点在于——画板能力住在渲染进程的 zustand store 里，而 MCP 客户端是外部进程。中间要架一座桥。

Claude Code / Codex
     │ MCP (stdio JSON-RPC)
     ▼
eas-mcp (薄 server，官方 SDK)
     │ HTTP + token，127.0.0.1
     ▼
Electron 主进程 (新增 src/main/mcpBridge.ts)
     │ ipc: mcp:invoke → 等 mcp:result
     ▼
渲染进程 zustand store (addWebNode / tidyFrame / ...)
方案做法优点代价评价
A · 薄 stdio + app REST 独立 node 脚本用官方 MCP SDK，转发到 app 的本地 HTTP 协议由 SDK 保证正确；stdio 是 Claude/Codex 最通用传输；app 侧只需实现简单 REST 多一个进程；要生成 MCP 配置 推荐
B · app 内嵌 HTTP/SSE MCP 主进程直接实现 MCP over HTTP 零额外进程 要自己实现 MCP 协议细节（initialize/tools/list/call、SSE 心跳），易踩坑 次选
C · 文件队列 像现在的 open shim 那样写文件、app 轮询 最简单，已有先例 没有返回值、没有错误处理、不是真 MCP 不用

配置怎么落到 Claude / Codex

app 启动时把 MCP 配置写进项目的 .mcp.json（Claude Code 会自动读取项目级配置），或者提供一个「复制 MCP 配置」按钮。配置里指向 app 内置的 server 脚本路径 + 当前端口/token。

Boundaries

安全边界：哪些绝对不能开放

MCP 一旦开放，AI 就能自主调用。有些能力给出去等于把方向盘交出去。

明确不开放
  • pty.write / 向终端写入 —— AI 能给自己或别的终端灌命令，等于绕过所有确认，最危险
  • git:resetHard —— 破坏性且不可逆，必须留在人工确认弹窗后面
  • fs:trash / fs:rename —— 文件操作 AI 本来就有自己的工具，没必要再给一条旁路
  • removeFrame —— 会连带杀掉一整个项目的所有终端进程
  • projects:remove —— 影响全局配置
  • stt / 麦克风相关 —— 隐私设备，只能用户主动触发
必做的三道锁
  1. 只监听 127.0.0.1 + 随机端口，不对外
  2. token 校验：随机 token 写进 userData，只通过 PTY env 注入给 app 自己起的终端 —— 外部进程猜不到
  3. 路径白名单：open_file/open_html 只允许项目目录内的路径，防止把 ~/.ssh/id_rsa 渲染出来

另外建议加一个可见的开关：标题栏一个小指示灯，显示「MCP 已连接 · N 次调用」，让你随时知道 AI 在动画布，也能一键断开。

Roadmap

分期落地

每期都是可用闭环，不做到一半晾着。

P1 · 最小闭环
预览三件套 + 通知 + 列 Frame
main 加 mcpBridge.ts（HTTP + token + ipc 往返）· PTY env 注入 4 个变量 · 内置 eas-mcp stdio server（5 个工具）· 自动写 .mcp.json。约 400 行，无新依赖（MCP SDK 可选，也能手写 stdio JSON-RPC）。
P2 · 操作类
整理 / 聚焦 / 最大化 / 开终端 / 重命名 / 读状态
纯粹在 P1 的桥上加工具映射，每个 ~15 行。同时加标题栏 MCP 指示灯与开关。
P3 · 让 AI「看见」
画布截图回传 · 设计模块导出 · 便签批注
截图让 AI 能自查产出效果（"我生成的报告在画布里长这样"），是质变但也最贵。
