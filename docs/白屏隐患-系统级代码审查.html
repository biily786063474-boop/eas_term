一句话结论

白屏的机制是:项目既没有 React Error Boundary,主进程也没有 uncaughtException 兜底,更没有渲染/GPU 崩溃后的自动重载——三道安全网全缺。于是任何一处局部异常都会被放大成"整屏白且永不自愈"。

最可能的扳机有三条独立路径,任一命中都足以白屏:
① 在刚退出的终端里继续敲字 → pty:write 裸写已关闭 fd 抛 EPIPE → 主进程退出;
② 多终端连续缩放画布 → 每帧对每个终端重复 fit → GPU canvas 反复重分配 → GPU 进程 OOM;
③ 一份"能解析但成员畸形"的 canvas.json → 渲染期 f.nodes.length 抛错 → 因启动即进画布模式,每次开机都白、且订阅未挂无法覆盖坏档 → 永久打不开。

关键实据:你机器 ~/Library/Logs/DiagnosticReports 里零条 Eas-Term 崩溃报告 → 白屏不是原生段错误,而是 JS 层异常把 React 整树卸载,与"缺 Error Boundary"完全对应。另:你正式 app 的 canvas.json 里 agent 仍是旧字符串结构 → 你在跑的是旧构建,此白屏是它本就有的老隐患,与本次 Codex 改动无关。
