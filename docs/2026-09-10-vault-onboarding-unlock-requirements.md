# 2026-09-10 密钥柜首次引导与就地解锁

## 用户补充
当需要解锁密钥柜时，不要让用户自己翻找位置；直接弹窗让用户解锁，解锁后继续使用。
首次使用密钥柜、首次索要凭证、或 Agent 首次请求用户创建凭证时，如果尚未启用密钥柜，要先创建密钥柜的解锁密码。
首次显示一段说明，解释密钥柜的用途；随后不重复展示。
视觉沿用最近两天已落地的密钥柜/设置界面风格。

## 拟定交互
- 所有入口共用初始化/解锁状态，不为每个 Agent 各设一遍密码。
- 尚未配置：首次介绍 → 设置解锁密码并确认 → 成功后继续原来的创建/授权/使用请求；取消不记为完成。
- 已配置但锁定：直接打开解锁弹窗；不要求跳到标题栏找密钥柜，不重新新建已有凭证。
- 已解锁：已有有效授权继续取用；未授权只确认使用范围；确实缺失才创建。
- 解锁不等于授权全柜，创建解锁密码不等于创建 API key。
- 保留错误退避、单弹窗、防骚扰及取消；请求绑定真实会话与进程代次，退出/重启后的迟到确认不能误授权。
- 沿用现有 UI 字体、间距、背景、边框、强调色与按钮体系，不引入汇报页 report 样式。

## 首次文案草案
密钥柜用于在本机加密保存 API Key、访问令牌等凭证，省去反复填写。需要时，你可以授权当前 AI 会话使用指定凭证，无需把密钥粘贴进聊天。
先设置一个解锁密码。以后密钥柜锁定时，输入它即可继续。解锁密码用于打开密钥柜，不是服务的 API Key。
安全边界：应用不主动把密钥正文返回给模型；执行命令时仍须避免打印凭证或输出包含鉴权信息的日志。
