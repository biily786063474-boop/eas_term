Gap 01

CSS 静默覆盖 —— 唯一正在造成返工的

同一个类在同一个文件里定义两次，后面那个赢。改前面那个没有任何反应， 也没有任何工具会告诉你为什么。

文件重复选择器典型间距
canvas.css（5249 行）10 个
.agentbar / .crm-mini / .re-tools / .rm-primary …		.agentbar 两处相隔 2141 行
agentChat.css（1450 行）3 个
.ac-bar-send / .ac-gauge-row / .ac-quota		.ac-bar-send 相隔 510 行
workspace.css（2490 行）3 个—
其余 5 个文件8 个—

今天的两次现场

现场一：发送键整个消失

把发送键从「绝对定位钉在右下角」改成「文档流里的工具条」，新样式写在文件末尾。 旧的 position:absolute 那份没删，它排在后面反而生效 —— 于是发送键和麦克风叠在同一个位置（实测相差 2px），加上 opacity:.4， 视觉上就是「按钮不见了」。 

/* 第 197 行 · 旧 */
.ac-input-send { position:absolute; right:8px; bottom:8px; border:1px solid … }

/* 第 1376 行 · 新（我写的）*/
.ac-input-send { border-radius:50%; border:none; … }
   ↑ 侥幸：我恰好写了 border:none 才盖住旧的边框。漏写就留着旧值。

现场二：.ac-bar-send 至今仍是两份

第 882 行那份带 border:1px solid rgba(...)，第 1392 行我新写的用 border:none 覆盖掉了。这次没出事纯属运气 —— 这种「靠后写的完整重定义盖住前面的」结构，每加一个属性就是一次赌博。

注意要和 .agentbar 那种区分开：它第二处只有一行 border-bottom:none，是有意的补充，不是重定义。检查脚本要能分辨。

该补的规范

GR-CSS-DUP

扫描每个 .css，找同一文件内定义两次以上的顶层类选择器。 只有「两处都定义了 3 个以上属性」才算 FAIL（完整重定义）， 后者只补 1–2 个属性的放行（有意的补充）。

错误信息按 CCteam 的标准写成 agent 可读的形式： 

[GR-CSS-DUP] .ac-bar-send 在同一文件里被完整定义了两次
  File: src/renderer/src/features/agentChat/agentChat.css:882 和 :1392
  FIX: 后面那处（1392）是生效的。把 882 那处删掉，
       并逐条确认它的属性都已在 1392 覆盖 —— 漏一条就会留着旧值。

Gap 02

142 处教训，只有 22 处变成了测试

项目里到处是「历史教训」「实测确认」「白排查过一轮」这类注释 —— 这是好习惯，说明每个坑都被记下来了。问题是它们绝大多数停在注释层面， 下一个人（或下一个我）读不到那一行就会再踩一次。

教训注释总数
142
其中有自动化测试兜底
22 / 15.5%
今天就重复踩了一个

「子元素 position:absolute; inset:0，父容器必须有定位祖先」这个坑， 项目里已经有一段很详细的注释记录（canvas.css 的 .skl-item-tree， 讲 FileTree 的 .filetree-body 会一路向上找定位祖先、飞到抽屉外面）。

今天做灯箱时，CodeMirror 用同样的方式铺满了整个屏幕、盖住标题栏， 表现是「右上角关闭键点不动」。同一个坑、不同的组件、隔了几个月， 而那段注释救不了我 —— 我没在写灯箱时去读文件树的注释。

CCteam 给的解法：不变量优先

反复出现的 Bug 应从 Known Pitfalls 提升到 docs/invariants.md， 然后转化为自动化测试。Reviewer 是第二道防线；自动化测试是第一道。 —— CCteam-creator SKILL.md，Team-Lead 运营指南
该补的规范

建 docs/invariants.md，收录「踩过两次以上」的坑（不是所有 142 条）。 每条三段式：不变量是什么 / 违反时的症状 / 用什么检查它。 

## INV-01 · 内含绝对定位子元素的容器必须自带定位

不变量  任何要装 CodeMirror / FileTree / xterm 的容器，自身必须
       position:relative（那些库内部是 absolute; inset:0）
症状    子元素一路向上找到最近的定位祖先（常是 position:fixed 的遮罩），
       铺满整个屏幕，盖住本该在上面的东西。表现为「某个按钮点不动」，
       而元素本身在 DOM 里、样式也正常 —— 只有命中测试查得出来
现场    2026-05 FileTree 飞出抽屉 · 2026-08-19 CodeMirror 盖住灯箱标题栏
检查    scripts/check-invariants.mjs 扫 .css，凡是选择器里出现
       .flb-body / .skl-item-tree / .wk-tree 这类已知宿主，
       必须能在同一规则块里找到 position: relative

起步只需要 3–5 条。判据是「踩过两次」 —— 只踩过一次的写注释就够了， 收进不变量会让这份文件迅速膨胀成第二个 CLAUDE.md，然后没人看。

Gap 03

质量门没有串起来

typecheck 和 test 两条命令都在 package.json 里， 但没有任何东西强制它们在提交前跑。CI（build.yml）只做 Windows 打包 + 冒烟。

关卡现状今天漏掉的东西
tsc 有 手动跑 抓不到 TDZ：cliMenuItems 引用了声明在它之后的 selected，同作用域内 tsc 不报，运行时整个组件被 ErrorBoundary 吃掉，表现是「点新建 AI 对话没反应」
eslint 没有 上面那个 TDZ，no-use-before-define 一条规则就能拦住
test 有但报告不醒目 一个测试文件因 import 少写 .ts 整体加载失败，npm test 只报「1 个文件失败」，28 个测试一个没跑，我看成 651/652 就把提交发出去了
CI 只构建 以上全部
该补的规范

一条命令 npm run check，把四件事串起来，CI 和提交前都跑它：

1. golden_rules.py（排除 design/composer）  → 文件大小 / 密钥 / 文档新鲜度
2. check-css-dup.mjs                       → Gap 01
3. check-invariants.mjs                     → Gap 02
4. tsc --noEmit ×2 + node --test            → 已有，只是没串进来

退出码 0 = 全绿，1 = 有 FAIL。所有错误信息带 FIX 指令。

CCteam 关于这个脚本有一句话值得照抄： 「骨架在项目启动时不需要完整——它随项目一起成长。但文件必须从第一天就存在， 否则之后没人会去创建它。」

顺带修一个小的

node --test 在文件级加载失败时，汇总行只体现为「1 个文件失败」， 看不出那个文件里有多少测试没跑。在 check 脚本里对比「实际跑了多少测试」和 「测试文件数 × 历史均值」，数量骤降时明确报出来 —— 这次是我肉眼发现的， 下次未必。

Not Applicable

CCteam 里不该搬进来的部分

它是为「一个 Claude Code 会话里 spawn 多个子 agent」设计的。Eas-Term 是 「画布上并列多个独立 CLI 进程」。这不是同一个东西的两种实现，是两个层级。

CCteam 的机制搬不搬理由
不变量优先（坑 → invariants.md → 测试） 搬 见 Gap 02，本项目 142 处教训只有 15.5% 有测试兜底
agent 可读的错误信息（带 FIX 指令） 搬 你的检查脚本都是给 AI 看的，写成人话不如写成可执行指令
run_ci.py 单一入口 搬 见 Gap 03
假设审计（定期删掉不再触发的机制） 记着 现在还没有足够多的机制值得审计，但这个思路要留着 —— 你的 CLAUDE.md 已经在膨胀
.plans/ 文件化规划（每 agent 一目录、findings 只当索引） 观望 你的 memory/ 是扁平的一堆 md，查得到但没有「这个任务到哪一步」的结构。先用 CCteam 跑一个真项目再决定，没跑过就重构容易搬错东西
六个角色分工 + custodian 不搬 你是一个人 + 若干 CLI 会话，不是一个团队。角色分工解决的是「多个 agent 之间怎么不打架」，你的画布用进程隔离解决了同一个问题，而且更彻底
TeamCreate / spawn 子 agent 不搬 硬搬等于用画布重做一遍子 agent，反而丢掉画布的优势（独立进程、看得见、能单独关、各有各的额度）。CCteam 应该跑在 Eas-Term 的一个终端节点里，不是被 Eas-Term 吸收
