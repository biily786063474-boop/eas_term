核心裁决

图纸最值钱的部分不是架构结构图，是三张"反直觉清单" —— 它们无法从代码结构推导，只存在于注释和事故史里：跨文件同步清单、历史修复区、静默失效区。AI 改代码时踩的几乎全是这三类，而不是"不知道模块关系"。

保留的分歧

canvas 是"违章建筑"，图纸只记录未纠正。 features/canvas/CanvasContextMenu.tsx 被 canvas 之外的 6 个 feature 依赖 —— agentChat / workspace / terminal / files / git 用菜单组件本身，gantt 只用它导出的 useMenuAnchor / useDismiss（四个导出都是对外 API，动哪个都得全量 grep）。它本该在 ui/。canvas ↔ workspace 还是双向依赖。

图纸的立场是：先如实标注风险，不在出图纸这次顺手重构。把它挪进 ui/ 是正确方向，但那应该是一次独立的、有验证的重构。

出站的准确口径：上面 4 条是常驻/自动发起的。另有两条只在特定动作下才走：
· 首次用语音识别 → 从 hf-mirror.com 下模型到 userData/models（模型不随包发，省约 300MB 包体）
· 未装笔纵画板时点安装 → 取 bzone.biily.top/version.json 拿安装包直链，失败就退回官网
口径写死在这里是为了「加端点必须改图纸」这条红线有得可比 —— 数不对就没法比。

手机那条不是只读：READ_ONLY 已于 2026-08-29 按用户要求关掉（server.ts）。
手机可以新建对话节点、给会话发消息，首条消息还会顺带把 CLI 进程拉起来。
这是有意开的，别当 bug 改回 true —— 逐次人工确认那道闸假设你够得着电脑，而这功能就是为够不着时用的。
真正的护栏是四层：配过对 · 动作白名单 isAllowed · 每次留痕 audit · 写动作边界只在渲染层 provider 判一次。

五条边界红线

  • 隧道绝不终止 TLS —— hub.test.ts 断言手机拿到的证书指纹等于电脑那张
  • 手机服务端绝不绑 0.0.0.0
  • MCP 桥三道锁：只听 127.0.0.1 · 随机 token 经 PTY env 注入（同时明文落 mcp-endpoint.json，0600）· 路径白名单
  • 不得新增网络出站端点
  • 生图路径只有笔纵画板一条（illustrator 角色 deny 通配符钉死）

密钥的真实边界（别误传）

密钥经 pty.ts 注入为环境变量 → 同进程内任何命令（含 AI）echo $KEY 就能读到。

承诺的是：不进对话、不进 jsonl、不进 shell history。没有承诺"AI 读不到"。

文件型密钥（SSH key / .p8 / .pem）不进环境变量，走 eas-secret run --files：临时落 0600 文件，用完即删。

fsGuard 是 IPC 侧唯一的路径白名单（MCP 的 canvas_open_file / open_html 另有一套，在 mcpHandler.ts 里，两者互不知道对方存在），而且它只覆盖写操作。fs:readDir / readTextFile / readImageFile / openPath / showInFolder 零路径校验，理论上能读取或在 Finder 打开任意绝对路径。

这是"读比写风险低"的设计取舍，不是遗漏。但要改成有边界时别当成新功能随手加 —— 先确认不会打断"拖任意文件进画布预览"这类既有用法。

普通后端项目没有这张图。对本项目它是产品能力的核心目录 —— 33 个自有工具 + 画板 52 个（数量的唯一真相源是 mcp/eas-mcp.mjs 的 TOOLS 数组，别信任何一处手抄的计数）。

进程模型（容易误传，钉死）：
shim 是每会话一个（MCP 协议天然行为），但共享同一个 HTTP 网关。
多会话 = 多个轻量 shim + 一个共享后端，不是每会话一套后端。
例外：bizone-canvas 真的每会话一个进程（ELECTRON_RUN_AS_NODE），实测每客户端增量约 93MB。

三道锁

  1. 只监听 127.0.0.1
  2. 随机 token 经 PTY 环境变量注入给 App 自己起的终端 —— 没有这两个变量时 tools/list 返回空工具面，对外无感。但不是「只经 env」：同一个 token 还明文落在 userData/mcp-endpoint.json（0600），所以它是「本机同用户可读」级别，不是每终端独有的密钥
  3. canvas_open_file / open_html 有项目内路径白名单（防渲染 ~/.ssh）

三层超时 · 不等式必须成立

③ 渲染层等待窗口—8min

四条耦合警报

1 CanvasContextMenu 是违章建筑

被 agentChat / workspace(3处) / terminal / gantt / files / git 六个 feature 当通用右键菜单用。

它本该在 ui/，实际长在 canvas 里。动手前先 grep -r CanvasContextMenu src/renderer。

2 canvas ↔ workspace 双向依赖

canvas → workspace（projectMenu.ts）；workspace → canvas（大量）。canvas 还依赖 editor / web / status / files，并经 registry 依赖 git / team / design。近似循环依赖。

3 PaneView 是面板路由中枢

import 了 terminal / editor / image / git / chat / agentChat / web / canvas 八个 feature。新增面板类型必须改它，且编译器不会提醒。

4 layout.ts 共享 leaf 契约

PaneKind 的 leaf 在 split / canvas / board 三种 ViewMode 间共享同一份实例 —— 绝对定位保证 xterm 永不重挂载。任何导致重挂载的改动都会丢终端会话。
