# 快捷键盘点与规划

> 摸底结论先行：**这个 app 目前几乎没有功能快捷键**，而且现有的那几个**在默认视图下是失效的**。
> 要做「设置里可配快捷键」，得先有一份注册表 —— 现在没有，键都散在 34 个组件的 `keydown` 里。

## 一、现状盘点

### 1. 主进程：零快捷键

| 机制 | 数量 |
|---|---|
| Electron 菜单 `accelerator` | **0** |
| `globalShortcut`（全局热键） | **0** |

意味着：没有菜单栏快捷键，也没有「app 不在前台也能触发」的键。

### 2. 全局层：只有 5 组，且**只在分屏模式生效**

`src/renderer/src/App.tsx` 里挂了一个 `window.keydown`：

| 键 | 功能 |
|---|---|
| `⌘T` | 新终端 |
| `⌘W` | 关闭当前面板 |
| `⌘D` / `⇧⌘D` | 右分屏 / 下分屏 |
| `⌘1`–`⌘9` | 切到第 N 个标签 |

⚠️ **但它开头有一句 `if (s.viewMode !== 'split') return`** —— 画布 / 看板 / 甘特图三种视图下，
这 5 组键**全部不工作**。而画布是默认视图。

这不是纯粹的 bug：画布自己占用了 `⌘D`（复制选中），直接放开会撞车。但结果是
「用户在默认视图下按 `⌘T` 没反应」，体验上说不过去。**这条需要你拍板**（见第三节）。

### 3. 画布：4 个键

| 键 | 功能 |
|---|---|
| `Delete` / `Backspace` | 删除选中（两个都认 —— Mac 键盘上写着 delete 的那个发的是 Backspace） |
| `⌘D` | 复制选中 |
| `F` | 把画面聚焦到选中内容（fit + 居中） |
| `Space` | 按住临时平移 |

### 4. 其余 34 个文件：都是局部交互键

`Enter` 确认、`Escape` 关闭、`↑↓` 导航、`Tab` 补全 —— 这些是**组件内的交互**，
不是「功能快捷键」，不该进快捷键设置界面，也不该允许改键。

### 5. 没有注册表

键写死在各组件的 `keydown` 回调里。**没有任何地方能列出「这个 app 有哪些快捷键」** ——
这正是做设置界面的第一道坎：界面要渲染列表，得先有数据源。

### 6. 设置面板：分区机制现成

`SettingsPanel.tsx` 已有 8 个分区（主题 / AI / 提示音 / 更新 / 看板 / 手机 / 性能 / 隐私），
用 `cset-tabs` 渲染。**加一个「快捷键」分区是顺理成章的，不用改架构。**

## 二、缺口：有按钮、没有键

以下功能都有明确的 UI 入口，但敲不出来。按我判断的价值排序：

| 优先级 | 功能 | 现在怎么触发 | 建议键 |
|---|---|---|---|
| 高 | 切视图：分屏 / 画布 / 看板 / 甘特图 | 顶栏下拉 | `⌘1`–`⌘4`？（与「切标签」冲突，见下） |
| 高 | 新建 AI 对话 | 画布工具栏 | `⌘J` |
| 高 | 新建终端（**画布模式下也要能用**） | 画布工具栏 | `⌘T` |
| 高 | 打开设置 | 顶栏 | `⌘,`（各家通用） |
| 中 | 整理排列（模块按大小对齐） | 画布工具栏 | `⇧⌘O` |
| 中 | 抽屉开关：文件信息 / 知识库 | 左右边缘标签 | `⌘B` / `⇧⌘B` |
| 中 | 辞典 / 密钥 / 额度 | 顶栏 | `⌘K` 系列或留给命令面板 |
| 中 | 画布工具切换：选择 / 矩形 / 箭头 / 批注 / 待办 | 底部工具栏 | 单字母 `V` `R` `A` `N` `T`（Figma 惯例，画布内无输入焦点时） |
| 低 | 缩放：放大 / 缩小 / 适配 | 右下角 | `⌘+` / `⌘-` / `⌘0` |
| 低 | 新建浏览器节点 | 画布工具栏 | — |

## 三、需要你拍板的三件事

**① `⌘T` 等键要不要在画布模式下生效？**
- A：生效。画布下 `⌘T` = 在当前 Frame 里开终端（语义自洽），`⌘D` 保持画布的「复制选中」不动，
  `⌘W` = 关闭选中节点。**我倾向这个。**
- B：维持现状，画布模式就是没有这些键。

**② `⌘1`–`⌘9` 是「切标签」还是「切视图」？**
两者都想要的话得错开，例如 `⌘1-9` 切标签（现状）、`⌃1-4` 切视图。

**③ 单字母快捷键（`V`/`R`/`A`）要不要做？**
画布上敲单字母很顺手（Figma 那套），但要小心：便签、Frame 改名、终端都是输入场景，
必须在有输入焦点时全部让路。现有的 `F` 键已经是这个模式，可以照抄它的判断。

## 四、实施分期

### 一期 · 建注册表 + 设置里能看（不改键）

1. 新建 `src/renderer/src/shortcuts/registry.ts`：一份 `{ id, 中文名, 分组, 默认键, 作用域 }` 的数组。
   **作用域**很关键：`global` / `split` / `canvas` / `board` —— 现有的「只在分屏生效」就是作用域概念，
   把它显式化，而不是散落在各处的 `if (viewMode !== 'x') return`。
2. 把 App.tsx 与 CanvasStage 里现有的键**迁移**到注册表驱动（行为不变，只是数据外移）。
3. `SettingsPanel` 加「快捷键」分区，按分组渲染注册表 —— **只读**，先解决「看得见」。

一期做完就有了「这个 app 有哪些快捷键」的唯一真相源，也是二三期的地基。

### 二期 · 补绑定

按第二节的表补，每补一个都要过一遍冲突检查（注册表能自动查重）。

### 三期 · 支持改键

设置里点一行 → 录一个新组合 → 存 `prefs`。需要处理：冲突提示、恢复默认、
「系统已占用」的组合（如 `⌘Q`）要拒绝。

## 五、坑

- **`⌘W` 有歧义**：现在是「关面板」，但在很多 app 里是「关窗口」。用户按下去要是把整个窗口关了会很恼火 —— 迁移时确认现有实现只关面板。
- **单字母键与输入焦点**：抄 `CanvasStage` 里 `F` 的判断（输入框 / textarea / contentEditable 一律放行），别自己写一遍。
- **`Delete` 与 `Backspace` 都要认**：Mac 键盘上写着 delete 的键发的是 Backspace，只认 Delete 会导致「按删除键没反应」，这个坑代码注释里记着，别在重构时丢掉。
- **改键存哪**：`prefs`（走 `window.api.prefs`），不要新开一个 JSON —— 图纸里「每类数据独立文件」说的是新类别，快捷键属于偏好。
