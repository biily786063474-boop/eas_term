MCP 接入测试怎么跑

Claude / Codex 现在能直接操控画板：开预览、聚焦、最大化、整理、贴便签、发通知。 这页是给你自己验收用的 —— 每条都写清「说什么话」和「应该看到什么」。

日期 2026-07-26 工具数 13 个 验证方式 开发版 + 真实 MCP 协议 分发 零配置，app 内自动生效 状态 代码全通，等你人工体验

Verdict

先看这一句

你不用配置任何东西。在 Eas-Term 的终端里起 Claude Code，工具自动就在。

核心机制

端口和令牌由 app 在创建终端时注入环境变量，MCP server 因此天然知道 「我在哪个终端 → 属于哪个 Frame → 相对路径该按哪个项目解析」。 所以 AI 不需要你告诉它 frame id，产出直接开在它自己所在的 Frame 里。

Setup

开始之前：两步

测试必须在 Eas-Term 自己的终端里进行 —— 外面起的 Claude Code 拿不到注入的环境变量，工具会报「未检测到 Eas-Term 环境」。

第一步
启动开发版
项目目录下 npm run dev。（我没有打包——你没说打包）
第二步
在 app 内的终端里起 Claude Code
画布模式任一终端节点，或终端模式任一标签页，输入 claude 回车。 起来后打 /mcp 应该能看到 eas-term 已连接、13 个工具。
如果 /mcp 里没有 eas-term

包装脚本是在第一次创建终端时装的。如果 app 刚装好就打 claude 可能还没装上， 关掉这个终端重开一个即可。检查：command -v claude 应该指向 ~/Library/Application Support/Eas-Term/bin/claude。

Checklist

逐项测试：说这句话 → 该看到什么

直接把左栏的话说给 app 里的 Claude 听。右栏是判定标准，不符合就是 bug。

对 Claude 说应该看到验过没
「把 docs/MCP-测试清单.html 在画板里打开」 自动切到画布模式，当前 Frame 里多出一个浏览器节点，显示的就是这一页 代码已验
「读一下画板现在什么状态」 它能报出每个 Frame 名字、里面有几个模块、都是什么类型（终端 / 浏览器 / 代码 / 设计），以及它自己在哪个 Frame 代码已验
「把刚才那个预览最大化，我要仔细看」 该节点铺满整个画布视口（沉浸模式） 代码已验
「还原」 退出沉浸，回到画布里原来的位置和大小 代码已验
「把这个预览重命名成『测试清单』」 节点标题变了，左下角缩略图上的名字也跟着变 代码已验
「整理一下这个 Frame」 模块按大小从左上角流式重排，重叠和空隙消失（等同你手点「整理」按钮） 代码已验
「贴张便签：明天要改 XX」 Frame 右侧外边出现一张便签，写着这句话；再贴一张会自动往下排，不重叠 代码已验
「新开一个终端」 Frame 里多一个终端模块。它只开不打命令——留给你自己跑 代码已验
「聚焦到那个终端」 画布视口移过去并选中它 代码已验
「把刚才开的预览关掉」 预览节点消失 代码已验
「把那个终端关掉」故意的 必须被拒绝：「终端节点不允许由 AI 关闭，请让用户手动关」 代码已验
「任务做完了，通知我一下」 标题栏铃铛亮起 + 侧边栏项目徽标（跟 CLI 跑完任务的提醒同一套） 代码已验
「打开 github.com 我看看」 画布里新建浏览器节点并加载（内嵌 Chromium） 代码已验
「打开 ~/.ssh/config」故意的 必须被拒绝：路径越界，只允许项目目录内 代码已验
「打开 docs/根本不存在.html」故意的 必须报错「文件不存在」，而不是开出一个空白预览让 AI 以为成功了 代码已验

还要看一眼的：标题栏指示灯

只要 AI 动过画板，标题栏就会出现一个插头图标 + 计数（平时完全不占位）。

  • 调用发生时它会亮一下（1.2 秒）——你能感知到「刚才 AI 动了东西」
  • 点开是流水记录：什么工具、动了什么、多久之前；失败的显红
  • 右上角有总开关：关掉之后所有 MCP 调用立刻被拒，不用去改 Claude 配置

Distribution

分发给用户时怎么做到「即插即用」

目标：用户装上 app 就能用，不用配置任何东西；同时不碰用户的全局配置，app 外面一切照旧。

做法

app 在自己的 shim 目录里放 claude / codex 包装脚本， 这个目录只出现在 app 自己终端的 PATH 里。脚本自动带上 MCP 参数后 exec 真正的 CLI。 用户的 ~/.claude.json 和 ~/.codex/config.toml 一个字都不改。

Eas-Term 的终端里：
  claude  → shim/claude → exec 真claude --mcp-config=<app生成的json>
  codex   → shim/codex  → exec 真codex  -c mcp_servers.eas-term...

iTerm / 系统终端里：
  claude  → 真claude，干干净净，没有 eas-term
检查项结果
app 内真实 Claude 会话调工具✅ claude -p 成功调用 canvas_list_frames，返回「9 个」
app 内 Codex 认得 eas-term✅ codex mcp list 显示 eas-term + 用户原有的 bizone-canvas
app 外零污染✅ 只有用户自己的 bizone-canvas，没有 eas-term
用户全局配置未被修改✅ ~/.claude.json 79 个键完好、无 eas-term；~/.codex/config.toml 无 eas-term
不破坏正常 CLI 使用✅ 位置参数、带空格带引号的参数都正常透传
找不到真程序时✅ 一行提示 + exit 127，不死循环、不报语法错
Windows暂不支持 .cmd 包装的转义没法在本机验证，宁可没有不可写坏

路上踩的两个坑

坑后果修法
--mcp-config 吞参数严重 它声明为可变参数 <configs...>，空格分隔会把用户自己的位置参数一并吃掉 —— claude mcp list 把 mcp、list 当成配置文件路径直接报错。 用户所有带位置参数的 claude 调用都会坏。 改写成 --mcp-config=<file>（等号形式只取一个值）
脚本依赖外部命令 原本用 tr / grep / paste 切 PATH，PATH 异常的环境里脚本直接挂 改成纯 shell 内建（IFS 分割 + 字符串拼接），零外部依赖
Codex 会问一次审批

Codex 首次调用 MCP 工具时会弹审批提示 —— 这是 Codex 自己的安全机制，交互模式下点同意即可。 没有替用户关掉它：那等于降低用户的安全防线，不该由 app 代做决定。

Boundaries

安全边界：哪些是死活不给的

开放能力的同时，这几条是硬拦的 —— 不是「AI 应该不会那么做」，是代码层面调不到。

三道锁

  • HTTP 桥只听 127.0.0.1，外网碰不到
  • 每次启动随机令牌，只经 PTY 环境变量给 app 自己起的终端
  • 路径白名单：只允许调用方项目或目标 Frame 项目目录内

明确不开放

  • pty.write —— AI 不能替你往终端里打命令
  • git.resetHard —— 不能回退版本
  • removeFrame —— 不能删 Frame
  • fs.trash —— 不能删文件
  • 关终端 —— 判断不了里面有没有在跑的活，一律拒绝
为什么终端一个都不给碰

你之前因为快捷键误删终端吃过亏。AI 看不到终端里跑到哪一步了， 关错 = 一个跑了半小时的任务没了。所以 canvas_close_node 遇到终端节点直接抛错， 写命令的能力压根没开放。

Gotchas

已知的坑 · 修过的两个真 bug

P1 阶段自己写出来又自己抓到的，记在这里免得以后重犯。

问题后果怎么修的
相对路径按错项目解析 AI 说 docs/a.html，结果按「回落 Frame 的项目」找，开出别的项目的文件 基准改为优先取调用方自己的项目；两个项目都算合法范围
文件不存在也返回成功 开出一个空白预览，AI 以为成功了继续往下走 先 probePaths 校验存在性和「是不是目录」，不过就报错
~/.claude.json 覆盖风险高危 解析失败会从空配置写入，抹掉整份 Claude 配置（你那份有 79 个顶层键） 解析失败直接跳过不写 + 写前备份；实测 79 个键完好
指示灯弹窗看不见 DOM 里有内容但屏幕上是透明的一片字 标题栏 overflow:hidden 裁掉了它、画布 webview 遮罩盖住了它 → 改 portal 到 body + fixed 定位；顺带修了 CSS 变量名写错导致的背景透明

使用上要知道的

  • 开发版和打包版会互相覆盖那条配置：两者的 ~/.claude.json 里 eas-term 指向各自的可执行文件。同时装了就以最后启动的为准。
  • 外部终端里的 Claude 用不了：没有注入的环境变量，工具会明确报「请在 Eas-Term 的终端里运行」。这是设计如此，不是 bug。
  • MCP 目录要随包发：已在 package.json 的 extraResources 里配好，打包时 mcp/ 会进 Resources。
