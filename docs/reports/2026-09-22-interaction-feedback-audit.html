如何补充：先立契约，再逐区落地

状态建议反馈边界
Hover背景/边框/文字轻变化，100–150ms；同一层级控件同一强度。触屏没有 hover，不能作为唯一状态信号；不要全站加发光/上浮。
Pressed立即出现的深一档底色或 0.98–0.99 缩放，60–100ms；松开恢复。危险操作按下后仍要走确认；异步操作由 busy/结果态接棒，不能只闪一下。
Focus-visible2px 可辨识描边 + 2px offset；与 hover 同等可发现。只给键盘焦点，避免鼠标点击后到处留粗圈；隐藏动作要用 :focus-within 显露。
展开/收起箭头 140–180ms；短内容 opacity+高度 160–220ms，同步开始/结束。虚拟列表、大量文件树、画布布局不要逐项动画；可只动画容器遮罩/透明度。收起完成后再卸载。
Busy/成功/失败点击后锁定重复提交、明确“正在…”；成功以内容状态变化确认，失败就地给原因。不要编造百分比，不要让 spinner 无上限；取消/重试路径须可见。
Reduce motion去掉位移、缩放和循环装饰，保留瞬时颜色/边框与必要状态切换。不能把“减少动效”做成“没有反馈”。

时长是起步建议，不是已获用户拍板的设计 token。先用 2–3 个代表组件实际比较，再固定为语义变量；不要直接对所有 button 写全局 transition: all。

推荐实施顺序

  1. 先补基础状态与验收样板：从空 Frame 三按钮、Frame 标题栏图标、设置页标签/次按钮选 4 个样板，统一 pressed、focus-visible、disabled。用鼠标和键盘分别验收。
  2. 再做两种折叠样板：短内容用终端待办；长内容用 AI 工具调用。分别验证快速连点、内容高度变化、收起后焦点去向，再推广到 Skill 分类和运行面板。
  3. 修隐藏动作：待办删除及其他 hover-only 动作补 :focus-within，并检查触屏/无 hover 的常显或菜单替代入口。
  4. 最后统一 token 与自动检查：用变量表达快/常规两档时长；为关键控件增加状态截图/交互测试，扫描新增 transition: all、无降级的循环动画和无 aria-expanded 的折叠按钮。
验收口径：同一控件要跑「hover → mouse down → mouse up → 展开 → 快速收起 → 键盘 Tab/Enter/Space → 减少动效」。在隔离实例中验证暗/亮两种主题；确认无布局抖动、没有旧内容被动画挡住，也不让画布/终端的重绘负担上升。
