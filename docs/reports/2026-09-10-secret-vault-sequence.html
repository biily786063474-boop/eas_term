DESIGN REVIEW / 修复方向

推荐严格路径；通用终端只作为明确标识的兼容模式。

这是跨会话身份、工具契约和执行边界的架构调整，不是一个界面补丁。以下为单代理多视角评审，不冒充多代理已审。

方向完成性体验 / Token 成本安全约束
A · 仅接通 wrapper任意命令覆盖广，实施相对小沿用指令；错误重试仍耗 token不符合强保护：Agent 代码能打印值，不能作为最终方案。
B · 受控业务操作（推荐）连接器逐项支持，不是马上覆盖所有 shell/SSH模型传 credentialRef + operation + 参数；已授权复用，减少重填重试；暂无成本量化限定目标、操作和响应；不向任意代码发值，拒绝重定向携带鉴权及任意输出。
C · 人工代执行覆盖受手工操作限制确认频繁、自动化弱只作高风险任务的临时处理办法。
严格路径必须声明威胁模型。

可信应用及受控执行服务持有值；模型和工具转录不获值。若 Agent 仍有同用户无限制 shell、可读凭证来源/调试受信进程或持有 /secret-env 取值票据，只加代理接口并不构成硬隔离。严格会话需不可达明文通道，必要时采用 OS 级隔离；不承诺抵御控制本机的恶意管理员。

01 · 创建：用户输入，本机加密

创建入口实际差别

六位码用于操作锁，不直接参与密文加密；系统加密不可用时保存被拒绝。备注会被模型读取，请勿把秘密写进备注。

02 · 模型如何从任务走到密钥请求

“模型 / Agent CLI”合并表示推理与工具循环：用户消息由 CLI 交给模型，模型提出工具调用，CLI 执行 MCP，再把工具返回交给模型。MCP 本身不是模型，也不替用户批准凭证用途。

柜子锁着 ≠ 柜子为空。无参 secret_check 在锁定时返回 locked:true，不应立即让用户重填。请求弹窗还有防骚扰：同类请求至少间隔 60 秒，同时最多一个，某终端连续取消两次后本轮不再弹。

03 · 密钥实际在哪里被使用

# 文本凭证：让子进程脚本读取环境，不把值写入命令字符串
 eas-secret run --vars DEMO_API_KEY -- node task.js
# task.js 内部读取 process.env.DEMO_API_KEY，并传给目标服务 SDK

# 必须由 shell 展开时，延后到包装器启动的子 shell 内
 eas-secret run --vars DEMO_API_KEY -- sh -c 'your-command --token "$DEMO_API_KEY"'
# 上式可能把值暴露在目标进程参数中；能让 SDK 直接读环境时优先读环境。
这不是“AI 永远无法读到密钥”的隔离沙箱。Agent 能执行命令，就可能把环境变量或文件内容打印出来；stdout/stderr 会进入模型上下文。不要 echo 密钥、cat 私钥、开启带鉴权头的调试日志。完整凭证会按业务需求发送给目标服务，不应宣称它绝不出网。SIGKILL、断电等不能保证执行临时文件清理。

04 · 为什么新终端能直接用，旧终端需要包装器

环境变量是进程创建时的快照。修改柜内值不会改掉已启动进程；关闭自动注入或锁定柜子也不会撤回既有进程已经持有的值。锁定会阻止后续包装器取值。

两本账不是同一份：secretsEnv(opts.secretNames) 决定本次注入哪些文本变量；issueSecretToken(id, autoInjectGroups()) 当前以自动注入组初始化包装器授权。不要把“显式选中的变量”与“包装器授权组”当成天然一致。

05 · 所有分支，以及不能画成成功的部分

现场状态当前行为 / 应走路径
柜里有，且 inThisTerminal直接执行读取环境变量的命令。变量是否来自外部 shell 配置，不完全由密钥柜元数据覆盖。
柜里有，旧终端没带needsWrapper → eas-secret run；还必须通过解锁、专属 token、ptyGrants 授权，存在不代表可取。
柜里没有先只查存在性，不打印值；确实没有才 request_secret → 用户录入 → 保存 → grantToPty。
用户取消 / 请求限流返回 saved:false 或工具错误，不生成凭证，不继续假装鉴权成功。
库无法解密 / MCP 关闭 / 缺专属 token / 未授权取值失败，返回说明，不返回密钥。重开正确终端、用户解锁或补授权后再试，不绕过校验。
目标服务 401 / 凭证失效可走 report_secret_invalid 修正弹窗；只更新对应变量，其他同组值保留，然后重新执行验证。
缺口 A · 原生 AI 对话并非 PTY 链路。

agentChat/session.ts 使用 mcpEnv({project,teamRole}) 与 capabilitySessionEnv，但当前读取的启动路径没有调用 secretsEnv / issueSecretToken，也没有传入 ptyId。OMP 环境清洗还明确移除继承的 EAS_SECRET_TOKEN / EAS_PTY_ID。由此不能确认原生 Claude / Codex / OMP 对话都能走通同一取值链；这是静态代码发现，非三CLI端到端结论。

缺口 B · 现有凭证的“只授权、不重新录入”流程。

request_secret 当前普通表单要求填写所有值，并调用新建 save；变量已存在时可能被全局重名校验拒绝。虽然工具错误文案建议 request_secret 授权，但当前表单不是一个独立的“批准使用已有组”选择器。这一分支不能画成无条件成功。
