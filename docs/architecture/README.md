# Eas-Term 架构图纸

> 这套文档的读者**首先是 AI**（Claude Code / Codex 等在本仓库干活的 agent），其次才是人。
> 目标不是"介绍项目有多好"，是让一个刚进来的 agent 在动手前知道：
> **我在哪、能改什么、碰什么会出事故。**

## ⚠️ 先分清两个 agent 语境（不分清整套图会串味）

这个项目本身就是 AI Agent 的宿主，所以"agent"这个词在本仓库有两个完全不同的意思：

| | **产品内 agent** | **开发期 agent** |
|---|---|---|
| 指谁 | Eas-Term 托管起来的 Claude Code / Codex 会话、team 子 agent、内置角色（当前 8 个，以 `src/main/roles.ts` 的 `BUILTIN_ROLES` 为准）| 正在读这份文档、要改这个仓库代码的你 |
| 边界由谁定 | `src/main/roles.ts` + `fsGuard.ts` + 审批 hook（**代码**） | 本目录的领地图与所有权矩阵（**文档**） |
| 图纸 | 01 / 02 / 03A / 11 / 12 | 03B / 10 / 13 |

**两者的禁区完全不同。** 产品内 agent 被 `fsGuard` 拦在项目目录里，是运行时安全；
开发期 agent 的禁区是"改了会静默失效/回退历史修复"，靠文档约束，没有代码兜底。

## 动手前跑什么、改完跑什么

图纸划的是边界，下面这几条命令是边界的执行者 —— **只跑 `typecheck` 等于没查**。

| 命令 | 是什么 | 什么时候跑 |
|---|---|---|
| `npm run check` | `typecheck` + 四个 `scripts/check-*.mjs` + `npm test` | **提交前必跑** |
| `npm test` | `node --test 'src/**/*.test.ts' 'src/**/*.test.mjs'`，Node 原生跑 TS，不用先构建 | 改契约层 `src/shared/` 或任何纯逻辑之后 |
| `npm run verify` | `npm run build` + `scripts/verify-app.mjs --seed`：起一个 **userData 隔离**的构建产物实例并挂 CDP 9333 | UI / IPC 改动 —— 这层单测证明不了，只能真机看 |

四个 `check-*` 拦的都是 **tsc 和构建一起放行、只有真打开 app 才看得出来**的东西
（CSS 少一个 `}` → 后面的规则被整段吞掉、全 app 变无样式毛坯房；条件 `return` 之后写 hook
→ React 按调用顺序认 hook，整界面被 ErrorBoundary 兜白）。各自的理由写在脚本文件头。

⛔ **`npm run dev` 不能替 `npm run verify`**：dev 模式的 userData 走 `app.getName()`，
和正式版**是同一个目录**，密钥柜就在里面 —— 拿它做验证等于在真凭证上做实验
（`scripts/verify-app.mjs` 文件头记着这笔账，白名单 seed 也刻意不含 `secrets.json`）。

## 维护纪律

1. **改代码时顺手改图纸，同一个 commit 里提交。** 脱节的图纸会反复咬人 —— 这条纪律
   和 `~/.claude/servers/` 服务器档案是同一个道理。
2. **禁区条目只增不减。** 想删一条"禁改"，先在 commit message 里写清楚为什么它不再危险。
3. **本目录不放评审/汇报页。** 那些是一次性的，归 `docs/` 根目录（既有习惯：根目录已积了 35 个
   方案与评审 HTML）。本目录只放"长期为真"的结构。
4. **具体踩坑记录归 `memory/`，不归这里。** `memory/` 的风格是"现象→根因→修复→教训"，
   本目录是"结构与边界"。图纸里引用 memory 条目用相对链接。
