## ⚠️ 先分清两个 agent 语境（不分清整套图会串味）

## 动手前跑什么、改完跑什么

**只跑 `typecheck` 等于没查。**

| 命令 | 是什么 | 什么时候跑 |
|---|---|---|
| `npm run check` | `typecheck` + 几个 `scripts/check-*.mjs` + `npm test`（以 package.json 为准）| **提交前必跑** |
| `npm test` | Node 原生跑 TS，不用先构建 | 改契约层 `src/shared/` 或任何纯逻辑之后 |
| `npm run verify` | 构建 + 起一个 **userData 隔离**的产物实例并挂 CDP 9333 | UI / IPC 改动 —— 单测证明不了，只能真机看 |

`check-*` 拦的都是 **tsc 和构建一起放行、只有真打开 app 才看得出来**的东西（CSS 少一个 `}` → 后面规则被整段吞掉、全 app 变毛坯房；
条件 `return` 之后写 hook → 整界面被 ErrorBoundary 兜白）。理由写在各脚本文件头。

⛔ **`npm run dev` 不能替 `npm run verify`**：dev 模式的 userData 走 `app.getName()`，和正式版
**是同一个目录**，密钥柜就在里面 —— 拿它做验证等于在真凭证上做实验
（`scripts/verify-app.mjs` 文件头记着这笔账，白名单 seed 也刻意不含 `secrets.json`）。

## 维护纪律

1. **改代码时顺手改图纸，同一个 commit 里提交。** 脱节的图纸会反复咬人 ——
   和 `~/.claude/servers/` 服务器档案是同一个道理。
2. **禁区条目只增不减。** 想删一条"禁改"，先在 commit message 里写清楚为什么它不再危险。
3. **本目录不放评审/汇报页。** 那些是一次性的，归 `docs/` 根目录；本目录只放"长期为真"的结构。
4. **具体踩坑记录归 `memory/`**（风格是"现象→根因→修复→教训"），本目录是"结构与边界"；
   图纸里引用 memory 条目用相对链接。
