## 发版链路

流程本身在全局 memory 的「Eas-Term 发版流程」里，这里只记会静默出错的耦合：

- **版本号唯一来源是 `package.json`。** `publish-site.sh` 读它，再用 `sed` 把 `site/index.html` / `site/download.html` 里的版本号与下载链接回填。手改那两处会被 sed 刷掉，或被后面的 STALE 检查拦下。
- **`CHANGELOG.md` 一份来源两处消费**：`changelog.mjs html` 生成 `site/changelog.html`，`changelog.mjs notes <版本>` 塞进 `latest.json` 的 `notes`（被 `updater.ts` 的 `LATEST_URL` 取走）。漏写本版条目时，`publish-site.sh` 第一步的 `check` 直接 exit 1 —— 这条是**响亮**的；但 `notes` 找不到版本时**返回空数组不报错**，所以绕开 check 的路径上，应用内更新提示会是空的。
- mac 走 `EAS_NOTARIZE=1 npm run dist`（产物落 `~/Eas-Term-release`，即脚本的 `PKG_DIR`）；Windows 走 CI 的 `dist:ci`，产物要 `gh run download` 拉进**同一个** `PKG_DIR`。下载页指向新版 exe 而本地没有它时脚本会中止。**Windows 链接允许落后一版**，这是刻意的。
