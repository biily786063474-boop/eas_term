# 15 · 视觉令牌与主题（设计系统规范）

> 这份图纸回答一个问题：**改颜色、改层级、改形状、改间距，该动哪儿。**
> 短答案：动 `src/renderer/src/styles/base.css` 的令牌，不要在功能 CSS 里写死值。

2026-09-02 做了一整轮系统性 UI 改造，这份文档是那一轮的**结论落档** ——
每一条都写清「为什么这么定」，因为**光看数值改不对**。

---

## 一、地基

| | |
|---|---|
| 统一管理层 | `styles/base.css`（约 174 个令牌）|
| 主题机制 | `data-theme` 属性（CSS 侧）＋ `themes.ts`（xterm 侧，**两边必须同步**）|
| 主题 | **暗色 / 亮色 / 跟随系统**（黑粉已删）|
| CSS | 24 个文件 20300 行 |

### 主题：三个选择，两个类型

```ts
ThemeChoice = 'dark' | 'light' | 'system'   ← 用户**选的**
ThemeId     = 'dark' | 'light'              ← 真正落到 DOM / xterm 的
```

**两者必须分开。** 只存解析结果的话，用户选了「跟随系统」，
下次系统换了、而我们记着的还是上次那个具体值，就不跟随了。

「跟随系统」还**订阅了系统变化**（`watchSystemTheme`）——
不订阅它只在启动那一刻跟随一次，那这个选项就是假的。
订阅句柄在模块级，切主题时先退掉上一个；**只有选了 system 才挂**。

`loadTheme()` 认得出历史值：`default` / `pink` 都落到 `dark`，老用户升级不被重置。

## 二、六条硬规矩

### ① 层级由 surface 的明度表达，不由描边

```
--bg    最底：窗口 / 画布底
--s-1   贴在底上的区域：侧栏、工具条
--s-2   卡片、面板
--s-3   浮层：菜单、下拉、popup
```

文字三级：`--t-1`（主）· `--t-2`（次）· `--t-3`（弱到几乎不参与阅读：
时间戳、行号、工具调用的次要信息）。

> **`--t-3` 在两个主题里同值（`#8f8f8f`）是有意的** —— 它表达的是「退后」，
> 而不是某种亮度，明暗底上都该是同一种退后感。

### ② 描边只留给三种东西

- `--stroke-input` / `--stroke-input-focus` —— **输入框**（唯一允许描边的常规控件）
- accent 色边 = **状态**（选中的 Frame、激活的按钮）、红边 = 出错
- **Frame 的一条细虚线** —— 见规矩 ⑥

层级描边令牌（`--glass-border` `--glass-border-strong`）已削到
`0.035 / 0.06`（暗）与 `0.045 / 0.07`（亮）——**几乎不可见，但没归零**：
两块明度相同的面叠在一起时（浮层压浮层）明度差本来就不存在，留一丝当兜底。

> **削的是令牌，不是那 176 处语句。** 283 处全环描边里有 188 处用的就是这两个令牌。
> ⚠️ 削之前**必须先把输入框摘出去**指向 `--stroke-input`（当时 12 处），
> 不然它们会跟着一起消失 —— 而输入框恰恰是点名要留边的。

### ③ 五组叠色令牌，一个都别写死

| 令牌 | 语义 | 暗色 | 亮色 |
|---|---|---|---|
| `--wash-1..3` | **沉一档** | 加黑 | 压出浅灰 |
| `--lift-1..3` | **浮一档** | 加白 | 压出更浅的灰（**白底上加白是看不见的**）|
| `--ink-1..3` | 投影的墨色 | 0.28~0.55 | **0.04~0.10** |
| `--sem-*` ＋ `--sem-*-rgb` | 红/黄/绿/橙的**语义** | 暗底调的亮色 | 同色相压明度，过 4.5:1 |
| `--hl-bg` / `--hl-fg` | 选中/激活的**实心底** | accent ＋ 近黑字 | **近黑底 ＋ 白字** |

三条踩过的：

- **投影黑度也要跟主题走。** 95 处 `box-shadow` 的黑是照暗底调的，
  压白底上就是一圈脏晕（用户原话：「投影太重了 太脏了」）。
- **语义色不能只换明度不管色相，也不能只保色相不管对比度** ——
  用户认的是「粉＝出错、黄＝注意」，换色相等于换语义；而暗底调的粉在白底上
  对比度只有 1.4~1.9，等于没有字。
- **`--canvas-dot`**（画布点阵）同理：写死 `rgba(255,255,255,.06)` 时白底上等于没有。

### ④ 两个主题都不用蓝 —— 强调靠明度，不靠色相

| | 强调色 |
|---|---|
| 暗色 | `#dfe3e8` 近乎白的浅灰 |
| 亮色 | `#2f3338` 近黑（带一丝冷）|

暗底上最强的对比是近白、白底上最强的对比是近黑。一块低彩度的蓝两头都不占：
既不够抢眼，又把界面拉出一层杂色。

**CTA 的渐变自动跟着走** —— `--accent-dark` 由
`color-mix(in srgb, var(--accent) 78%, #000)` 派生，改 `--accent` 两端一起变。

> **分类色不在此列。** 看板的状态点、词典的类目、wiki 的笔记类型各有各的色相 ——
> 那是「这是哪一类」的信息，全改成灰就分不出类了。判据是
> **「这个颜色在表达身份，还是在表达强调」**。

### ⑤ 「表达身份」的东西不参与主题 —— 而且必须整套一起不参与

**这一轮栽得最多的一条，同一个形状犯了三次。**

有些元素刻意**跟主题反着来**，因为它们承担的是「这是什么」而不是「这在第几层」：

| 元素 | 暗色 | 亮色 |
|---|---|---|
| `.cframe-head`（Frame 的窗口条）| 深 | **仍然深**（`#1c1c1c` / 字 `#f2f2f2`）|
| `.pane-kind-btn`（模块类型选择器）| **白底黑字** | **黑底白字**（反相）|
| tooltip · `.gantt-toast` | 深底浅字 | **仍然深底浅字** |

**⚠️ 底不跟主题，字就也不能跟。** 三次事故都是只翻了一半：

1. tooltip 的 `background` 用 `--tooltip-bg`（不跟主题）而 `color` 用 `--fg`（跟主题）
   → 亮色下深字压深底，对比度 1.2。修法：加 `--tooltip-fg` **与 bg 成对**。
2. `.pane-kind-btn` 反相之后，被更具体的
   `:root[data-theme='light'] .pane-header button { color: #3d3d3d }` 盖住
   → 深灰字压深底。修法：`button:not(.pane-kind-btn)`。
3. 渲染层手抄的类型漏字段（同一个「两处各写各的」形状，见 13 图纸）。

**判据不是「它浮不浮着」，是「它是提示还是面板」**：
`.gantt-pop`（带内容、可滚动、可删除的卡片）跟亮色走；
`.gantt-toast`（一两行字、看完即走）保持深色反相。

### ⑤·五 模块类型角标：实心 accent，两个主题自动反相

**2026-09-06 用户给了参考图**：Frame 里除终端和 AI 对话之外的所有模块（文件预览 /
画布组件 / 自由节点，三者共用 `.cfile-head`），类型图标做成**悬在左上角外侧**的
圆角方形角标 —— 压着模块的圆角探出去 8px。

两件跟本图纸有关的事：

1. **底用 `--accent`、图标用 `--on-accent`，不写死白色。**
   参考图是白底黑图标；暗色下 accent(`#dfe3e8`) 本来就接近那块白，而亮色下
   accent 转深、`--on-accent` 跟着翻 —— 写死白色的话亮色主题上就是白底白图标。
   这正是规矩 ⑤「底不跟主题，字就也不能跟」的正向用法：**成对的令牌，一起翻**。
   `check-accent-contrast.mjs` 拦的就是这一对被拆开。

2. **`.cfile-node` 因此不能再 `overflow: hidden`** —— 那会把角标裁掉。
   圆角裁剪改由上下两段各自负责：`.cfile-head` 收上面两个角、
   `.cfile-body` 收下面两个角（body 本来就有自己的 `overflow: hidden`，内容照旧不外溢）。
   **改这三条里的任何一条都要三条一起看**，只改一条的症状是圆角缺一半或角标被切。

hover 那团一过性烟雾**每种模块一个色相领域，渐变只在色环 30° 以内走**
（用户 2026-09-06）。30° 是「同一族的深浅冷暖」，不是彩虹 —— 一眼认出
「这是图片模块」，而不是每个角标都糊成同一团七彩。色相角在 base.css
（`--smoke-h-code` 218 蓝 · `-web` 172 青 · `-image` 305 品红 · `-git` 28 橙 ·
`-design` 340 粉 · `-team` 132 绿 · `-codegraph` 262 紫 · `-plugin` 48 琥珀，
兜底 `--smoke-h` 230）。canvas.css 只按 `data-kind` 派令牌，不写色值；
加一种模块类型就加一行。**彼此拉开 40° 以上**，否则 30° 的跨度会让相邻两类看成一种。
它**故意不随主题变** —— 不表达语义，就是一下装饰性的彩色。

> ⚠️ **`var()` 是在「声明」这个自定义属性的元素上替换的，不是在使用它的元素上。**
> 渐变配方一开始写在 `:root` 的 `--badge-smoke` 里，`var(--smoke-h)` 当场就按
> `:root` 的兜底 230 烤死了，往下继承的是**已经算完的颜色** ——
> 八种类型全长一个样，而查 `--smoke-h` 变量本身还是对的（很难看出来，
> 2026-09-06 实测踩过）。配方必须声明在能拿到自己那份 `--smoke-h` 的元素上，
> 现在在 `.cfile-badge`。这条对**任何「一份配方 × 多个变体」的令牌**都成立。

它的性能约定在下一节。

### ⑥ Frame 两个主题都要毛玻璃

Frame 是「盖在画布上的一块地」，透出底下的点阵才有浮起来的实感；
实心底会把它压成一块贴纸。

⚠️ **毛玻璃要生效，底色必须半透明** —— 不透明底下面什么都没有可模糊。
亮色是 `rgba(232,232,232,0.72)`：叠在白画布上视觉仍是那一档灰，但点阵透得上来。

Frame 的边是**一条细虚线**（规矩 ② 的例外）：毛玻璃 ＋ 半透明底跟背景差得很少，
光靠明度看不出边在哪。**虚线读作「范围」，实线读作「容器的外壳」** —— 这里要前者。

## 三、形状：圆角与胶囊

| 令牌 | 值 | 谁在用 |
|---|---|---|
| `--radius-xl` | **26px** | Frame |
| `--radius-lg` | **20px** | 模块面板、菜单外壳 |
| `--radius-md` | 10px | 菜单里的搜索框与条目、小控件 |
| `--radius-sm` | 7px | 更小的控件 |
| （不走令牌）| `999px` | **胶囊**：`.pane-kind-btn` · `.tab` |

### 基准钉在灵动岛上

用户：「和灵动岛一个体感。」岛展开 32px、收起 20px（`src/renderer/island/island.css:122/103`）。

调过三轮，账留着因为它本身是结论：

```
18/14  原值 —— 偏方，跟岛不是一家
36/28  「加大二倍」—— 顶栏两端的内容被吃进圆弧，得连带放大内边距
26/20  现在这档
```

**比岛的 32px 收一点是有意的**：面板比岛大得多，同样的半径在大面积上看着更圆；
26px 在面板尺寸下读出来的「圆度」，才和 32px 在岛上一致 ——
**体感一致靠的是视觉比例，不是数值相等**。改这两个数之前先去 `island.css` 量一眼。

### 圆角嵌套：内圈 ≈ 外圈 − 内边距

双击菜单外壳 `--radius-lg`（20px），里面的搜索框曾是 `--radius-sm`（7px），
差了近三倍 —— **像一个圆盒子里塞了几张方卡片**。都提到 `--radius-md` 之后两条圆弧才同心。

### 胶囊是一种语汇，不是一个数值

`.pane-kind-btn` 与 `.tab` 用 `999px` 且**刻意不跟 `--radius-md` 走**：
那个令牌管「小控件的圆角」，而这里要的是「胶囊」——语义不同，
跟着令牌走会在下次调 md 时被带偏。

> 一个胶囊挨着一个圆角矩形，看着像两套设计。**同一区域里形状语汇要统一。**

## 三·五、动画：只动 transform / opacity

`check-animations.mjs` 那道闸只是底线（infinite 动画不许动布局属性），
**一次性的转场同样该守这条**。

### hover 动效的四条省法（模块角标那团烟雾）

用户 2026-09-06 点名「注意渲染资源不要重复」。在 `.cfile-badge` 这里它具体是四件事，
**加任何 hover 动效都照这四条办**：

1. **一个伪元素，不是一层 DOM。** 渐变是静态背景，只在第一次绘制时光栅化一次，
   之后 transform 拿的是同一张纹理。
2. **只动 transform 和 opacity。** 不动 `filter: blur` —— 模糊跟着 transform 变
   就得每帧重新光栅化；柔和感改用渐变自身的透明度分布做，视觉差不多、代价差一个量级。
   顺手加个 `box-shadow` 过渡也不行，那是每帧重绘阴影。
3. **不写 `will-change`。** 一屏几十个节点，常驻的合成层提升就是几十份显存，
   而它们 99% 的时间没在动。让浏览器在动画真的开始时临时提升就够了。
4. **静置零成本。** 不 hover 时伪元素 `opacity: 0` 且 `animation-name: none`
   —— 真机量过：离开 hover 600ms 后 `transform: none`、`will-change: auto`、
   `filter: none`，一分钱不花。

> ⚠️ **多关键帧动画的缓动函数是逐段生效的。** 这团烟雾最初写
> `cubic-bezier(0.16,1,0.3,1)`（easeOutExpo），每一段都往前挤，
> 实测 130ms 还在、320ms 已经散完 —— 「一过性」变成了看不见。
> 现在是 `linear`，节奏由关键帧的位置表达。

### 最大化 / 还原用 FLIP

不能给 `left/top/width/height` 加 transition —— 那四个属性每帧触发
布局→绘制→合成，而节点里装的是终端、编辑器这些重内容；
xterm 还会按容器尺寸重算字符网格，**动画期间字一直跳**。

FLIP：**布局一步到位（瞬间变终态），只用 transform 把视觉倒推回起点，
再跑回 identity**。几何在 `features/workspace/flip.ts`（7 条单测），
时序与判据在 `features/workspace/useFlip.ts` 的 `useMaximizeFlip`。

**四个可最大化的模块共用那一个 hook**（用户 2026-09-07：「frame 中所有可以最大化
窗口都要统一的放大缩小过度动效」）：`PaneView`（终端 / AI 对话）·`CanvasFileNode`
（文件预览）·`CanvasComponentNode`（画布组件）·`CanvasFreeFileNode`（自由节点）。
在那之前**只有 PaneView 有**，另外三个是瞬移 —— 因为逻辑当时内联在 PaneView 里，
想给别人用只能抄。**加第五个可最大化的模块时用这个 hook，别再抄一份**：
抄出来的第一天是一样的，改过一次曲线或阈值之后就不一样了，
而症状只是「有的窗口手感不对」，极难查。

> ⚠️ **被别人最大化盖住时要传 `null`**，不能传它当时的矩形 ——
> 那时元素是 `display:none`，量出来 0×0；hook 收到 `null` 会把「上一帧的矩形」
> 一起清掉，藏起来再出现时不会被当成一次跳变。

两条 2026-09-07 用户实拍报出来、**从 FLIP 上线那天就错着**的：

- **`transform-origin` 由动画自己给，不能指望元素上有。** `invertTransform` 的公式按
  「原点在左上角」推。`PaneView` 自己设了 `transformOrigin: '0 0'`（给它的位图缩放用），
  所以终端那条一直对；而画布上三个节点组件从来没设过，实测 `.cfile-node` 是
  `150px 110px`（默认的中心）—— 缩放绕中心、平移按左上角，起点落不回原位。
  这正是用户原话里的「**有些**不是从原位到全屏的」：是「有些」，不是全部。
  现在写在关键帧里，调用方元素上有没有都不影响。
- **⚠️ 绝不能用 `el.style.transform` 去「按住」元素。** `.pane` 自己就带一个内联
  `scale(vp.scale)`（React 的 style 属性下发）—— 写进去会覆盖它，清理时又容易把
  `transformOrigin` 留在元素上，于是那个 scale 改成绕左上角缩放，**整块渲染位置全错**
  （用户实拍「坐标好像错乱了」，2026-09-07 我真踩了一次）。
  要「按住」就用 `anim.pause()` 停在第 0 帧：WAAPI 的值在动画期间盖过 CSS transform，
  `cancel()` / 结束后自动还原，全程不碰内联样式。
- **动画要等一帧「不贵的」再启动。** 还原时画布上**所有**被 `display:none` 藏起来的
  节点同一帧全部恢复显示（实测 55 个元素，冷启动 175~191ms，热了之后仍有 ~58ms），
  而 **WAAPI 是按时间走的** —— 卡住的那段时间里动画时钟照走，卡完直接跳到 67% 再收尾，
  观感就是「收回明显卡顿」。修法是**先建好动画再 `pause()` 按在第 0 帧**（元素就定在
  起点了，且是 WAAPI 的值不动内联样式），等某一帧间隔 <20ms 说明布局风暴过去了再
  `play()`（上限 4 帧兜底）。按住和延迟启动是**一对**，只做后者会先跳到终态一帧。
  只等一帧不够：实测风暴跨两帧（79.5ms + 49.7ms）。
  实测修完：放大 / 收回都没有时钟跳变，动画期间最大帧间隔 8.9 / 16.7ms。
- **真正的治法是把那笔开销挪出动画窗口** —— `useHidingHolder`（同一个文件）让
  「因为谁而藏着」比 `maximizedNode` **晚一个收回动画的时长才清空**，兄弟节点等动画
  放完再恢复显示。它们在最大化期间本来就一直看不见，晚 260ms 出现不改变任何语义。
  ⚠️ **只有 `hiddenByMax` 能用这个滞后值**；`isMax` 与最大化的几何必须用实时的
  `maximizedNode`，否则被还原的那个节点会晚 260ms 才开始缩，动画就没了。
  四个地方都要改（三个画布节点组件 ＋ `PaneLayer` 里那句「其它节点隐藏」）。
  实测：收回动画 280ms 窗口内**零掉帧**（中位 8.5ms、最长 17.7ms），
  从点击到动画开跑 18~19ms（改之前 64~100ms）。

> ⚠️ **量动画掉帧时别只信 rAF。** 主线程的 `requestAnimationFrame` 量不到合成器掉帧；
> 要看真正呈现出来的帧得用 CDP 的 `Page.startScreencast`。
> 但它**只在页面重绘时才出帧** —— 静止不动的那段会被算成一个巨大的「缺口」，
> 我 2026-09-07 为此两次得出「冻了半秒」的假结论。**采集窗口要恰好卡住动画那一段**。

三条参数上的决定：

- **`transform-origin: 0 0`** —— 默认 `50% 50%` 会让缩放绕中心发生，
  平移量得连带补偿中心偏移，公式又长又容易错。
- **只给「面积变了一大截」的跳变做动画**（比例 <0.6 或 >1.7）。
  平移/缩放画布时 rect 也在变，那些本来就连续，再叠补间会拖泥带水。
- **放大 320ms、缩小 260ms**，曲线 `cubic-bezier(.32,.72,0,1)` ——
  起步快、收尾慢、**不回弹**（窗口最大化回弹显得轻浮）。

> ⚠️ **终态宽高为 0 时不要倒推**：除以 0 得 `Infinity`，浏览器会把整条
> transform 判为无效 —— 症状是「动画根本不发生」而不是报错。

## 三·六、沿边滚动条（`ui/CtxScrollRail`）

滚动进度**沿着容器自己的圆角边框走**，不画成一根竖条。
几何在 `ui/ctxRail.ts`（10 条单测）：顶边距右端 1/3 起 → 右上角圆弧 → 右边到底。

- **终点必须到底**，不能停在半空 —— 滑块贴到一个悬空的末端时，
  人读到的是「下面还有，只是走不动了」。**轨道的终点就是「到头了」这个信息本身。**
- **藏掉原生滚动条**，否则一个信息画两遍。
- **滚动时不走 setState**：滚动是每秒上百次的事件，每次 diff 整棵 SVG 会让滑块落后。
  尺寸走 state（只在开合/搜索时变），滑块位置走 ref 直接写属性 ＋ rAF 合帧。
- **不加 CSS transition** —— 滚动条要零延迟同步，补间只会让它追在后面跑。
- ⚠️ 它虽然 `position: fixed`，**祖先有 `overflow: hidden` 照样被裁**
  （设置面板那层灯箱就有）—— 挂在不被裁的那一层，宿主用 ref 指过去。

## 四、两个主题的手法不一样

| | 暗色 | 亮色 |
|---|---|---|
| 层级主力 | **明度差**（`#0d0d0d → #171717 → #1c1c1c → #212121`）| **投影**（`#fff → #f7f7f8 → #fff`）|
| 投影 | 几乎看不见，只做点缀 | 分层主力 |

白底上 `#fff → #f7f7f8` 差得太少，光靠明度分不开浮层；暗底上投影几乎看不见。
**照搬另一边的手法就会「层级糊成一片」。**

配色基准：ChatGPT / Codex 网页那套 —— 近中性灰、极低彩度、
强调色只用于可点/激活且面积极小。

## 五、CTA 与次级强调：用渐变的强度分主次

CTA（`.ab-launch` / `.wk-primary` / `.upd-go`）：

```css
linear-gradient(180deg, rgba(255,255,255,.24), rgba(255,255,255,.04) 46%, rgba(0,0,0,.12))
inset 0 1px 0 rgba(255,255,255,.5)   /* 内高光 */
```

`.pane-kind-btn` 用**同一套形状、按比例收弱**（.14 / .03 / .07，内高光 .3）：

> **保持同一个形状（上亮、46% 转折、下压暗），只降幅度** ——
> 换个形状就不是「同一套」了，只是「另一个渐变」。
>
> 为什么要弱：CTA 是「按这里会发生事情」，这枚是「这是什么模块」。
> 两者都用最强的白底，光靠底色分不出主次；**用渐变的强度分**。

## 九、真机怎么验（三条量法上的坑，都实际栽过）

起隔离实例（`npm run verify`），**走 store 切主题**：

```js
window.__store.getState().setTheme('light')
```

> ⚠️ 直接 `document.documentElement.setAttribute('data-theme','light')` 会
> **绕过 xterm 那侧**（它由 `themes.ts` 在 `setTheme` 里应用），
> 量出来终端底还是上一个主题的值。

1. **数描边要按 `border-width`，不是 `border-style`** —— `style: solid` 但宽度 0 的
   元素也会被算进去（颜色是继承来的 `currentColor`），一次量出 1586 处「明显边」，全是假的。
2. **往上找背景色时判据是 `alpha > 0.5`**，不是「字符串以 `rgba(0,0,0,0` 开头」——
   后者会把 `rgba(0,0,0,0.028)`（`--lift-1`）当成透明，一路找到暗色祖先，
   量出一堆假的「对比度 1.08」。
3. **改了令牌名要回头看检查器还认不认**，并做变异测试。

**这三条比结论值钱**：量错了会得出「已经修好」的假结论，而那比没修更危险。

### 启动按钮巡游高光（0.4.83）

`FrameStart.tsx` 的 `cframe-start-ring` 是固定圆角环形遮罩，内部伪元素绘制静态 conic-gradient，只动画 transform。避免动画 CSS 自定义角度导致每帧重绘。hover 任意按钮暂停整排，当前按钮隐藏环并显示扫光；减少动效时停止旋转。
