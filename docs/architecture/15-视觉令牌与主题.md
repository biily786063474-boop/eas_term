# 15 · 视觉令牌与主题

> 这份图纸回答一个问题：**改颜色、改层级、改间距，该动哪儿。**
> 短答案：动 `src/renderer/src/styles/base.css` 的令牌，不要在功能 CSS 里写死值。

## 为什么这份图纸存在

2026-09-02 做系统性 UI 改造时清点出来的家底：

| | |
|---|---|
| 统一管理层 | `styles/base.css` |
| 主题机制 | `data-theme` 属性（CSS 侧）＋ `themes.ts`（xterm 侧，**两边必须同步**）|
| CSS | 24 个文件 20300 行 |

最后一行是这份图纸的由来：**那 792 处全部建立在「底是暗的」这个假设上**
（软件此前只有两个主题，都是暗色）。它们不是风格问题，是**亮色主题做不成的原因**。

## 三条硬规矩

### ① 层级由 surface 的明度表达，不由描边

用户 2026-09-02 定的：「尽量不要用 stroke，靠颜色的明度差异区分层级，
输入框可以有 stroke。」

四层 surface，越浮越亮（暗色）/ 越浮越白 ＋ 投影（亮色）：

```
--bg    最底：窗口 / 画布底
--s-1   贴在底上的区域：侧栏、工具条
--s-2   卡片、面板
--s-3   浮层：菜单、下拉、popup
```

文字三级：`--t-1`（主）· `--t-2`（次）· `--t-3`（弱到几乎不参与阅读：
时间戳、行号、工具调用的次要信息）。

> **`--t-3` 在两个主题里同值（`#8f8f8f`）是有意的** —— 它表达的是「退后」，
> 而不是某种亮度，明暗底上都该是同一种退后感。

### ② 描边只留给两种东西：输入框、状态

- `--stroke-input` / `--stroke-input-focus` —— **唯一允许描边的常规控件**
- accent 色边 = **状态**（选中的 Frame、激活的工具条按钮）、红边 = 出错

层级描边令牌（`--glass-border` `--glass-border-strong`）已经削到
`0.035 / 0.06`（暗）与 `0.045 / 0.07`（亮）—— **几乎不可见，但没归零**：
两块明度相同的面叠在一起时（浮层压浮层），明度差本来就不存在，留一丝当兜底。

> **削的是令牌，不是那 176 处语句。** 283 处全环描边里有 188 处用的就是这两个令牌；
> 改令牌是一处、将来想调回去也是一处，而删语句要动 176 个文件位置、每处都可能改错缩进。
> ⚠️ 削之前**必须先把输入框摘出去**指向 `--stroke-input`（当时 12 处），
> 不然它们会跟着一起消失 —— 而输入框恰恰是点名要留边的。

### ③ 「压一层」用 `--wash-1..3`，不要写 `rgba(0,0,0,x)`

暗色主题里到处用半透明黑表达「比周围沉一点」。**那是把主题假设写死在颜色里**：
亮色底下它是一块块黑污渍（真机抽样：切亮色后 12 类元素仍是暗底，绝大多数是这个）。

`--wash-*` 的语义是**「沉一档」**，不是「加黑」：暗色继续压暗，亮色改为压出浅灰。

> **投影不在此列。** `box-shadow` 的黑本来就该是黑的（95 处），迁移时一处不碰。

### ④ 「浮一层 / 沉一层 / 投影 / 语义色 / 高亮」都有令牌，别写死值

| 令牌 | 语义 | 暗色 | 亮色 |
|---|---|---|---|
| `--wash-1..3` | **沉一档** | 加黑 | 压出浅灰 |
| `--lift-1..3` | **浮一档** | 加白 | 压出更浅的灰（**白底上加白是看不见的**）|
| `--ink-1..3` | 投影的墨色 | 0.28~0.55 | **0.04~0.10** |
| `--sem-*` | 红/黄/绿/橙的**语义** | 暗底调的亮色 | 同色相压明度，过 4.5:1 |
| `--hl-bg` / `--hl-fg` | 选中/激活的**实心底** | accent ＋ 近黑字 | **近黑底 ＋ 白字** |

三条踩过的坑：

- **投影黑度也要跟主题走。** 95 处 `box-shadow` 的黑（0.28~0.6）是照暗底调的，
  压白底上就是一圈脏晕（用户原话：「投影太重了 太脏了」）。
- **语义色不能只换明度不管色相**，也不能只保色相不管对比度 ——
  用户认的是「粉＝出错、黄＝注意」，换色相等于换语义；而暗底调的粉在白底上
  对比度只有 1.4~1.9，等于没有字。
- **亮色下高亮要黑底白字。** 白底上一块低彩度的蓝跟周围浅灰拉不开距离，
  「选中」这件事传达不出去。暗色维持 accent —— 暗底上它已经是最亮的一档。

### ⑤ 深色条的两层：窗 ＞ 窗里的分区

亮色主题下有两条**刻意的深色条**，它们不遵守「靠明度差分层」那条规矩 ——
因为它们承担的是「**这是一扇窗**」这个信息，而不是层级：

```
.cframe-head  #1c1c1c / 字 #f2f2f2   ← 窗（最强）
.pane-header  #333333 / 字 #d0d0d0   ← 窗里的分区（弱一档）
```

**底和字必须同时退档**：只压底色的话，两条上的白字一样亮，
眼睛仍然会把它们读成同级，「谁装着谁」就丢了。

## 两个主题的手法不一样

| | 暗色 | 亮色 |
|---|---|---|
| 层级主力 | **明度差**（`#0d0d0d → #171717 → #1c1c1c → #212121`）| **投影**（`#fff → #f7f7f8 → #fff`）|
| 投影 | 几乎看不见，只做点缀 | 分层主力 |

白底上 `#fff → #f7f7f8` 差得太少，光靠明度分不开浮层；暗底上投影几乎看不见。
**照搬另一边的手法就会「层级糊成一片」。**

配色基准：ChatGPT / Codex 网页那套（用户 2026-09-02 选定）——
近中性灰、极低彩度、强调色只用于可点/激活且面积极小。

## 跨文件同步清单

| 改了这个 | 必须同时改 | 不改的症状 |
|---|---|---|
| `themes.ts` 的 `ThemeId` | `base.css` 里对应的 `:root[data-theme='…']` 块 | 切过去令牌不变，界面纹丝不动 |
| 新增主题 | `XTERM_THEMES` 里那一支 | 终端还是上一个主题的配色；**亮色下最致命** —— 暗色前景 `#d8dae0` 放白底上对比度不到 1.3:1，等于没有字 |

| 实心 accent 底上的前景 | 一律用 `--on-accent` | `check-accent-contrast.mjs` 会拦 |

## 真机怎么验

起隔离实例（`npm run verify`），`document.documentElement.setAttribute('data-theme','light')`
切过去，然后在 DOM 上量。三条量法上的坑，都实际栽过：

1. **数描边要按 `border-width`，不是 `border-style`** —— `style: solid` 但宽度 0 的元素
   也会被算进去（颜色是继承来的 `currentColor`），一次量出 1586 处「明显边」，全是假的。
2. **往上找背景色时，判据是 `alpha > 0.5`，不是「字符串以 rgba(0,0,0,0 开头」** ——
   后者会把 `rgba(0,0,0,0.028)`（`--lift-1`）当成透明，一路找到暗色祖先，
   量出一堆假的「对比度 1.08」。
3. **改了令牌名要回头看检查器还认不认。** 47 处 `var(--accent)` 迁成 `--hl-bg` 之后，
   `check-accent-contrast.mjs` 当场瞎了却照样报绿 —— 改完做一次变异测试
   （故意造一处违规，看它拦不拦）。
