## 用户原话

> 你还记得之前做的插件窗口吗，这个插件是如何和 harness 进行通信的，如何做一个协议，能让我这里的插件可以和任何 harness 互通，并且可以读到插件里面的前端，前端面板可以被渲染显示在插件模块中。
>
> 一期收窄只做自家插件；面板可独立于会话；示例插件做看板；出实现方案。

## 一、已拍板的决定

| # | 决定 | 理由 |
|---|---|---|
| 1 | **插件 = 一个标准 MCP server（stdio）+ 一份我们的清单 + 若干 `ui://` HTML 资源**。工具层全靠 MCP，不发明新 RPC | 三个 harness（Claude Code / Codex / omp）唯一的交集是 MCP；omp 的 `session/new` 只吃 stdio（`omp/launch.ts` `readMcpServers` 明写 http 型会让整个 session/new 失败）。stdio 是最大公约数 |
| 2 | **会话里的插件不由 harness 直接 spawn，而是经一个转发 shim（`mcp/eas-plugin-shim.mjs`）走现有 HTTP 网关到宿主里的那**一个**插件进程** | 若 harness 自己起进程，模型调工具我们一无所知，「模型调了 `board_add` → 面板刷新」做不到；而且面板一个进程、每个会话再一个进程，一个插件轻松四个进程（bizone 每会话 93MB 的教训）。转发 shim 就是 `eas-mcp.mjs` 的既有形状：每会话一个轻量 shim，共享一个后端。三家都能连 stdio shim，omp 也过 |
| 3 | **界面层按 MCP Apps 做**：工具 `_meta.ui.resourceUri` 指向 `ui://…`，宿主 `resources/read` 取 HTML，放进 sandbox iframe，postMessage 上跑 JSON-RPC。方法名集中在**一个**纯函数模块 `appsProtocol.ts` 里映射 | 让同一份面板在 Claude.ai / VS Code 等 MCP Apps 宿主里也能显示。规范仍在演进，方法名只能改一处（`LONG_WAITS` 两处不一致那类坑提前避开） |
| 4 | **Eas-Term 特有能力全部挂 `eas/*` 前缀，作为 `ui/initialize` 的 `_meta.eas` 扩展**；别的宿主忽略即可 | 标准里没有画布、Frame、项目的概念；放进命名空间不污染标准、不破坏面板在别处运行 |
| 5 | **面板 = 画布组件节点 `component.type = 'plugin-panel'`，插件身份放 `props`**；只注册这**一个**组件，不把插件 push 进 `CANVAS_COMPONENTS` | 组件表是编译期数组，插件是运行时发现的；`component.type` 一经发布不能改名（组件协议纪律）。一个类型 + props 让旧画布节点不受影响 |
| 6 | **面板独立于会话**（用户拍板）：打开面板不起对话；「带着它开对话」是 picker 里另一个动作，复用 L1+L2 那条路 | 看板本来就不该依赖一次对话。两个动作共用同一个插件进程（决定 #2 的引用计数） |
| 7 | **自家插件的 `cli` 不固定**：`PluginInfo.cli` 联合加 `'eas'`；带它开对话时 CLI 走 `resolveConversationCli` 的默认挑选，不像 Claude/Codex 插件那样钉死 | 自家插件是 harness 无关的，钉死某一家反而错。全仓库 `plug.cli` 只有 1 处使用（`CanvasStage.onPickPlugin`），改动可控 |
| 8 | **插件目录 `~/.eas/plugins/<name>/`，只读扫描、绝不写入；示例「看板」随包分发在 `resources/plugins/board/`，以内置身份列出** | 延续 `plugins.ts` 的纪律（装插件是用户的事）。示例放包内才能随版本更新，不会被用户改坏后失去样板 |
| 9 | **示例看板的数据落在项目内 `<cwd>/.eas/board.json`，由插件 server 自己读写，不用 Eas-Term 的 `todos:*` IPC** | 插件只能用两样东西：MCP 和面板桥。样板若偷用内部 IPC，就不是一个能拿去别的宿主跑的插件 |
| 10 | **沙箱是一期验收项不是可选项**：`sandbox="allow-scripts"`（**不给 `allow-same-origin`**）、主进程注入 CSP、HTML ≤ 512KB、桥只放行白名单方法、`eas/canvas.call` 只透传 `mcpHandler` 已有白名单 | 这是本方案唯一新增的攻击面 |
| 11 | **一期不做**：导出为 Claude/Codex 插件、接第三方 MCP Apps server、OpenAI Apps SDK 兼容、抽屉「组件」分区动态列插件、分屏视图里的面板 | 用户拍板收窄。面板和其它组件一样只在画布 |

## 二、隔离契约（只许「加」）

- 现有两家插件（`cli: 'claude' | 'codex'`）的扫描、点选、合并逻辑**一个字节不动**；新增分支全部判 `plug.cli === 'eas'` 或 `plug.panels?.length`——对旧数据恒为 no-op。
- `agentMcpConfigPath(pluginId)`：只在 `plug.cli === 'eas'` 时把该插件写成**shim 条目**（决定 #2），其余仍走 `substPluginVars` 原路。
- `CanvasNode.component` 结构不变；`plugin-panel` 只是一个新的 `type` 值。`canvas.json` 老文件读进来没有这个类型，什么都不会发生。
- `mcpHandler.ts` 不新增工具；`eas/canvas.call` 是**对已有工具的透传**，白名单复用。
- 网关 `mcpBridge.ts` 加两条路由（`/plugin/rpc`、`/plugin/events`），鉴权同 `x-eas-token`；不新开端口。

### M · 清单与扫描

`~/.eas/plugins/<name>/plugin.json`（自家清单，字段名**借 Codex 的 `interface` 块**，现有 picker UI 一行不改就能显示）：

```jsonc
{
  "name": "board",                      // 目录名一致；`eas:<name>` 是 PluginInfo.id
  "displayName": "看板",
  "description": "项目待办三栏看板",
  "brandColor": "#5E6AD2",
  "composerIcon": "./ui/icon.svg",       // 相对清单；主进程解成绝对路径（同 iconAbs）
  "defaultPrompt": "看看这个项目的看板，有什么该推进的",
  "mcp": { "command": "node", "args": ["./server.mjs"], "env": {} },   // 相对路径以插件目录为基
  "panels": [
    { "id": "main", "title": "看板", "tool": "board_show",
      "entry": "ui://board/panel",       // 经 server 的 resources/read 取（标准路径）
      "defaultSize": { "w": 460, "h": 340 } }
  ],
  "permissions": { "canvas": ["canvas_open_file", "canvas_add_note"] }   // eas/canvas.call 的允许集
}
```

`pluginManifest.ts`（纯函数，**测**）：`parseManifest(json, dir) → { ok, info?: PluginInfo, errors }`。校验：`name` 只许 `[a-z0-9-]`；`mcp.command` 必填；`panels[].entry` 必须是 `ui://` 或插件目录内相对路径（`..` 拒）；`permissions.canvas` 每一项必须在 `CANVAS_CALL_ALLOWLIST`（见 B）里，不在的**丢弃并记 warning**，不整份拒绝。

`PluginInfo` 扩展（`shared/types.ts`，只加字段）：

```ts
cli: 'claude' | 'codex' | 'eas'
panels?: { id: string; title: string; tool?: string; entry: string; defaultSize: { w: number; h: number } }[]
permissions?: { canvas?: string[] }
mcp?: { command: string; args: string[]; env: Record<string, string>; cwd: string }   // 仅 eas
```

`plugins.ts` 加 `easPlugins()`：扫 `resources/plugins/*`（内置）+ `~/.eas/plugins/*`（用户），同名**用户覆盖内置**。`plugins:list` 返回三家合集，顺序：eas → codex → claude（自家在前）。

### H · 宿主进程

**一个插件一个进程，引用计数复用**（决定 #2）。`pluginHost.ts`：

```ts
interface Hosted { name: string; proc: ChildProcess; client: McpClient; refs: Set<string> /* panelSession | agentSession */; tools: ToolDef[] }
acquire(pluginId, refId) → Hosted   // 没有就 spawn + initialize + tools/list；有就 refs.add
release(pluginId, refId)            // refs 空 → 延迟 30s 再 kill（面板关了又开不抖）
```

进程 spawn：`cwd` = 插件目录；env 只给 `PATH`/`HOME` + 清单里的 `env`；**不注入 `EAS_TERM_TOKEN`**（插件不该拿到网关 token；它需要画布能力走面板桥，不走网关）。

`mcpClient.ts`（零依赖，`eas-mcp.mjs` 的客户端镜像）：`initialize` / `tools/list` / `tools/call` / `resources/read` / 接收 `notifications/*`。一行一条 JSON-RPC，30s 超时；`resources/read` 结果按 `mimeType` 收 `text`，其余拒。**纯解析部分（帧切分、id 配对）抽 `jsonrpcFrames.ts` 测**。

`mcp/eas-plugin-shim.mjs`（会话侧转发，决定 #2）：环境变量 `EAS_PLUGIN=<name>` + `EAS_TERM_PORT/TOKEN`；把 harness 发来的 `initialize` / `tools/list` / `tools/call` 原样 POST 到网关 `/plugin/rpc`，网关转给 `Hosted.client`；`tools/call` 的结果**同时**广播为面板事件（见 B 的 `tool-result`）。缺 `EAS_TERM_PORT/TOKEN` 时 `tools/list` 回空，与 `eas-mcp.mjs` 同一纪律。`agentMcpConfigPath` 里对 `cli==='eas'` 的插件写：

```json
"board": { "type": "stdio", "command": "node", "args": ["<resources>/mcp/eas-plugin-shim.mjs"], "env": { "EAS_PLUGIN": "board" } }
```

网关新增：`POST /plugin/rpc {plugin, method, params}`（x-eas-token）→ `Hosted.client` 调用；`acquire(plugin, 'session:'+ptyId)` 在首次 `initialize` 时，`release` 在 shim 进程退出（网关按 ptyId 收 PTY 退出事件——已有的 `pty:exit` 钩子）。

IPC（渲染层 ↔ 主进程）：

| 通道 | 方向 | 载荷 |
|---|---|---|
| `plugin:panelOpen` | R→M | `{pluginId, panelId, ctx: CanvasComponentCtx}` → `{panelSession, html, tools}`（html 已注入 CSP，见 B） |
| `plugin:panelClose` | R→M | `{panelSession}` |
| `plugin:panelRpc` | R→M | `{panelSession, method, params}` → 结果或 `{error}`；只接受 `appsProtocol` 白名单 |
| `plugin:panelNotify` | M→R（webContents.send） | `{panelSession, method, params}`：`tool-result` / `host-context-changed` / `resource-teardown` |

### B · 桥协议

`appsProtocol.ts`（渲染层，纯函数，**测**）是**唯一**写方法名的地方：

```ts
export const IFRAME_TO_HOST = ['ui/initialize', 'ui/initialized', 'tools/call', 'resources/read',
  'ui/size-changed', 'ui/open-link', 'eas/canvas.call', 'eas/panel.resize'] as const
export const HOST_TO_IFRAME = ['ui/notifications/tool-input', 'ui/notifications/tool-result',
  'ui/notifications/host-context-changed', 'ui/resource-teardown'] as const
export function initializeResult(ctx: CanvasComponentCtx, theme: 'dark'|'light'): InitializeResult
  // → { protocolVersion, hostInfo:{name:'eas-term'}, capabilities, _meta:{ eas:{ context: ctx } } }
export function canvasCallAllowed(tool: string, manifestAllow: string[]): boolean
  // 双白名单：CANVAS_CALL_ALLOWLIST ∩ manifestAllow。CANVAS_CALL_ALLOWLIST 一期只有
  // canvas_open_file / canvas_open_url / canvas_add_note / canvas_focus_node
export function routeIframeMessage(msg: unknown): { kind: 'rpc', method, id, params } | { kind: 'drop', why }
```

> ⚠️ **方法名以 `@modelcontextprotocol/ext-apps` 当前版本为准**。上表按 2025-11 的 SEP-1865 写，
> 动手第一步是对照 SDK 的 `types.ts` 逐个核对并只改这个文件；核对结果钉进图纸 11。

`panelHtml.ts`（主进程，纯函数，**测**）：`prepare(html) → { ok, html } | { ok:false, why }`。
① 长度 > 512KB 拒；② 在 `<head>` 首部注入 `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; connect-src 'none'; frame-src 'none'">`（已有 CSP meta 时**替换**，不叠加——两条 CSP 取交集会把插件自己允许的东西也掐掉，行为难查）；③ 把 `<a target=_blank>` 与 `window.open` 交给 `ui/open-link`（面板不能自己开窗）。

面板侧的 postMessage 校验（`PluginPanel.tsx`）：只处理 `event.source === iframe.contentWindow` 的消息（srcdoc iframe 的 origin 是 `"null"`，**不能拿 origin 当判据**）；每条必须过 `routeIframeMessage`。

### P · 面板组件

`registry.tsx` 加一项：

```ts
{ id: 'plugin-panel', name: '插件面板', Icon: PlugIcon, defaultSize: { w: 460, h: 340 }, needsProject: true,
  render: (ctx) => <PluginPanel ctx={ctx} /> }   // 插件身份在 ctx.props: { pluginId, panelId }
```

`PluginPanel.tsx` 生命周期：mount → `plugin:panelOpen` → `<iframe sandbox="allow-scripts" srcdoc={html}>` → 收 `ui/initialize` 回 `initializeResult(ctx)` → 转 `tools/call`/`eas/*` 到 `plugin:panelRpc` → 订阅 `plugin:panelNotify` 推给 iframe；unmount → `plugin:panelClose`。头部复用 `.cfile-*` 外壳（组件协议已定），标题 = `panel.title`，右上多一个「刷新」（重新 `resources/read`，改面板 HTML 时不用重开）。

`CanvasFilePicker` 插件 tab：`cli==='eas'` 且有 `panels` 的条目**多一个动作**——「打开面板」（`addComponentNode(frameId,'plugin-panel',x,y,w,h)` 后写 `props`）；原有「带着它开对话」保留（决定 #6/#7）。

`addComponentNode` 现签名 `(frameId, type, x, y, w, h)` 不带 props → **加可选第 7 参 `props`**（`canvas/types.ts` + `canvasSlice.ts` 两处），旧调用不传即原行为。

## 四、协议消息表（面板 ⇄ 宿主）

| 方法 | 方向 | params → result | 宿主行为 |
|---|---|---|---|
| `ui/initialize` | 面板→宿主 | `{protocolVersion, appInfo}` → `initializeResult(ctx)` | 记录握手；未握手前其它请求一律 `drop` |
| `ui/initialized` | 面板→宿主（通知） | — | 之后才开始推送通知 |
| `tools/call` | 面板→宿主 | `{name, arguments}` → 工具结果 | 只许调**本插件** server 的工具；`arguments._meta.eas.cwd` 由宿主补 |
| `resources/read` | 面板→宿主 | `{uri}` → 内容 | 只许 `ui://<本插件>/…` |
| `eas/canvas.call` | 面板→宿主 | `{tool, args}` → 结果 | `canvasCallAllowed` 双白名单；走 `mcpHandler` 同一执行体与路径白名单 |
| `eas/panel.resize` | 面板→宿主 | `{w, h}` | 夹在 `[240, 1200]`，调 `resizeNode` |
| `ui/size-changed` | 面板→宿主（通知） | `{width,height}` | 同上（标准名，兼容） |
| `ui/open-link` | 面板→宿主 | `{url}` | 只许 http(s)；用 `canvas_open_url` 开成网页节点，不开系统浏览器 |
| `ui/notifications/tool-result` | 宿主→面板 | `{name, arguments, result}` | 会话侧或面板侧任何一次 `tools/call` 完成都推（shim 经网关广播） |
| `ui/notifications/host-context-changed` | 宿主→面板 | `{theme, _meta.eas.context}` | 明暗切换 / 节点被挪到别的 Frame |
| `ui/resource-teardown` | 宿主→面板 | — | 面板即将卸载 |

错误：JSON-RPC 标准 `{code, message, data}`；被白名单拒的用 `-32601`（method not found）而不是自定义码——别的宿主也这么回。

## 五、安全验收项（一期硬性）

1. iframe 属性精确为 `sandbox="allow-scripts"`；测试断言 DOM 上没有 `allow-same-origin` / `allow-top-navigation` / `allow-popups`。
2. 面板里 `fetch('https://…')` 被 CSP 拒（真机验：面板 console 出现 CSP 报错、网关日志无请求）。
3. 面板发 `tools/call` 调**别的**插件的工具 → `-32601`；发 `eas/canvas.call canvas_snapshot`（不在允许集）→ `-32601`。
4. 面板发 `eas/canvas.call canvas_open_file` 传 `~/.ssh/id_rsa` → 被 `mcpHandler` 路径白名单拒（现有锁，验它对新入口同样生效）。
5. 插件进程 env 里没有 `EAS_TERM_TOKEN`（`ps eww` 验）。
6. 600KB 的 HTML → `panelOpen` 返回 `{ok:false}`，面板显示「面板太大」而不是空白。
7. 清单 `name` 含 `../` → 扫描直接跳过并记 warning。

| 1 | `@modelcontextprotocol/ext-apps` 当前版本 | **1.7.5**（2026-07-23）。协议版本 `2026-01-26`；UI 指针是 **`_meta["ui/resourceUri"]`**（扁平键，`RESOURCE_URI_META_KEY`），老写法 `_meta.ui.resourceUri` 兼容读；宿主→面板通知：`tool-input` / `tool-input-partial` / `tool-result` / `tool-cancelled` / `host-context-changed`，请求 `ui/resource-teardown`；面板→宿主：`ui/initialize`、`tools/call`、`resources/read`、`ping`、`ui/open-link`、`ui/message`、`ui/update-model-context`、`ui/request-display-mode`，通知 `ui/notifications/initialized` / `size-changed`（**是通知不是请求**，§四表里原写的 `ui/size-changed` 改正）。`ui/initialize` 结果形状 `{protocolVersion, hostInfo, hostCapabilities, hostContext}`——**我们的 `_meta.eas` 挂在 `hostContext` 下**（它允许附加属性），不挂顶层 | 方法名与常量全部落在 **`src/shared/pluginProtocol.ts`**（主进程与渲染层共用一处） |
| 2 | HTML 资源 mimeType | **`text/html;profile=mcp-app`** | 同上文件 `PANEL_HTML_MIME` |
| 3 | srcdoc sandbox iframe 的脚本能不能跑 | **不能。** 渲染层 CSP 是 `script-src 'self'`，srcdoc / blob / data 文档**继承父页 CSP**，内联脚本被拦（真机实测 `postMessage` 超时，Electron 37.10.3） | **面板改走自定义协议 `eas-plugin://<panelSession>/`**（同 `easfile` 的 `registerSchemesAsPrivileged` + `protocol.handle`），**CSP 用响应头下发**（`panelHtml.ts` 的 `PANEL_CSP`），不往 HTML 注 meta；HTML 自带的 CSP meta **剥掉**（两条取交集难查）。渲染层 `index.html` 的 CSP 加 **`frame-src eas-plugin:`**。iframe 仍 `sandbox="allow-scripts"`、不给 `allow-same-origin`，origin 因而是 opaque——判据仍是 `event.source === iframe.contentWindow` |
| 4 | shim 退出时怎么 release | 主进程 `pty.ts:506` 有 `proc.onExit`，但 shim 跑在 AI 对话会话里（不是终端 PTY），且 `agent-mcp.json` 是 userData 下**一份共享文件**、写不进会话 id | **shim 心跳**：`initialize` 时向网关登记随机 `shimId`，每 15s `POST /plugin/heartbeat`，stdin 关闭时 `POST /plugin/bye`；网关 45s 没心跳即 release。不依赖会话内部实现 |
