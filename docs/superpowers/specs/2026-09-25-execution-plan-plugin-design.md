# 执行计划插件 · 设计规格

> 状态：用户已确认（2026-09-25）。基线：`origin/main` 的 `affc0406`；隔离分支 `feat/execution-plan-plugin-20260925`。

## 目标与已确认的决定

用户希望在 Eas-Term 收到需要执行的任务后，由当前模型把任务拆成可见的待办步骤，推进一项更新一项，而不是只回复「之后会做」。首版仅覆盖 Eas-Term **受管 AI 对话节点**的 Claude Code、Codex、OMP；终端里手动运行的 CLI 不在首版范围。

- 采用随 Eas-Term 分发的**后台业务插件**，不占现有「手选业务插件」槽位，因此可与时间线、看板并存。
- 模型在**同一轮**调用插件工具建立、推进计划；不为分类或拆分另开付费模型轮次。若未调用，给用户可见的「本轮未建执行清单」提示，不替模型编造步骤、不自动重发任务。
- 执行清单按**一次工作目标**建立；一个项目可有多份计划，一份计划可跨同一 AI 会话的多轮继续。项目视图聚合，默认聚焦当前会话的活动计划。
- 计划是过程记录，不是独立验收结论。模型报告完成与用户/验证器验收必须分开。

## 方案比较

| 路径 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 后台插件 + 通用 MCP 工具 | 三 CLI 一套语义；不占手选槽；可热更新 UI | 需要宿主补受管会话身份和后台装配 | **采用** |
| 复用现有看板插件 | 工具、项目存储、面板已有 | 项目卡片不等于单次执行计划；占手选槽；无法自然归属会话/轮次 | 不采用 |
| 镜像各 CLI 的原生任务列表 | Claude 原生体验好 | Codex/OMP 契约不一；私有存储与版本变化；多套状态分叉 | 不采用 |

## 业务语义

### 计划与步骤

一份计划含稳定 `planId`、项目根、创建它的受管会话 ID、来源轮次 ID、标题、状态、步骤顺序、时间戳与版本号。步骤含稳定 `stepId`、短标题、完成判据、状态、模型给出的依据摘要、更新时间。最小状态：`pending`、`in_progress`、`blocked`、`reported_done`；另有独立 `accepted` 标记，首版仅由用户在面板中显式确认设置（不开放给模型工具）。

面板把 `reported_done` 画为已勾选，但同时标「模型报告完成 · 待验收」；`accepted` 才显示「已验收」。勾选不等于自动证明正确。允许模型追加/调整未完成步骤；已完成步骤的标题、依据与历史更新不能无痕覆盖。用户可在面板撤回勾选或验收。

### 何时建、何时续

受管会话的提示只要求**多步骤执行任务**在真正行动前调用 `plan_create`；普通问答、单步小操作无需人为膨胀成计划。工具说明要求计划保持短小、可验收，不把每条 shell 命令拆为步骤。

模型在同一会话继续已有工作时调用 `plan_get`/`step_update`；遇到新的独立工作目标调用 `plan_create`，不覆盖旧计划。宿主维护当前会话的活动 `planId`，但不凭一条自然语言消息猜新旧任务。用户在面板可切换、归档计划。自动重试同一轮时，`plan_create` 以宿主签发的来源轮次 ID 幂等，不能重复长出两份。

### 没有建计划的轮次

宿主只记录**结构化工具回执**与真实 CLI 事件，不用正则解析「我会」「已完成」推断计划。轮次结束仍没有 `plan_create` 时，对话尾部显示低强调度的「本轮未建立执行清单」；若该轮发生过执行/编辑工具调用，文案加强为「已执行但未建清单」。普通问答也可能出现前一种中性提示，不能将其标成错误。提供「让 AI 补建」操作，但必须由用户发起新消息；不自动唤醒模型。

**明确限制**：选择了零额外模型调用后，宿主无法可靠地判定一条纯文本回复本应执行还是只应讨论。因此这个提示能暴露缺席，不能保证模型每次都建计划，更不能自动补齐漏掉的执行。

## 插件与 CLI 接线

`resources/plugins/execution-plan/` 包含 Eas-Term 插件清单、stdio MCP 服务、项目内存储与 `ui://` 面板。它随应用分发，可在设置中独立停用；启用时作为**基础后台服务**追加到受管 AI 会话的 MCP 组合中，不替换手选业务插件，也不覆盖用户已有 MCP 配置；停用时不注入建计划提示，也不显示漏建提醒。Claude、Codex、OMP 都使用现有会话 MCP 装配路径；首次启动、参数变更后的 restart、resume 必须一致。

模型可见的工具仅限 `plan_create`、`plan_get`、`plan_list`、`step_update`、`plan_archive`（必要时增补少量字段，不另起平行写接口）。工具回执含 `planId`/`stepId`/版本与错误码，不回传整个项目历史；列表分页、有界。计划面板读取与工具结果通知沿用插件宿主的面板 RPC / fanout，不轮询、不额外模型调用。

现有普通插件 shim 只携带项目路径，不能直接让模型自报 `sessionId`/来源轮次。宿主必须从**受管会话租约**验证调用者身份，绑定项目真实根与当轮 ID，再将可信元数据传给插件；模型参数里的路径、会话 ID、验收身份均不作为授权依据。不能为此放宽 `fsGuard`、泄漏全局网关 token，或改变主进程 `whenReady()` 的既有注册顺序。首版不接终端 PTY，因为那里缺受管任务身份与相同的生命周期闸。

## 持久化与冲突

项目数据放在项目根 `.eas/execution-plans.json`，不混进终端手动 `todos.json`、看板 `.eas/board.json` 或时间线 `.eas/timeline.json`。宿主在交给插件写入前校验项目根及目标路径；插件存储层再拒绝软链、超大/损坏记录，使用原子替换与同项目写锁，坏库不以空表覆盖。写入基于 `version` 做冲突检测；两个会话同时推进同一计划时，不允许后写整份覆盖前写。

UI 默认只取活动计划摘要与当前步骤，展开才请求详情/历史。面板关闭、会话重启、应用重启后仍能按项目与会话定位原计划；插件热更新/卸载时遵守现有宿主失效与重新握手生命周期，不留旧进程继续写。

## 界面与视觉

沿用 Eas-Term 现有插件面板视觉，不另换一套风格。AI 对话节点在出现计划后显示紧凑进度入口（如 `2/5 · 当前：验证字幕同步`），点击打开完整插件面板；**不擅自在画布上新建节点**。完整面板按计划标题 → 当前步骤 → 全部步骤逐层展开，状态、完成判据、依据和“待验收”明确分层。空态、暂停/中断、受阻、插件不可用、同步冲突、只读角色、重启恢复都有可读状态；小尺寸面板可用键盘操作，不用颜色单独表达状态。

## 验收与非目标

1. 同一项目的 Claude/Codex/OMP 受管节点均能看见同一套工具；绑定时间线或看板时计划插件仍可用。
2. 模型创建 3 步计划、推进、报告完成后，面板同步；重开应用与恢复 CLI 会话后不丢；不同项目/会话不串。
3. 工具回执失败、坏数据、软链、跨项目路径、伪造 session/turn、并发版本冲突都不能伪造勾选或覆盖数据。
4. 未建计划的纯文本结束轮显示中性提示；执行过工具但未建计划显示较明确提示；均不自动付费重试。
5. 安全分叉重试与重复工具调用只产生一份计划、一次步骤状态变化；取消/停止后迟到回执不能标记当前轮。
6. 单测覆盖状态机、身份/路径、幂等与并发；隔离应用眼验三 CLI 装配、面板、恢复及插件替换；构建、全量检查与 Windows CI 在合并/发版阶段分别确认。

首版不读取或改写 Claude Code 私有 `~/.claude/tasks/`，不覆盖终端里手动运行的 CLI，不替用户自动批准计划，不把模型自述当作测试结果，不做云同步或自动执行调度。
