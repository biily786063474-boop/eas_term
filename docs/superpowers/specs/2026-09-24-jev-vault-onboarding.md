# Jev 凭证、等待反馈与密钥柜免输码 · 实施说明

## 用户问题与根因

- Jev 面板的异步 `action` 仅设置内存 `busy`，没有可见状态，也没有禁用重复验证。
- 插件配置 `save` 在密钥柜锁定时被主进程租约拒绝；设置页不弹解锁，且原实现无论成功失败都清空草稿，所以用户输入的 API Key 会丢失。
- Jev 的 `panel/grant connect` 在锁定时也只返回错误；六位码仅解锁进程内 15 分钟，没有用户可选的设备信任。

## 交互与安全边界

1. 保存/测试等用户发起操作发现密钥柜锁定时，在原设置对话框内显示 `VaultGate`，保留未提交草稿。解锁后继续原操作；取消原生保存确认或操作失败都不清空草稿，成功保存后才清空。
2. Jev 验证连接发现锁定时由宿主显示同一个解锁 UI，并立即结束当前面板 RPC；解锁后用户再次点“验证”。不跨越面板 RPC 的 35 秒超时等待六位码，也不擅自发起可能收费的请求。原生“验证连接”确认继续保留。
3. Jev 等待时显示文本与旋转指示、禁用重复验证；`prefers-reduced-motion` 下不旋转。
4. “信任此设备，以后免输六位码”默认关闭，仅用户勾选/在已解锁柜内主动开启。只持久化布尔开关；密钥仍由 Electron `safeStorage` 加密，Key 与六位码不写明文。OS 安全存储不可用或 Linux `basic_text` 后端不得开启。手动锁定立即撤销设备信任并终止插件凭证租约；重启后仍要求六位码。
5. 插件 Key 保存于**插件专属的加密凭证库**，受密钥柜解锁保护，不与通用密钥分组混存；UI 明确说明这一点。密钥值不回显、不进日志，不暗示“连接已验证”。

## 验收边界

使用隔离 HOME/userData、假 Key 和离线 Jev 服务夹具，验证原地解锁、加密落盘、等待状态、测试连接二次确认、重启免输码及手动锁定撤销。真实 TypeSafe 账号/付费调用与 Windows 不纳入本轮通过项。
