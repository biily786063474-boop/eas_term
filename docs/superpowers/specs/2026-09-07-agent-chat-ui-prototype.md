# Eas-Term 启动页与聊天页：Figma 原型方案

状态：Figma Review 01 主界面经用户“那就改吧”批准，已在隔离分支实施并验证。新增提问目录先补 Figma，待用户审查后接入代码。

最新约束：用户之后要求主操作不换行，AI pane 最小宽度改为 640px；本文件下文的 480px 自然换行描述保留为早期设计历史，实施以新约束为准。安装引导与旧功能接入审查见 `2026-09-07-startup-install-audit.md`，各原型状态的实施范围和验证边界以该审查文档及验证 README 为准。

## 目标与范围

使用 Eas-Term 已有内容和交互，参考 Codex 客户端的克制布局、清晰阅读层级和状态反馈。保留画布工作台、项目、CLI、角色、分支、首轮模型/强度、插件、工具执行、资源、审批、语音、停止与用量。模型目录和可用控件仍由公共能力驱动。

上一版功能基线为 0764b25。用户确认 Codex / Claude Code / omp 共享风格后批准实施；能力差异继续由公共协议驱动。

## 启动页

主画板 1440×960，主操作区最大宽度约 720px；另外画 480×900 的画布窄面板。保留现有“伟大的产品始于一句‘你好’”文案，标题与输入卡片形成一个视觉重心。标题 28/36、字重 600–700，采用项目系统字体，不引入品牌字体。

输入卡片上半部放首条消息，空态约 100–120px 高，随内容增长。下半部放启动模型、思考强度、刷新；语音与发送始终成组。卡片内一行次级提示明确“首条消息使用 GPT-5.6-Sol”。未显式选择时保留真实的“跟随 CLI 配置，启动时确认”，不把模型列表的第一项当默认值。

项目目录、CLI、角色、分支作为输入卡片下方的运行上下文行；切 CLI 后立即显示该 CLI 的模型读取状态，原型演示 Codex/Claude/omp 的能力差异。历史入口维持折叠，避免历史内容占据首次操作的中心。

窄面板将参数自然换行，保证发送和语音成组、错误提示可读，长模型名截断但下拉完整显示。内容宽度由节点决定，不依据整个桌面的宽度。

## 聊天页

正文与底部输入卡片对齐到同一条阅读中轴，最大宽度约 760px。保留已有提问吸顶机制；用户提问使用低对比背景，模型正文保持开放排版。正文 14–15px、行高约 1.7，段落留白 12px，轮次间距约 24px。最终数值以原型眼验为准。

工具执行显示为轻量行，默认折叠详情；错误以图标、文字和语义色共同表达，保持失败项可见。资源链接与工具结果相邻。审批仍是较高层级的独立卡片。正文、链接、代码复制、工具展开等已有能力不能被装饰覆盖。

底部输入卡片与启动页使用相同圆角、边框、焦点反馈。模型和强度是主要参数，插件/目录来源/沙箱说明是次级信息；语音和发送/停止固定成组。用量放在卡片下方轻量展示，原型只用已有字段，不模拟未知精确数值。

## 视觉基础

沿用现有 token：背景 --bg #0d0d0d，正文 --t-1 #ececec，次级正文 --t-2 #b4b4b4；强调色 --accent #dfe3e8 与 --on-accent 成对使用。输入面使用 --lift-2，边框 --stroke-input。Figma 内建立语义变量与文本样式，亮色模式复用项目亮色映射，不写一套独立品牌色。

圆角分级：输入卡片约 20px，菜单/工具详情约 10px，小控件约 7px；不把所有内容做成同样的胶囊。控件保留明确焦点状态、可读标签和热区。运行中的球形指示器保留为 Eas-Term 已有内容，不新增装饰性背景动画。

## 原型连线与动效

| 触发 | 结果 | 建议过渡 |
|---|---|---|
| 点击模型 | 打开模型菜单 | 120–160ms 淡入与轻微位移 |
| 选择模型 | 菜单关闭、首轮摘要更新 | 120ms 状态淡变 |
| 点击发送 | 启动页进入回复中 | 180–220ms 过渡；保持输入卡片视觉连续 |
| 展开工具 | 展示详细结果 | 160–200ms 展开状态；实际实现优先 transform/opacity |
| 点击停止 | 停止态、继续输入可用 | 120ms 按钮状态切换 |
| 模型读取失败 → 刷新 | 加载 → 目录返回 | 状态文案与轻量加载反馈 |
| 减弱动态效果 | 相同状态与布局 | 关闭位移和循环动效，直接切换或短淡变 |

上述时长是待审查的设计建议，不声称是 Codex 客户端的私有动画参数。Figma 原型需提供可点路径、交互标注与组件状态；不能以一张截图冒充可编辑原型。

## 审查顺序

1. 先审启动页主布局及“发第一句前可选模型”是否明确。
2. 再审聊天阅读宽度、执行记录层级与输入区域。
3. 最后审窄窗口、亮色、错误/审批和动效。

Figma 文件创建并逐页截图检查后，提交设计链接供用户审查；取得用户明确认可后才改代码。

### 原型边界

这是视觉与交互提案，Figma 不执行真实 CLI、不录音、不发送真实消息。窄面板和亮色主要用于布局审查；尚未给每个次级操作制作完整业务流程。动效以 120–200ms 淡变为主，减弱动态效果作为实施约定标注。完整实际业务行为在用户通过原型后按公共能力模型实现。

主界面已在 codex/agent-chat-codex 分支实施：启动模型收进输入卡片、运行上下文下置、聊天阅读宽度与输入框对齐、刷新/语音/发送/停止图标化、强度下拉、窄 Frame 和减弱动态效果支持。未合并或发布。

## 新增提问目录（待审查）

用户截图对应当前对话内的提问索引：每次用户提问一条刻度，当前阅读位置变亮且加长，悬停预览该问题及回复摘要，点击定位对应轮次。计划复用公共 turns，不按 CLI 分支。
