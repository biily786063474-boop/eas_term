# 页面开发观察窗 × 汇报页联动 · 设计规范

## 目标与范围

AI 开发本机网页时，用户在同一工作台里看到调试画面；当**同一会话明确提交**一份本地 HTML 汇报页后，右侧观察区变成上方调试页、下方汇报页。两区分别支持软件内沉浸式最大化，并能返回原上下布局。不得以模型回复文本、文件名或 HTML 标题猜测“汇报页”。

这是一项 Eas-Term 宿主能力，不依赖 Jev 或第三方插件安装。首版覆盖三种受管 CLI（Claude、Codex、OMP）经同一 MCP 工具提交的本地 HTML；不接管外部 Chrome，不改变观察窗仅限 loopback 开发服务器的边界，不把本地文件路径传给 `page_live_open`。

## 决策与取舍

采用**显式提交事件 + 宿主归属校验**，不用 prompt-only、自然语言识别或扫描磁盘。新增语义明确的 `canvas_publish_report` 工具，输入只有项目内 HTML 路径；它沿用 `canvas_open_html` 的真实路径、文件存在性、Frame 归属和同文件复用规则，同时额外登记 `agentLeafId / frameId / nodeId / 规范化路径` 的关联。工具成功是唯一自动进入双页布局的信号。普通 `canvas_open_html` 保持原行为，不误触发。

模型漏调时，用户可在已授权的 HTML 节点上手动选择“在观察窗中作为汇报页显示”。这一动作也走同一宿主校验，不接受任意文本路径。模型是否主动调用工具影响召回率，**不影响识别准确性**；不能承诺三家模型 100% 主动调用。

受管能力说明仅补一条短触发规则，指导“本次产出供用户阅读的 HTML 汇报页用 `canvas_publish_report`；普通 HTML 仍用 `canvas_open_html`”。不按插件安装注入默认提示词，不在每轮对话重复长文，不覆盖用户或项目指令。保留现有 `page_live_open` 仅用于本机网页开发、`canvas_open_html` 用于其他 HTML 的规则；同步修改 `canvas.md` 以消除两种提交入口的歧义。MCP 工具描述仍是调用依据，不能把提示词当成功证据。

## 交互与状态

1. **只有调试页**：维持现有右侧抽屉与画板 AI 模块内预览；无空白的“汇报页”占位。
2. **明确提交汇报页后**：若该 AI leaf 有可见或可恢复的观察会话，右侧抽屉内容切为上调试、下汇报，默认 55/45；分割线可拖动且限制两边最小可读高度。原有 440ms 抽屉滑入不改；双页内容转场克制，禁用突然闪白。若还没有观察会话，汇报页仍按原规则进入所属 Frame，不凭空启动调试浏览器；之后同 leaf 打开观察窗时可组合。
3. **沉浸最大化**：调试区和汇报区各有独立最大化按钮。点任一项后仅软件内观察区域铺满可用工作区，另一项暂时隐藏但状态保留；Esc 或“返回上下分屏”恢复。按 Esc 只退出当前观察最大化，不误退出 AI 面板、画布或系统全屏。现有“弹出独立窗口”保留，弹出的仍是同一调试浏览器会话；它不代表最大化。
4. **视图切换**：分屏模式的抽屉不被 `canvas_publish_report` 强制切到画板。画板模式继续在当前 AI 模块里展示观察窗和汇报页，空间不足时退化为纵向布局；用户主动切到画板中的汇报节点时，原节点仍可独立阅读与现有最大化。返回分屏时恢复所属会话的组合状态，不复制调试会话。
5. **关闭与回退**：收起观察区只停捕帧，不删除汇报关联；结束调试会话后汇报页仍留在 Frame；关闭或移走汇报节点后退出双页模式；文件删除/移动或授权失效时下区显示明确错误与“在 Frame 中定位”入口，不静默展示旧内容。会话结束或 leaf 删除时清理临时关联与浏览器资源，报告源文件及原 Frame 节点不随之删除。

## 数据流与安全边界

- `canvas_publish_report` 在现有 MCP→renderer `mcpHandler` 路径中取得可信 `ctx`；使用 `safePath`、`probePaths` 与提交后的再归属检查，成功才登记关联。主进程不得接受未经校验的任意 `file://` 导航。不得因双页布局放宽 `fsGuard`、外部资源加载或 Electron webview 的现有沙箱设置。
- 当前 `canvas_open_html` 经 `openArtifact()` 会切换 `viewMode` 为 canvas；专用提交入口需把“创建/复用 Frame 节点”和“是否切换视图/聚焦”分离，只在新入口保持当前分屏。旧工具继续保持原切换行为。
- 关联按 agent leaf 和 Frame 绑定，不按全局“最近一份 HTML”绑定；多个同时运行的观察会话不串页。切换 active leaf 时只显示该 leaf 的汇报/调试组合，其他会话暂停捕帧。仅记关联元数据，不把页面内容或截图送入 LLM 提示词、日志或远端。
- 汇报页本地 HTML 使用已有受限 webview 预览能力；分屏时仅挂载当前可见的一个汇报 guest，画板节点在该模式下不同时挂第二份。离开视图释放或复用 guest 时保留路径和滚动恢复信息；若不能可靠保留精确滚动，则在实现验收前不得声称“恢复阅读位置”。不得把汇报页塞进只允许 loopback 的 `livePage` BrowserWindow。
- 最大化状态由观察区局部状态持有，并接入现有 `fullscreenOverlay` 键盘所有权机制；Esc、关闭、切 leaf、popout 的优先级必须明确，不能抢其他全屏模块的热键。

## 验收与不做

- 三家 CLI 的同一 `canvas_publish_report` 调用均能在**有观察会话**时出现双页；普通 `canvas_open_html`、回复里提到路径、报告样式普通 HTML 都不触发。
- 不同 leaf、不同 Frame 的报告不串联；旧授权/失效路径不能加载；报告删除、节点关闭、会话关闭、观察窗崩溃均有可见回退。
- 分屏、画板、窄屏、亮暗主题、减少动效分别验证：上下布局、拖动分割线、两区最大化、Esc/按钮返回、独立弹窗、切换 leaf、原 Frame 节点复用与刷新。
- 检查 guest 数量、隐藏捕帧定时器、长时间任务中的内存/CPU，避免为了双页预览永久运行两份相同报告。构建、全量测试、隔离应用实际打开并截图；Windows 和在线三模型端到端如未运行需单列未验证。
- 首版不提供 DevTools 嵌入、外部 Chrome 同步、任意远程 URL 汇报、自然语言自动分类、报告版本历史或自动录制。
