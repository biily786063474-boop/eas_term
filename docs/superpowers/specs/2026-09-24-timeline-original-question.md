# 时间轴成果记录保留用户初始问题 · 设计规格

## 目标与定义

用户希望时间轴一项成果同时回答“用户最初要解决什么”和“最终完成了什么”。“初始问题”指**发起该成果/任务的用户原话**，不是对话会话的第一句话，也不是 AI 的成果摘要。详情页在成果摘要之前展示独立的「用户初始问题」。

## 范围与原则

- 项目内 AI 主动记录：`timeline_record` 增加可选 `originalQuestion` 字段；插件指令要求有明确来源时传用户原话，禁止模型编造；旧记录或没有可确定原话的成果可以缺失。记录相同 `taskKey` 的后续更新若省略该字段，应保留原值，不能意外擦除；明确的新原话可修正。
- 全局记录候选：宿主仅在用户授权的完成轮次采集本轮用户消息，关联到事件；当用户只说“继续/好的”等续接语时，沿用会话内最近一次明确任务请求；无法可靠对应时不填，绝不把会话开场白或系统提醒误写成初始问题。采集来源仅限主进程真实 `user.message`，不读取历史、不调用额外模型、不改变授权范围。
- 自动候选在确认收录后把 `originalQuestion` 写进正式成果；待确认列表也显示该字段。直接 `timeline_record` 成功的轮次仍不生成重复候选。
- 本地 `.eas/timeline.json` 维持 `version:1`，新增字段可选。旧记录可读；UI 缺字段时显示「未记录」，不得反推。列表仅返回标题等摘要，原话只在详情/候选按需读取。
- 字段限制：非空字符串，最多 4000 字；主进程事件只传白名单字段并限制长度，避免无界事件/存储。UI 全程用 `textContent`，防止原话含 HTML 时被解释。

## 数据路径

1. 用户消息 → `agentChat/session.ts` 的现有 `user.message` 事件 → `pluginEvents.ts` 轮次缓冲的 `originalQuestion` → 项目授权事件总线 → `candidateFromEvent`。
2. AI 工具调用 → `server.mjs` 的 `timeline_record` schema → `store.mjs` 校验与更新 → 项目 `.eas/timeline.json`。
3. 自动候选 → `candidates.mjs` 持久化 → 用户确认 → 同一个 `record()` → 详情页 `panel.html`。

## 边界与验收

- 不改会话投递顺序、CLI 启动、权限、插件事件授权或沙箱；不触碰全量历史和已有真实记录。
- 测试覆盖：主动新增/幂等更新/省略时保留/旧数据读取/非法字段；真实用户消息与续接语关联、失败取消/撤销不入库；候选确认贯通；详情页有/无字段、HTML 原话安全显示。
- 构建并打开隔离实例，在时间轴详情与候选原位置亲眼验证；自动化回归失败原样报告。正式用户数据不作迁移写入。
