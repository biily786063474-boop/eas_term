# skill 管理面板

**日期**：2026-08-14
**范围**：在画布里查看 / 组织 / 临时禁用各 CLI 的 skill，并给 agent 开一个受 schema 约束的分类口子。

---

## 用户原话

> skill 管理面板（单独一个模块，可扩展可维护）
>
> 在对应的项目 frame 中可以查看不同 cli 的全局 skill 和 cli 可以通过点击 cli 按钮
> 来选择 skill 目录，当前项目的项目 skill 放到知识库抽屉中，没选中 frame 的情况下
> 显示全局 skill，点击知识库抽屉左上方名称通过下拉菜单切换，用户可点击 skill 名称
> 来查看 skill 的详细文件树，文件树可以拖拽到画布上进行编辑，skill 可以被在本软件中
> 右键复制，粘贴到 skill 的其他目录，用户也可以右键暂时禁用和恢复使用某个 skill，
> skill 面板开放一个可以被 skill 接管的口子，这个口子可以让 agent 来自动整理 skill 分类，
> 然后这个分类会在前端 GUI 中显示，并且分类可折叠，这个口子要严格规范输入输出 schema，
> 并且与其配套的 skill 要和这个模块一起维护

## 用户已拍板的两条

1. **「临时禁用」写一份禁用清单，不动硬盘上的 skill 文件。**
   在 app 自己的配置里记「这几个禁用了」，面板上置灰。
   代价（已知并接受）：CLI 自己仍会加载它，禁用只在本软件的视图里生效。
2. **给 agent 的分类口子做成 MCP 工具**（与现有 28 个 `canvas_*` / `wiki_*` 工具同一体系），
   输入输出 schema 写在工具定义里，天然受约束。

## 一、现状（已实测）

用户这台机器上的实际分布：

| 位置 | 数量 | 说明 |
|---|---|---|
| `~/.claude/skills` | 18 | Claude Code 的全局 skill |
| `~/.claude/design-skills` | 11 | 用户自己搬出默认扫描路径的（渐进式披露，由 `design-router` 分发）|
| `~/.claude/motion-skills` | 20 | 同上，由 `motion-router` 分发 |
| `~/.codex/skills` | 0 | 存在但空 |
| `<项目>/.claude/skills` | 1 | 项目 skill（本仓库只有 `agent-onboarding`）|

**「用户自己把 skill 搬出默认路径做渐进式披露」这件事必须被这个面板照顾到** ——
它不是异常状态，是用户刻意的组织方式。面板要能显示这些非默认目录，
而不是只认 `~/.claude/skills`。这正是「CLI 按钮可以选择 skill 目录」那条需求的由来。

主进程已有 `src/main/agentRules.ts` 在读写 `~/.claude/skills/`，可复用其路径与写文件的既有做法。

**与既有 skill 的重叠**：项目里已有 `.claude/skills/agent-onboarding`，
它盘的正是「给 Eas-Term 接入一个新 AI CLI 要改哪五个注入面」。
本面板的「多 CLI」部分与它高度相关，**设计与实现时必须一起看**，
否则会长出第二套并行的、迟早对不上的逻辑。

## 二、面板的两种上下文

| 场景 | 显示什么 | 位置 |
|---|---|---|
| 选中了某个项目 Frame | 该项目的**项目 skill**（`<项目>/.claude/skills` 等） | 知识库抽屉 |
| 没选中 Frame | **全局 skill**（按 CLI 分） | 知识库抽屉 |

**切换方式**：点知识库抽屉左上角的名称 → 下拉菜单切换（知识库 / skill / 各 CLI）。

**CLI 按钮**：面板内一个按钮，用来选当前查看哪个 CLI 的 skill 目录。
目录集合不是写死的 —— 要能加自定义目录（对应用户把 skill 搬去 `design-skills` / `motion-skills` 那种）。

---

## 三、面板内的操作

- **点 skill 名称 → 展开它的详细文件树**
- **文件树可拖到画布上编辑** —— 复用既有的「拖文件进画布生成节点」那条路
  （知识库抽屉已经在做同样的事，见 `CanvasWikiDrawer.tsx` 的自由只读节点）
- **右键复制 skill → 粘贴到别的 skill 目录**（这是真的复制文件）
- **右键临时禁用 / 恢复** → 只改禁用清单，不动文件（见 §「已拍板」第 1 条）

---

## 四、给 agent 的分类口子

一个 MCP 工具，让 agent 读取当前 skill 列表并写回分类结果；分类在面板里显示、**可折叠**。

**输入输出必须严格 schema 化。** 至少要约束：
- 分类名是字符串、非空、有长度上限
- 每个 skill 只能属于一个分类（或明确允许多归属并说明 UI 怎么显示）
- 引用的 skill 必须真实存在 —— **agent 报了一个不存在的 skill 名，要拒绝整批而不是静默丢弃**
- 分类结果存哪：存在 app 的配置里（跟禁用清单同一处），**不写进用户的 skill 目录** ——
  与「禁用不动文件」同一个理由

**配套 skill 与本模块一起维护。** 也就是说：这个 MCP 工具的描述、它期望的输入输出、
以及教 agent 怎么用它的那份 skill，三者要在同一次改动里保持一致。
在模块目录里放一份说明，指明「改这个工具就要同步改那份 skill」。
