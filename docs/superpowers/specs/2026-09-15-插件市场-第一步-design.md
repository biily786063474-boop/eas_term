# 插件市场 · 第一步：官方目录 + 一键安装 · 设计

> 讨论背景：竞品(OpenAI Apps SDK / Anthropic marketplace / Cursor)的插件市场都收敛到
> 「MCP server 目录 + 一键安装 + 审核」。Eas-Term 的自家插件系统已经具备协议层(MCP)、
> UI 层(`eas-plugin://` sandbox iframe + `panels`)、权限层(`permissions` + `CANVAS_CALL_ALLOWLIST`)——
> 缺的只有**分发层**。本文只定第一步:**做官方目录 + 一键装到 `~/.eas/plugins/`**,不碰第三方提交/审核(第二步)。

## 目标 / 非目标

**目标**
- 一个可订阅的**官方远程目录**(`registry.json`),托管在 `eas.biily.top`。
- 插件面板里能**浏览目录、一键安装/更新/卸载**自家(`cli: 'eas'`)插件,落到 `~/.eas/plugins/<name>/`。
- 安装前**展示插件要的权限**,用户确认后才装(延续「不静默装」红线)。
- 复用现有 `plugin.json` schema 与 `parseManifest`,不新造清单格式。

**非目标(留给第二步)**
- 第三方开发者提交 / 审核 / 签名信任链。
- MCPB(`.mcpb`)跨生态打包 —— 第一步只做自家 `.zip`,想跨 Claude/Cursor 生态时再上 MCPB。
- 给 Claude/Codex 生态插件做一键装(那两条仍是「预填命令让用户按回车」,`plugins.ts` 的既有红线不动)。

## 架构与安装流程

```
官方目录(服务器)                         客户端(主进程)                   用户
eas.biily.top/plugins/registry.json  ──拉取──▶ plugins:registry(缓存+离线兜底)
eas.biily.top/plugins/<name>/<name>-<ver>.zip                         浏览目录/点「安装」
                                     ◀──下载── plugins:install
                                              1. https 下载 zip → .part
                                              2. 校验 sha256(registry 声明)
                                              3. 防 zip-slip 解压到临时目录
                                              4. parseManifest 校验(必过)
                                              5. 展示 permissions ──确认──▶ 用户确认
                                              6. 原子移入 ~/.eas/plugins/<name>/
                                              7. plugins:list 刷新
```

## Registry schema(`registry.json`)

```jsonc
{
  "schema": 1,
  "updated": "2026-09-15T00:00:00Z",
  "plugins": [
    {
      "name": "board",                    // 须匹配 plugin.json.name，落盘目录名
      "displayName": "看板",
      "description": "项目待办三栏看板…",
      "category": "Productivity",
      "brandColor": "#5E6AD2",
      "version": "1.0.0",                  // 语义版本，比对提示更新
      "url": "https://eas.biily.top/plugins/board/board-1.0.0.zip",
      "sha256": "…64hex…",                 // 强制校验，registry 与包不一致即拒
      "size": 6421,                        // 下载前告知体积；下载超限即中止
      "permissions": { "canvas": ["canvas_open_file"] }  // 安装前展示，与包内 plugin.json 一致
    }
  ]
}
```

- **来源信任 = HTTPS + 官方域名**。第一步官方目录自己维护,不做签名;第三方/签名留第二步。
- `permissions` 在 registry 里冗余一份,是为了**下载前就能展示**;装完以包内 `plugin.json` 的 `permissions` 为准(两者不一致 → 拒,防目录谎报权限)。

## 包格式(`.zip`)

- 内容 = 一个插件目录的完整内容:`plugin.json` + `server.mjs` + `ui/…`(即 `resources/plugins/<name>/` 原样打包)。
- 解压后根部必须直接是 `plugin.json`(不允许多套一层目录)。
- 打包脚本:`scripts/pack-plugin.mjs <plugin-dir>` → 产出 `<name>-<version>.zip` + 打印 sha256/size(填 registry 用)。

## 安全模型(六条,每条对应一个纯函数/守卫)

1. **写入边界**:新 `guardPluginDir(name)` —— 只允许 `~/.eas/plugins/<name>/`,`name` 过 `NAME_RE`(同 `pluginManifest`)。不复用 `fsGuard`(那个边界是项目根+知识库根)。纯函数,可测。
2. **zip-slip 防护**:解压前每个条目的目标路径 `path.resolve(dest, entry)` 必须仍在 `dest` 内,否则整包拒。纯函数 `safeExtractPaths(entries, dest)`,可测。
3. **sha256 强制**:下载完算 sha256,与 registry 声明比对,不符即拒 + 清理。
4. **清单必过**:解压后 `parseManifest` 必须 `ok`,否则拒 + 清理(装进去一个跑不了/越权的插件比不装更糟)。
5. **权限确认**:安装前弹确认框展示 `permissions`(哪些 canvas 工具),用户点确认才装。**延续「不静默装」红线**(同 `agentInstall`/`plugins.ts`)。
6. **卸载边界**:只删 `~/.eas/plugins/<name>/`;`builtin`(`resources/plugins/`)与 Claude/Codex 插件不可从这里卸载(`plugins.ts` 只读纪律不破)。

## 分两步的边界(别越界)

- **第一步(本文)**:官方目录、自家 `.zip`、HTTPS+域名信任、一键装到 `~/.eas/plugins`。纯工程,风险可控,几天可落地,对你和用户立刻有用(装官方插件更顺 + 建好分发管线)。
- **第二步(想清楚再做)**:第三方提交 + 审核 + 签名 + MCPB 跨生态。这才进入**生态运营**,取决于有没有第三方开发者需求信号——是长期投入,不是代码问题。

## 已定决策(2026-09-15)

1. **托管**:第一步先用 `eas.biily.top/plugins/` 静态目录(复用 `publish-site.sh` 模式)。用户的对象存储是**阿里云 OSS**,就绪后把发布脚本的上传目标 + registry 里的 `url` 切到 OSS/CDN 域名——**对客户端透明**(客户端只认公开 HTTPS URL)。OSS 发布凭证(AccessKey)不在密钥金库,切换时再向用户取位置(不贴 key)。
2. **信任**:第一步不做签名,只 HTTPS + sha256 + 官方域名信任(第一步只上自己的插件,来源可信)。第三方 + 签名留第二步。

## 收录范围(回答「会不会有竞品同款插件」)

MCP 标准化的最大红利:**竞品市场里的插件绝大多数是标准 MCP server,你的市场可以直接收录,不用重开发。**分两层:

- **纯工具插件(无 UI)**:任何标准 MCP server(官方 `filesystem` / `fetch` / `github` / `slack` / `notion` 等)都能进你的 registry、一键装,行为与竞品市场同款。`plugins.ts` 现在已经能显示用户在 Claude/Codex 里装的 MCP 插件——Eas-Term 本就是「多生态聚合器」。
- **带 UI 的插件(panels)**:各家 UI 协议不同(ChatGPT Apps 的 `_meta.ui.resourceUri` + MCP Apps bridge ≠ Eas-Term 的 `panels` + `eas-plugin://`)。底层工具通用,但富交互 UI 要适配成 `panels`。第一步先只收工具型 + 自家带 UI 的。

**第一步 registry 首批** = 自家插件(board / computer / eas-capabilities)+ 精选收录几个成熟开源 MCP server(工具型)。「市场有多丰富」取决于你收录多少 + 生态,不是技术卡点。
