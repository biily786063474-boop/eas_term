# 插件市场统一连接与独立更新：设计稿

日期：2026-09-18。状态：用户已批准；实现与分层验收进行中，未发布。
用户已确认：按原 Demo 的 32 项清单接入，市场独立更新，统一补齐宿主能力。

## 1. 范围与交付边界

这是架构改造，不是往 registry 填 32 张卡片。分为两个可独立验收阶段：

1. 统一基础能力：远程 MCP、凭证与配置、兼容性门禁、真实状态、独立发布。
2. Demo 清单逐项接入：上游与许可证核验、连接器打包、账号授权、实际工具调用。

32 项原始清单与描述保存在 `docs/verification/plugin-marketplace/demo-integration-audit-2026-09-18.md`。
不替换条目凑数，不承诺上游尚未开放的能力。第一阶段通过不等于 32 项完成。
第三方开发者自助投稿、付费市场、评分排名、自建 OAuth 代理服务不在本轮范围。
正式安装器打包、上线发布是后续明确操作；本轮不替换用户正在运行的 app。

## 2. 路线对比与选定方案

|路线|完整性与体验|维护和调用成本|安全与风险|
|---|---|---|---|
|每个插件自行带 stdio 远程代理|可较快接少量工具，但授权、错误与状态分裂|重复依赖和进程，容易多份 token 缓存|难统一撤权、锁定与回调管理|
|宿主原生远程 MCP + 统一配置授权（选定）|软件内统一安装、连接、配置、诊断|一次基础投入；按需连接，不把所有插件工具常驻塞入上下文|集中审查出站、存储、授权和生命周期|
|交给各 CLI 单独安装|复用 CLI 生态，但三条链路体验不一致|三套配置和故障支持|违背现有 CLI 配置只读边界，不作为默认路径|

保留原 stdio 路径，不重写其已验证实现；新增远程客户端适配共同宿主接口。
远程协议使用官方 TypeScript SDK，实施时锁定核验后的具体版本与 lockfile；禁止运行时 npx latest。

## 3. 数据与兼容性

### 3.1 目录隔离

- 现有 `/plugins/registry.json` schema 1 保留给旧客户端，只投放它支持的旧包。
- 新客户端使用独立 `/plugins/v2/registry.json` schema 2；新协议插件不进入旧目录。
- v2 条目具备稳定 id/name、分类、介绍、来源与许可、版本、支持系统/架构、最低宿主版本、所需能力集合。
- 可安装条目必须有官方域名 HTTPS 包地址、sha256、size；上游待审核条目必须标不可安装及明确原因，不提供假下载。
- 主进程和安装 commit 两次校验能力/平台/版本；清单与目录的权限、连接目标、身份、版本必须一致。
- 兼容性不只看版本号：宿主发布固定 capabilities，插件声明所需集合；未知必需能力拒绝安装。
- 服务器目录更新不能改变已安装插件权限或连接目标；新版本在用户确认升级后才生效。

### 3.2 插件清单

保持 legacy `mcp.command/args/env` 可读。新清单引入带判别字段的连接配置：
- stdio：固定命令、参数、审查过的依赖及本地配置引用。
- remote：HTTPS 端点、认证模式（none / bearer / oauth）、出站与 OAuth 发行者策略。
- 配置字段：字符串、枚举、受控目录选择、secret 引用；字段有稳定 id、用途、必填与校验规则。
- 凭证只存引用；清单/目录/日志不得包含真实 token、cookie、密码。
- 配置不允许任意 JS、shell 拼接或 renderer 指定文件写入路径。
- 本地数据库/文件权限以具体目录或连接配置确认，不能以“插件已安装”替代数据授权。

## 4. 运行时与三 CLI

`Claude / Codex / OMP → 现有插件 shim → pluginHost → stdio 或 remote 客户端`。
三种 CLI 复用同一连接与授权，不写入它们的用户配置，不让 CLI 各起远程代理。

共同客户端接口保留 initialize、listTools、request、requestTracked、notifications、alive、close 等语义。
远程客户端的关闭代表本地连接及请求已收尾，不伪装成子进程 exit；运行时资源登记需要区分进程和连接。
停止窗口/会话时保留 ref 归属、排队代次与工具活动统计；取消请求不等于服务端副作用已撤销。

- 工具按现有启用/会话选择规则暴露；安装 32 项不等于启动 32 项、注入 32 项全部工具。
- 首次连接和用户点击测试时才握手，不在浏览市场时唤起登录或远程工具。
- 请求设超时与体积上限；工具错误、网络失败、需要授权、配置缺失分别反馈。
- 工具调用 POST 不因网络错误自动重放，避免重复发帖、写文件等副作用。
- Streamable HTTP 为首选；legacy SSE 只在经过明确声明和测试的连接器中启用，不在认证失败时乱降级。

## 5. 凭证与 OAuth

凭证统一由主进程管理，复用现有系统加密及锁定纪律，但不借用 PTY token 冒充插件授权。
新增插件专属授权范围，以插件 id、端点/issuer 和账号绑定；只返回连接状态与掩码给 UI。
不从用户全局 env、其他 CLI 缓存、已安装 Codex 插件中复制凭证。

- 密钥存储不可用或密钥柜锁定时失败关闭，不回落明文文件。
- 用户点击连接后，软件打开系统浏览器登录；回调只绑定 loopback 随机端口，校验 state、PKCE S256、超时、单次消费、请求来源会话。
- resource/issuer/redirect URI 按协议绑定；发现文档和跳转地址都执行出站验证，防 token 发错对象。
- token 在进程内使用，refresh 同账号单飞；撤权/关闭/卸载增加代次，使晚到刷新或回调不能复活旧连接。
- 锁定后停止需要凭证的新请求，取消本地连接并清除内存凭证；不声称已撤销服务端已执行操作。
- “断开并清除本地授权”立即生效；上游支持撤销时尝试远端 revoke，不支持时给账户端撤权指引。
- 账号由用户自己登录；插件需要应用注册/回调审核时明确标为待平台配置，不伪装其他获批客户端身份。
- API key 配置在软件密钥输入/选择控件中完成，不让用户在聊天发密钥。

## 6. 出站与安全边界

官方包下载域名白名单、哈希、解包路径/软链防护、两阶段确认门禁保持。
插件连接端点与包下载端点是不同权限域，不能把所有远程服务加进下载白名单。

远程连接遵循系统代理；HTTPS 为默认，验证 TLS；拒绝 URL userinfo、敏感 query、跨域转发 Authorization。
远程端点、OAuth metadata、授权/令牌地址和所有重定向逐跳校验；默认拒绝 loopback、私网、链路本地与 metadata 地址，并处理 DNS 重绑定。
合法本地 Figma/数据库端点必须是独立的显式本地连接类型，用户确认精确范围，不给全部远程插件放开私网。
OAuth loopback 回调仅作为本地监听例外，不是远程请求通用豁免。

注意：stdio 插件是经用户确认的本机可执行代码，现有 permissions.canvas 不是操作系统沙箱。界面不得宣称完整沙箱隔离。
新增真实联网机制前同步 `docs/architecture/01-系统上下文.md` 和 `site/privacy.html`。
保持 guardedHandle、guardPath/guardDir 或现有同等窄的插件安装守卫；不扩大用户路径白名单。

## 7. 市场与配置体验

沿用现有设计系统与原 Demo 分类，不另做视觉改版。
分别显示三组状态，避免把“安装”混同“可调用”：
- 分发：未安装 / 已安装 / 可更新 / 宿主不兼容 / 平台待审核。
- 配置：无需配置 / 缺少配置 / 待登录 / 已授权 / 授权失效 / 已锁定。
- 运行：未连接 / 连接中 / 可用 / 失败（明确原因）。

按钮按状态给出安装、更新、配置、连接、测试、断开；查看条目不自动测试或登录。
2026-09-18 用户截图反馈后确认：列表保持紧凑卡片，配置与OAuth账号操作移至独立详情对话面板；设置不拉高同排卡片，危险操作分区，明暗主题和Esc/焦点恢复都需实际验收。
更新前展示版本、权限与目标域变更；活跃请求不在执行中替换连接器，待释放或明确停止后升级。
刷新市场只取目录元数据。失败时显示缓存与过期提示，不覆盖最后一份有效目录。
不可用条目可查原因，但不显示可安装按钮；数量区分目录条目与可用插件。

## 8. 独立发布链

1. 每个插件独立版本，锁定依赖，构建归档并计算大小/哈希。
2. 验证清单、兼容性、权限、来源/许可、安装与至少一次真实工具调用。
3. 上传不可变版本包并逐一核验，再原子切换目录；旧包保留以便回退。
4. v1/v2 目录分别生成；先确认旧客户端只见兼容包，再验证新版刷新可见。
5. 用户确认后安装/升级；失败不破坏旧安装。目录更新不强制替换本机插件。

本轮不增加第三方投稿/自动审核服务。平台审核、开发者注册、付费与账号授权不会因完成代码而自动通过。

## 9. 模块边界

- `src/shared/`：清单连接、配置、兼容性、状态和 IPC 契约，不引入 IO。
- `pluginRegistry` / `pluginManifest`：版本化纯校验与兼容判断；共享类型与 preload 同步。
- `src/main/pluginConnections/`：远程传输、网络策略、授权编排、配置与专属凭证；纯策略与 IO 分离。
- `pluginHost`：复用计数、准入、生命周期、shim 与 panel 接线；不吸纳所有 OAuth 实现。
- `PluginMarketModal` 与独立配置组件：状态和用户动作；不接触持久凭证或执行命令。
- `scripts/`：双目录打包、验证、发布；具体连接器放 `plugins-store/`，不写死进 UI。
- 更新架构 01/03/10/13 与相关隐私文档，随实现同 commit 提交。

## 10. 验收与推进顺序

A. 契约与门禁：兼容旧包；未知能力、新 schema、错误平台不能装；旧客户端目录不污染。
B. 远程传输：隔离测试服务验证握手、工具列表/调用、通知、取消、超时、关闭、无重复写请求。
C. 配置与授权：假授权服务器验证 PKCE/state/issuer/resource、重放/过期、并发刷新、锁定、断开、晚到回调、脱敏；不拿真实用户凭证做破坏性实验。
D. UI：构建后开隔离应用，亲眼验证安装→配置→连接→测试→断开，以及离线缓存与错误状态；只改代码不算完成。
E. 三 CLI：分别经真实 shim 路径验证相同测试插件的 tools/list 与 tools/call；实际模型端到端另列证据。
F. 32 项：逐项核验官方来源、许可、实际能力、可用平台、认证前提；有条件的用测试账号调用只读工具，写工具仅对可丢弃测试资源验证。
G. 独立更新演练：不重新构建软件，发布测试目录新版本并刷新、安装、升级、失败回退；生产发布另行执行。

交付记录分为“代码与模拟协议通过”“隔离应用通过”“真实账号通过”“受外部条件阻塞”。任何一层未完成不得合并说成全部可用。
电脑视野继续受 `docs/verification/releases/computer-use-lifecycle.md` 约束，不能借本轮接入宣称外部指针问题已修复。
