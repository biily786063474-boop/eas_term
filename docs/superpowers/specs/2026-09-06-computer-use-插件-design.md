# computer use 插件 —— 自己做的 MCP server，三家底座通用

> 状态：设计稿，未动代码。
> 前置：插件面板宿主一期（`docs/superpowers/specs/2026-09-05-插件面板宿主-design.md`，0.4.79 起可用）。
> 图纸：落地时同 commit 更新 `10-模块领地图` / `11-MCP工具网络` / `13-所有权矩阵`。

## 用户原话

> 我想做 computer use。
> 那自己做一个 MCP server，但是要注意可能导致什么坑点，设计的时候注意这些，给我一个 spec。

## 一、先说清楚为什么只能自己做

2026-09-06 在本机把三处都翻了，Codex 官方这条路是断的：

| 查的地方 | 结果 |
|---|---|
| codex-cli 0.147.0 二进制 | 内置工具只有 `shell` / `local_shell`；feature 全表（`web_search` `imagegen` `view_image` `collab` `memory_tool` `undo` `js_repl` `code_mode` …）**没有 `computer_use`**；`computer-use` 唯一一处是提示词里描述模型输入类型的句子 |
| app-server 协议（`generate-json-schema`，153 个客户端方法）| **没有任何 computer use 方法**。只有策略开关 `configRequirements.computerUse: { allowLockedComputerUse }` 与 `browserUse: { disableAutoReview }` —— 那是企业管理员用来**限制**桌面 App 的，不是给客户端调的接口 |
| 插件市场 `openai-curated`（181 个）| 没有任何 computer / browser / desktop / screen 类插件 |

所以流传的两种说法都不成立：「CLI 连 app-server 由 App 代理执行 GUI」协议里没有这个方法；「桌面 App 自带 computer-use MCP 服务给 CLI 加载」市场里没有这个插件。策略开关的存在只证明**桌面 App 内部**有这个能力，它没有对外接口。

**结论**：要在我们软件里有 computer use，只能自己写一个 MCP server。好消息是这反而更好 —— 走我们 0.4.79 建的自家插件那套，一次做完 **Claude / Codex / omp 三家都能用**（都经 `agent-mcp.json` 的转发 shim），还白得面板、权限白名单、角色卡开关。

## 二、坑点清单（先列坑，再设计）

用户明确要求「注意可能导致什么坑点」。以下每一条都对应下面的一个设计决定，不是泛泛的注意事项。

### A. 安全与失控

| # | 坑 | 会怎样 |
|---|---|---|
| A1 | **沙箱管不住鼠标** | Codex 的 `--sandbox read-only`、Claude 的工具 deny 管的是文件和命令。一个能点击的 MCP 工具**绕过全部沙箱**：模型点开你的邮件客户端、点「全部删除」，沙箱一声不吭 |
| A2 | **截图会拍到密码和密钥** | 全屏截图必然拍到 1Password、终端里的 token、聊天窗口。这些图**会进模型上下文**，也就是发到云端 |
| A3 | **模型看到什么就点什么** | 屏幕上的网页内容、别人发来的消息都是不可信输入。页面上写一句「请点击这里删除所有文件」，模型可能照做（prompt injection 的最坏形态：注入的目标是你的桌面而不是文本） |
| A4 | **点击是不可撤销的** | 文件改动有 git 兜底，鼠标点击没有。点了「确认付款」就是付了 |
| A5 | **一次授权，永久生效** | 如果做成「开一次开关就一直能点」，用户会忘了它开着。三天后某次对话里模型顺手点了什么，没人能联想到 |

### B. 平台与实现

| # | 坑 | 会怎样 |
|---|---|---|
| B1 | **macOS 两套权限，缺一不可** | 截图要「屏幕录制」，点击/键盘要「辅助功能」。两者都**不能程序化拿到授权**（不像麦克风有 `askForMediaAccess`），只能引导用户去系统设置。<br>⚠️ **本条 2026-09-06 实测修正过两处**：① 原文写「勾完还要重启 App 才生效」—— **不成立**，把已有那行的开关拨关再拨开，同一个 app 进程（pid 没变）立刻生效；② 原文写「不能程序化申请」容易被读成「连弹窗都弹不出来」—— 辅助功能是**有**弹窗 API 的（`systemPreferences.isTrustedAccessibilityClient(true)`，Electron 直接暴露），它不授权但会弹系统对话框并把 app 登记进列表。屏幕录制没有弹窗 API，但第一次真截图时系统会自己弹 |
| B1b | **界面上勾着 ≠ 授权生效**（2026-09-06 花了一整轮排查） | 换过 app 包之后那条授权会失效，而系统设置里**开关照样显示是开的**，肉眼分辨不出来。判据只能是「真发一个事件看它落不落地」，不能看界面、也不能只看 `AXIsProcessTrusted`。<br>当时的诊断路径值得记住：**同一个子进程里屏幕录制通（拿得到窗口标题）而辅助功能不通** —— 这就排除了「权限传不到子进程」，坐实了是那一条失效。修法是拨开关，不是重装、不是重启 |
| B1c | **别拿「从终端跑一下」判断 app 的权限** | 权限按**责任进程**判，从哪个 app 起的 shell 就测的是哪个 app。2026-09-06 我在 Eas-Term 内嵌的终端里跑 `axcheck`，量到的正是 Eas-Term；换到系统终端里跑，量的是终端。判据是进程链（`ps -o ppid` 一路走到 app），不是「我在终端里」|
| B2 | **权限属于发起进程，不是脚本** | 插件 server 是我们 spawn 的子进程，TCC 认的是 **Eas-Term.app** 这个 bundle。所以权限提示上写的是我们的名字，用户会以为是我们在偷看屏幕 —— 文案必须解释清楚 |
| B3 | **公证要加 entitlements 与用途描述** | 现在的 `entitlements.mac.plist` 只有音频/摄像头。要加屏幕录制相关项与 `NSAppleEventsUsageDescription` 之类；漏了在别人机器上是静默失败，本机开发看不出来 |
| B4 | **坐标系四重不一致** | 逻辑点 vs 物理像素（Retina 2x）、多显示器负坐标、菜单栏偏移、窗口坐标 vs 全局坐标。任何一处搞错，点击会落在**别的地方**（最坏是落在另一个窗口的危险按钮上）|
| B4b | **`NSScreen.frame` 和 CGEvent 不是同一个坐标系**（2026-09-06 修） | AppKit 原点在主屏**左下角、y 向上**，CGEvent / CGWindowList 原点在主屏**左上角、y 向下**。单显示器时两者恰好都从 (0,0) 起，**看不出问题**；一接第二块屏，副屏 y 就算反（AppKit 说 +745，CG 说 −745），于是「这个点在不在屏幕里」同时出现误拒和误放行。<br>助手的 `displayBounds()` 已改用 `CGDisplayBounds`（本来就是 CG 坐标系，不需要换算），缩放因子按 displayID 回 `NSScreen` 取。**这条只有接第二块屏才验得出来，本机单屏，尚未实证** |
| B4c | **「动作后读回鼠标位置」挡不住屏幕外的坐标**（2026-09-06 实测推翻原设计） | `CGEvent(source:nil).location` 读的是**事件流里的坐标**，不是被系统夹回的真实光标。在一块 1147×745 的屏上发 `move(1300,900)`，回读理直气壮地说光标就在 (1300,900)，`verifyAt` 照过 —— 于是「看起来点成功了、其实什么都没点」。<br>**修法**：动作前加一道 `insideAnyDisplay` 落点闸（越界一律拒，不钳制 —— 钳到边缘会把「模型算错」变成「点到屏幕角落的某个东西」）。`verifyAt` 保留，但它真正挡得住的只有一种情况：**用户的手碰了鼠标/触控板把光标带走**（实测很容易发生）|
| B4e | **系统级热键要真的按下修饰键**（2026-09-06） | `key` 通道原来只在按键事件上挂 `CGEventFlags`。应用级快捷键（⌘C）这样就够；**系统级热键读的是真实修饰键状态**，所以现在改成「按下修饰 → 主键 → 松开修饰」，已证实 ⌘Space 能弹出聚焦搜索。<br>⚠️ 按下与松开之间**不许有任何提前退出** —— 修饰键卡在按下状态会让整台机器没法用。<br>⚠️ **未证实**改之前那种写法是否真的驱动不了系统热键（A/B 回测被打断两次，决定不追）。别把这条读成「修好了一个 bug」|
| B4f | **别用窗口列表判断热键生效了没有** | `listWindows` 只留 `layer == 0` 的普通窗口，聚焦搜索、⌘Tab 切换器这些**浮层面板天生被滤掉** —— 于是会得到「热键无效」的假结论。2026-09-06 我照这个假结论改了一轮代码。可靠判据：截图看，或挑一个会留下副作用的热键（⌘⇧3 存文件那种，但**用它之前要先确认存到哪、热键开没开**，否则又是一个未验证的判据）|
| B4d | **失败原因要说对，不然会把人引到完全无关的地方** | 上面那种「被真实鼠标打断」，原来报的是「事件被系统丢弃了（权限或屏幕状态问题）」—— 而权限明明是好的。2026-09-06 验收时我照这句话去查权限，绕了一整轮。现在权限和落点都已在前面查过，走到 `verifyAt` 失败就只剩这一种可能，报错直接这么说 |
| B5 | **截图很大很慢** | 一张 Retina 全屏 PNG 约 5–15MB，base64 后更大。直接塞进 MCP 响应会把上下文撑爆、把一轮对话变得极慢极贵 |
| B6 | **`screencapture` 会发出快门声、可能闪一下** | 用户会以为软件在乱截屏 |
| B7 | **多显示器 / 锁屏 / 睡眠** | 锁屏时截图是黑的、点击无效但**不报错**，模型会以为点成功了继续往下做 |

### C. 与我们自己系统的冲突

| # | 坑 | 会怎样 |
|---|---|---|
| C1 | **模型可能点到 Eas-Term 自己** | 它能点自己的窗口 → 点到「删除项目」「清空画布」，甚至点开另一个对话去发指令。自噬 |
| C2 | **红线：生图路径** | 会点会打字就能操作画板/浏览器去生图，绕开「只走 bizone-canvas / lovart」那条红线。必须显式挡 |
| C3 | **面板 iframe 的 CSP 不许外连** | 插件面板要显示实时截图，而面板 CSP 是 `img-src data: blob:`。截图只能以 data URI 或经宿主转成 blob 给面板，不能让面板去 fetch |
| C4 | **`plugin-panel` 的 `eas/canvas.call` 双白名单** | 现有白名单只有 4 个画布工具。computer use 的动作**不能**混进这条通道（那是给面板调画布的），要走它自己的 MCP 工具 |
| C5 | **team 多 agent 并发** | 几个 agent 同时点鼠标 = 互相打架。必须全局串行化 |

## 三、已拍板的设计

| # | 决定 | 对应坑 |
|---|---|---|
| 1 | **做成自家插件 `~/.eas/plugins/computer/`（随包分发一份样板）**，不是内置工具 | 三家通用；能被角色卡整个关掉；有面板 |
| 2 | **两档能力，分成两个 MCP server 名**：`computer-view`（只截图/只读）与 `computer-act`（点击/键盘）。**默认只装 view，act 要显式开** | A1 A5 |
| 3 | **`computer-act` 必须有一个「授权窗口」**：用户在面板上点「允许操作 10 分钟」才生效，到点自动失效，面板上有倒计时和「立即收回」。**没有永久授权这个选项** | A5 A4 |
| 4 | **每个动作都写进操作日志**（时间、动作、坐标、目标窗口标题、发起的会话 id），面板上实时滚动，落盘 `userData/computer-use.log` | A3 A4 |
| 5 | **截图默认打码**：可配一份「敏感窗口标题/进程名」清单（1Password、Keychain、终端…），命中的窗口在截图里整块涂黑。**默认清单非空** | A2 |
| 6 | **截图默认按窗口而不是全屏**，且默认缩到长边 ≤1280、JPEG q80，**不返回 base64 到工具结果里**：写进 `userData/computer-shots/<id>.jpg`，工具只回文件路径与摘要，面板显示图 | A2 B5 |
| 7 | **绝不点 Eas-Term 自己**：动作前取目标窗口所属 bundle id，等于我们自己就拒绝并说明 | C1 |
| 8 | **坐标只接受「屏幕逻辑坐标」并显式带 `displayId`**，server 内部统一换算；越界、无显示器、锁屏一律**报错而不是静默不动** | B4 B7 |
| 9 | **全局互斥**：一个动作没做完不接第二个，跨会话共享同一把锁（宿主里那个插件进程本来就只有一个，天然是单点） | C5 |
| 10 | **红线守卫**：`computer-act` 的目标窗口若属于画板/浏览器且当前对话在做生图类任务 —— 不做花哨判定，直接在 skill 文档与工具描述里写死「不许用它绕开生图路径」，并把画板 bundle id 加进拒绝名单 | C2 |
| 11 | **权限缺失要给一句人话 + 一个按钮**：面板检测到没授权时显示「需要在系统设置里给 Eas-Term 勾上『屏幕录制』和『辅助功能』，勾完要重启软件」，按钮直接打开对应的系统设置面板 | B1 B2 |
| 12 | **一期只做 macOS**；Windows/Linux 的工具直接返回「这个平台还不支持」 | 别做半个 |

## 四、工具面（一期）

`computer-view`（只读，默认可用）：

| 工具 | 参数 | 返回 |
|---|---|---|
| `screen_list` | — | 显示器列表（id、逻辑尺寸、是否主屏）、当前前台窗口标题与 bundle id |
| `screen_shot` | `displayId?` `windowTitle?` `region?` | 截图**文件路径** + 尺寸 + 是否有窗口被打码。默认前台窗口 |
| `screen_text` | 同上 | 走系统 OCR（Vision）返回文字与位置，**给模型定位用，比让它读图省得多** |

`computer-act`（写，需授权窗口）：

| 工具 | 参数 | 备注 |
|---|---|---|
| `act_grant_status` | — | 还剩多少秒、谁授的。**未授权时其余工具一律拒绝并回这条的说明** |
| `act_click` | `x` `y` `displayId` `button?` `count?` | 动作前拍一张「动作前」截图存证 |
| `act_type` | `text` | **不接受粘贴板**（避免顺走剪贴板里的密码）；单次长度上限 |
| `act_key` | `keys[]`（如 `["cmd","s"]`）| 组合键白名单，禁 `cmd+q` / `cmd+w` 之类破坏性的 |
| `act_scroll` | `dx` `dy` `displayId` | |

**一期不做**：拖拽、右键菜单导航、录制回放、跨窗口自动化脚本。

## 五、实现骨架

```
~/.eas/plugins/computer/            （随包样板：resources/plugins/computer/）
  plugin.json      两个 panel：实时预览 + 操作日志；permissions.canvas 只要 canvas_open_file
  server.mjs       MCP server（stdio，零依赖）。**只做协议与校验**，动作交给下面两个
  native/shot.mjs  截图：优先 `screencapture -x`（-x 静音，治 B6），窗口模式用 -l <windowid>
  native/act.mjs   点击/键盘：一期用 AppleScript（osascript）走 System Events，
                   零依赖、随系统走；性能不够再换原生模块
  ui/preview.html  面板：最近一张截图 + 授权倒计时 + 「立即收回」
  ui/log.html      面板：操作日志实时滚动
```

纯函数抽出来测（照 `pluginManifest.ts` 的规矩）：

- `coords.ts` —— 逻辑坐标 ↔ 物理像素、多屏偏移、越界判定（**B4 全靠它**，必须有测试）
- `redact.ts` —— 敏感窗口匹配规则（默认清单 + 用户追加）
- `grant.ts` —— 授权窗口的状态机（授予 / 剩余 / 过期 / 收回），可注入时钟
- `guard.ts` —— 拒绝名单（自己的 bundle id、画板）、组合键白名单

## 六、验收（真机，隔离实例）

1. 未授权时 `act_click` 被拒，返回的话里说清楚怎么授权
2. 面板点「允许 10 分钟」→ 倒计时出现 → `act_click` 生效 → 到点后再调被拒
3. 「立即收回」当场失效
4. `screen_shot` 默认不返回 base64；文件落在 `userData/computer-shots/`，面板能显示
5. 打开 1Password（或任一在默认打码清单里的 App）后截图，那块是黑的
6. 让模型点 Eas-Term 自己的窗口 → 被拒绝并说明原因
7. 锁屏后调 `screen_shot` / `act_click` → **报错**，不是静默成功
8. 两个 agent 同时点 → 串行执行，日志里能看出顺序
9. 关掉「屏幕录制」权限后打开面板 → 出现引导与「打开系统设置」按钮
10. 角色卡里把 `computer-act` 加进 denyServers → 那个角色的会话里这几个工具不存在
11. 三家底座（Claude / Codex / omp）各跑一次 `screen_shot`

## 六 · view 档实施回填（2026-09-06）

已实施：四个纯函数（`coords` / `grant` / `redact` / `guard`，28 测试）＋ `windows.ts`（7 测试）＋
插件本体（`plugin.json` · `server.mjs` · `ui/view.html`）＋ Swift 窗口助手与构建脚本。

**动手前核对的结果**（§八）：

| # | 结论 |
|---|---|
| 1 | `screencapture` 有 `-l<windowid>` `-R` `-x`（静音）`-t jpg`。**`-R` 收逻辑点、输出物理像素**：本机 1147×745 点 ↔ 2294×1490 像素（scale 2），coords.ts 据此建模 |
| 2 | **窗口列表只能靠编译产物**：`CGWindowListCopyWindowInfo` 是 C API，JXA 的 ObjC 桥返回 function（调不到），系统 python3 无 Quartz 模块，`osascript` 取 `AXPosition` 需要辅助访问（错误 -1719）。改为 40 行 Swift 编成**通用二进制**（arm64+x86_64，149KB），随 `resources/plugins` 打包；`scripts/build-computer-helper.mjs` 挂在 `npm run build` 前面，没有 Xcode 命令行工具就跳过并走降级 |
| 3 | 屏幕录制权限：拿不到窗口列表时**不猜**，`screen_permission` 工具直接报「看不到任何窗口，多半是没给屏幕录制权限，勾完要重启软件」 |
| 5 | 缩图用系统自带 `sips`（`-Z 1280` + jpeg q80），零依赖。实测一张窗口图 64–120KB |

**一期把「打码」实现成「拒绝」**（比设计稿更严）：像素级涂黑要引入图像库，而
「宁可不给也不泄漏」不需要它 —— 屏幕上开着敏感窗口时整屏截图直接拒绝并列出是哪些，
指名截敏感窗口也拒绝。按窗口截时天生不会拍到别的窗口，本来就不需要涂黑。

**真机撞到并修掉的一处**：`frontWindow` 跳过了 Eas-Term 自己，但**显式传
`windowTitle:'Eas-Term'` 照样截到了**。我们自己的界面里有密钥柜、有别的对话，
截了还会形成「截自己再喂回自己」的回环 —— 现在 `isBlocked` 把自己也算进去，
`screen_list` 里也标成 sensitive。

真机验收（隔离实例，面板里真点）：面板挂载 → 点「拍一张」→ 截到前台窗口（自动跳过
Eas-Term）→ 64KB 落在宿主注入的 `userData/plugin-data/computer/shots/` → 页脚报
「没有敏感窗口」。`screen_permission` 报「一切正常，看得到 13 个窗口」。

**view 档到此可用。act 档（点击/键盘）仍未开始**，它要辅助访问权限，且必须先有授权窗口 UI。

## 六 · act 档实施回填（2026-09-06）

**动手前那条最要紧的实测**：没有辅助访问权限时，`CGEvent.post` **不报任何错，事件被静默丢弃**。
实测 `AXIsProcessTrusted()=false` 时 post 成功返回，鼠标从 (533,419) 原地没动。
所以助手里每个写动作做两件事：① 动作前查 `AXIsProcessTrusted` ② **动作后读回鼠标位置验证**。
只信「调用没抛错」等于让模型以为点成功了继续往下做 —— 那是最坏的失败方式。
移动没到位就**不点**（位置都没到，点下去等于随机点了别处）。

三道闸，缺一不可：

| 闸 | 在哪 | 验收结果 |
|---|---|---|
| 授权窗口 | `server.mjs` 的 `grant`，档位 5/10/30 分钟 | 未授权点击 → 拒绝并说清怎么授权；授权后剩 298 秒；面板「立即收回」→ `granted=false` |
| 拒绝名单 | 目标窗口（自己 / 画板 / 敏感）＋ 组合键黑名单 ＋ 坐标越界 ＋ 文本上限 | `cmd+q` → 拒绝；`(99999,5)` → 「不在任何显示器内，当前 #0 0,0 1147×745」；600 字 → 拒绝 |
| 系统权限 | Swift 助手 | 授权在但系统权限没给时点击 → **明确拒绝并给出设置路径**，不是静默丢弃 |

**授权故意不是 MCP 工具**：`panel/grant` / `panel/revoke` 是面板私有方法，只有面板（用户真手点）
经宿主发得到；会话里的转发 shim 不认 `panel/` 前缀。实测模型调 `panel/grant` 被挡在
`tools/call` 那层：「本插件没有工具 panel/grant」。**模型给自己授权在结构上不可能。**

原生助手扩成一个二进制多个子命令（231KB 通用）：`windows` / `displays` / `axcheck` /
`move` / `click` / `scroll` / `type` / `key`。文本输入走 unicode 串直接发，不经键位映射
（中文和符号都能打，不受输入法布局影响），且**不读也不写剪贴板**。

**还没验的**（要辅助访问权限，本机未授予）：真实点击落点是否准确、连击、滚动、
多显示器负坐标下的落点、锁屏时的行为。这些等授权后在真机上补。
