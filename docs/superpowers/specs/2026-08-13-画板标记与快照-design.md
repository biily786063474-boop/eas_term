# 画板标记置顶与面板快照

> 2026-08-13 · 设计定稿

## 要解决什么

三件事，量级差别很大：

1. **用户画的标记被终端压住**。矩形/箭头/便签画上去之后，只要底下是活终端就看不见了 ——
   而标记的用途正是「指着某个终端说这块」。
2. **没有快照能力**。想把当前画板的样子留档、或者让 agent 看一眼画板现在什么样，都没有通道。
   全仓搜索 `capturePage` / `desktopCapturer` 零命中，agent 侧 12 个画布工具里也没有快照类的。
3. **画板模块拖到终端不能插路径**。资源抽屉里拖**文件**到终端已经能插路径了，
   但拖**模块本身**（终端节点、预览节点、Frame）没有这条路。

第 1 件是第 2 件的前提：标记要能被拍进快照里，就必须先在最上层。

## 排查：为什么标记压不到最上层

`App.tsx` 里 `CanvasStage`（画标记的地方）在第 292 行，`PaneLayer`（活终端）在第 301 行 ——
**后者在 DOM 里靠后，天然盖在上面**。

而且标记所在的 `.canvas-world` 带 `transform`，**自成层叠上下文** ——
在它内部无论把 z-index 调多高，都逃不出这个上下文，压不到 `PaneLayer` 之上。

所以只加 z-index 是无效的，必须把标记提成**独立一层、渲染在 `PaneLayer` 之后**。

## 设计

### 一、标记层：提到 PaneLayer 之上

新增一个 `CanvasShapeLayer`，在 `App.tsx` 里排在 `<PaneLayer />` **之后**，
用与 `.canvas-world` **完全相同**的视口变换（同一个 `viewport.x/y/scale`），保证与画布内容严丝合缝对齐。

`CanvasStage` 里原来渲染 shapes 的那段整体搬过去；`CanvasStage` 只保留**绘制中的草稿**
（`draft`）——那是跟着鼠标走的临时形状，属于绘制交互、不属于成品标记。

**指针事件的纪律**（这一条错了会让整个画布点不动）：

- 层容器 `pointer-events: none` —— 它铺满整个视口，不放行的话画布和终端全都点不到
- 每个 shape 自身 `pointer-events: auto` —— 标记要能选中、拖动、改大小
- 便签的编辑态照旧（它本来就要接键盘）

### 二、快照

**截什么**：画布视口那一块的**当前所见**（含所有 Frame、活终端、标记）。
不是只截选中的工作区，也不做「把视口外的内容也包进来」。

**不截什么**：所有盖在画布上的浮层。实测有 11 个：

```
canvas-drawer(45)  wiki-drawer(45)  cd-edge(29)  wk-edge(29)
canvas-minimap(41)  canvas-minimap-mini(41)  crm-mini(42)
canvas-toolbar(40)  canvas-zoombar  ctoolbar-mini(20)  cd-attn-bubble(31)
```

它们是**盖在画布上**的，不是画布旁边的 —— 所以按区域裁剪没用，必须在拍照的那一瞬把它们藏掉。

做法：给根节点加一个 `.snapshotting` 类，一条 CSS 规则把这 11 个一起
`visibility: hidden`（不用 `display:none` —— 那会触发重排，抽屉的宽度变化会让画布跟着跳）。
等一帧绘制完成再拍，拍完摘掉类。**用 `visibility` 而不是 `opacity`**：
`opacity:0` 的元素仍然参与合成，某些情况下仍会在截图里留下痕迹。

**存哪儿**：`<选中工作区所属项目>/screenshot/<YYYY-MM-DD>/<YYYYMMDD-HHmmss>-<当日序号>.png`

- 按**天**分文件夹。按小时分会碎，按月分一个目录几百张。
- 文件名里同时有完整时间戳和当日序号：时间戳保证排序和唯一，序号让人能说「今天第 3 张」。
- 序号取当天目录里已有文件数 + 1，从 1 开始。

**什么时候能用**：必须先在画板上选中一个工作区（Frame）。
没选中时**按钮禁用**，hover 提示 **「请在画板中选择一个工作区」**。

理由：矩形/箭头/便签是画布全局的、不属于任何 Frame，一张快照也常横跨多个项目的 Frame ——
「这张图属于哪个项目」在数据上没有唯一答案，所以让用户自己指一个，而不是替他猜。

**标记怎么处理**：拍完弹窗确认，确认后清空所有矩形/箭头/便签。

弹窗文案要说清「图里已经有了」这件事，否则用户不知道清掉之后还剩什么：

```
已保存快照，标记已经拍进图里了。
要不要把画板上的 3 个标记清掉？

  ☐ 记住这次选择，以后不再问

        [保留]      [清掉]
```

**不做自动撤销**：清空是用户在弹窗里明确按下的，不是副作用。

**记住选择**：勾选后，以后快照不再弹这个窗，直接按记住的那次执行。
存 `snapshot-prefs.json`（userData）里的一个字段：

```ts
/** 快照后怎么处理标记。未设置 = 每次都问 */
clearShapesAfterSnapshot?: 'keep' | 'clear'
```

**怎么改回来**：设置面板加一项「快照后清空标记」，三态 ——
`每次询问（默认）` / `总是保留` / `总是清空`。选回「每次询问」就是把这个字段删掉。

设计上的两条纪律：

- **勾选框默认不勾**。「以后不再问」是用户主动放弃一道确认，不能替他勾上。
- **记住的是「保留」还是「清掉」，跟着他按的那个按钮走** —— 不是勾选框自己带一个默认动作。
  勾了之后按「保留」，记住的就是保留。

### 三、agent 侧的路由

新增两个 MCP 工具：

| 工具 | 干什么 |
|---|---|
| `canvas_snapshot` | 拍一张，返回文件路径。要求已选中工作区，没选中就返回那句提示 |
| `canvas_latest_snapshot` | 取最新一张的路径（可指定项目），没有就明说没有 |

并在 `canvas_get_state` 的描述里加一句路由指引：
**用户问「画板现在什么样」这类问题 → 先取最新快照看图，而不是只读结构**。

`canvas_get_state` 返回的是节点树（谁在哪、叫什么），回答不了「看起来怎么样」。

### 四、模块拖到终端 → 插项目路径

现有的 `startFileDrag`（资源抽屉拖文件到终端节点插路径）已经有整套拖放骨架。
本条是在同一套骨架上加一条分支：拖的是**画布模块**时，插它所属项目的**根路径**。

- 拖终端节点 / 预览节点 → 插该节点所在 Frame 绑定项目的路径
- 拖 Frame 本身 → 同上
- 落点不是终端 → 什么都不做（和现有行为一致）

插入的是路径文本，插到输入栏光标处，不自动回车。

## 明确不做

- **不把视口外的画布内容包进快照**。要做得临时改视口再截再恢复，中间会闪，
  而且内容多时单个模块会小到看不清。
- **不做快照的历史浏览界面**。文件在项目目录里，访达和文件树都能看。
- **不做自动快照 / 定时快照**。
- **不改 `canvas_get_state` 的返回结构**，只改它的描述。

## 风险与取舍

| 风险 | 处理 |
|---|---|
| 藏浮层时画面闪一下 | 用 `visibility` 不用 `display`（不触发重排）；藏→拍→还原在相邻两帧内完成 |
| 标记层铺满视口挡住一切 | 层容器 `pointer-events: none`，只有 shape 自身 `auto`。这条是本设计最容易出事的地方，要专门验「画布还能不能平移缩放、终端还能不能点」 |
| 拍照瞬间用户正好在拖动标记 | 拍照前先结束绘制态（`draft` 置空、退出便签编辑） |
| 项目目录不可写 | 明确报错，不静默失败 |
| `screenshot/` 目录进了 git | 在 spec 里提示用户自行决定是否 gitignore，**不替用户改他的 .gitignore** |
| 快照攒多了占空间 | 不自动清理。文件在项目目录里可见，用户自己管 |

## 验收

- 画一个矩形盖在活终端上 → 矩形在最上面，且终端仍然能点、能输入
- 画布能正常平移缩放（标记层没有吃掉事件）
- 没选中工作区 → 快照按钮禁用，hover 显示「请在画板中选择一个工作区」
- 选中工作区 → 拍一张，图里**没有**抽屉、缩略图、工具条、缩放条、运行监视
- 图里**有**所有 Frame、活终端内容、以及标记
- 文件落在 `<项目>/screenshot/<日期>/<时间戳>-<序号>.png`，同一天连拍序号递增
- 弹窗选「保留」→ 标记还在；选「清掉」→ 标记消失，图不受影响
- 勾上「记住这次选择」再按「清掉」→ 下次快照**不弹窗**、直接清空
- 设置里把它改回「每次询问」→ 下次快照又开始弹窗
- 勾选框每次弹出时都是**未勾选**状态（不继承上次）
- agent 说「看看画板现在什么样」→ 走到最新快照，而不是只读结构
- 把一个终端模块拖到另一个终端 → 输入栏出现该项目的根路径
