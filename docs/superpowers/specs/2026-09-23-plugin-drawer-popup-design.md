# 右侧抽屉插件面板弹窗 · 设计规格

状态：待用户审阅 · 2026-09-23

## 目标

用户在「更多 → 插件」的右侧抽屉中，点击已安装且已开启、带面板的插件卡片内容，可直接查看插件面板，而不必先在 Frame 中插入画布节点。Jev 等声明必填密钥的插件，在安装完成且尚未配置时先引导用户配置；以后点击未配置的卡片也先配置，不让用户进入不能工作的空面板。

## 用户流程

1. 已装列表中：`cli:'eas'`、`enabled!==false`、`panels.length>0` 的卡片内容为可聚焦点击面。开关、卸载等按钮仍独立，只执行原动作。无面板插件及未开放/未安装条目不出现伪入口；已关闭插件不可直接启动面板。
2. 单面板插件点击后直接打开居中 popup；多面板插件先在 popup 内显示面板选择，不暗猜默认面板。popup 右上角有明确关闭按钮；点击遮罩及 Esc 关闭，内部点击不关闭。关闭后焦点回到来源卡片。
3. 安装提交成功后，重新读取安装后的 `PluginInfo`。如果配置清单存在必填 secret 字段，并且 `plugins.configuration('status')` 表明缺失，则立即打开现有的安全设置对话框。该检查是安装后的一次用户触发动作，不在后台轮询，也不向模型请求密钥。
4. 点击已装卡片时，同样先检查必填配置：缺失则打开设置，用户保存并关闭后重新检查；仍缺失就停留在抽屉，不启动面板。取消/关闭配置不会启动面板。状态查询失败时不冒充“已配置”：显示原因并提供进入设置的路径。
5. 没有必填 secret 的插件不因普通可选字段/目录授权被强制挡住；其面板自行呈现连接引导。配置保存成功不等于在线连接成功，Jev 后续连接验证仍走原面板的显式确认。

## 技术与安全边界

- 复用现有 `PluginPanel` 的 `panelOpen → sandbox iframe → appsProtocol → panelRpc → panelClose` 生命周期与 `eas-plugin://` CSP，不建第二套可信 iframe 或工具代理。画布节点专属的 resize/rename 从面板核心中抽离；popup 尺寸只在宿主可视范围内调整，不写入画布节点。
- popup 会话使用明确的弹窗上下文和当前项目身份，不伪造一个实际存在的 Frame/节点。没有画布节点时不授予 `eas/canvas.call`；主进程必须按 popup surface 拒绝该调用，而不是只靠前端隐藏能力。普通 `tools/call`、插件私有 panel RPC 继续走既有校验。
- 只有主窗口可打开面板，只有已安装的本家插件可打开其清单列出的 panelId；插件已关闭、卸载或更新、抽屉关闭/应用窗口关闭时，popup 必须失效并释放 session。异步 panelOpen 晚到时立即 panelClose，不能泄露宿主引用。
- API Key 继续走现有 `PluginConfigurationControls`/加密存储。前端仅拿到已配置字段 ID，不拿到密钥值；输入不回显，密钥柜锁定时使用现有解锁说明。配置运行中禁止改值及旧确认复活的安全约束不变。
- popup 遮罩不覆盖配置对话框或安装确认的原有防误触逻辑；Esc 按最上层优先级关闭。点击弹窗内容不冒泡到抽屉关闭处理。

## 状态与失败处理

- `loading` 明示正在打开；面板返回错误时显示原错误和重试/关闭；不静默插入画布。
- 状态查询异常、配置被移除、插件更新导致清单变化：重新读插件元数据；不能用陈旧 `PluginInfo` 开面板。
- 多面板选择、popup 关闭和重复点击应只有一个活跃 popup session；切换 panelId 先关闭旧 session。
- 从配置页返回后即使保存了 API Key，也不自动发起可能收费的 Jev 连接验证；用户在面板内明确点击连接。

## 验收

- 隔离应用实际打开带面板插件 popup；遮罩/关闭按钮/Esc 均关闭，并确认 panelClose 释放；普通卡片、开关、卸载不误触。
- Jev 无密钥安装后及再次点击卡片均先见配置；保存后打开面板，取消则不打开；密钥不回显、锁定有指引、无静默付费验证。
- 多面板、卸载中/已关闭、缺失插件、异步开关窗口、主题与窄屏回归。
- 构建、类型检查、目标测试及全量检查；UI/交互只有在隔离应用亲眼验证后才称完成。

## 非目标

不自动开启 Jev 能力，不自动获取/生成 API Key，不改变画布中的面板节点，不安装插件以外的依赖，不发布正式版或生产插件目录。
