# 项目重命名与文件操作：让改名就是真改名

> 2026-08-12 · 设计定稿

## 要解决什么

三件事，量级差别很大：

1. **文件面板没有新建入口**。新建文件 / 新建文件夹**功能已经有了**（`FileTree.tsx` 右键菜单的头两项），
   但面板头部只有「转换器」，没人知道右键里有东西。
2. **项目区的「重命名」是假的**。`projects:rename` 只改 `projects.json` 里的 `name` 字段 ——
   一个纯展示标签，盘上的目录纹丝不动。于是出现「应用里叫 A、访达里叫 B」。
3. **画板的文件节点没法跳到访达**。头部有复制绝对路径、复制相对路径、最大化、删除，
   唯独没有「在访达中显示」。

第 2 件是主体。它要动盘上的目录，所以先做了一次完整排查。

## 排查结果：间接引用的架构已经在了

**改名后自动跟上的**（都已经是「存 `projectId`、用时从 `projects.json` 现查 `path`」）：

| 功能 | 依据 |
|---|---|
| 终端的 cwd | `tabsSlice.ts:138` |
| Frame / 画布节点归属 | `canvas.json` 存 `projectId` |
| 甘特图记录 | `gantt.json` 存 `projectId` |
| **MCP 路径白名单** | `fsGuard.ts` 每次现读 `projects.json`，不缓存 |
| 项目侧栏、git 面板 | 都从 `projectId` 取 `path` |

所以改名只要**原子地**做两件事：盘上 `rename` + 更新 `projects.json` 的 `path`，上面这些全自动跟上。
不需要为它们写任何代码。

**会断的只有四处**：

| # | 什么 | 为什么 | 本设计怎么处理 |
|---|---|---|---|
| 1 | 对话导航的历史会话 | Claude Code 把 transcript 存在 `~/.claude/projects/<把 cwd 非字母数字换成 `-` 的编码名>/`（`session.ts:20-23`）。改名 → 编码名变 → 读不到 | **记住旧路径，读的时候一起找**（见下） |
| 2 | 画布上已打开的文件节点 | `canvas.json` 的 `filePath` 是绝对路径 | **不动**（用户明确定的）。那些节点会显示「文件不存在」 |
| 3 | 正在跑的终端 | macOS 改目录名不杀进程（内核认 inode），但 shell 的 `$PWD` 停在旧路径，agent 记着的路径也对不上 | 确认弹窗里列出「N 个终端正在运行」，让用户决定 |
| 4 | 知识库正好在项目里 | `wiki.json` 的 `path` 是另一套配置，不跟着走 | **直接拒绝改名** |

## 设计

### 一、历史会话：不碰 Claude Code 的目录

原本有两个显而易见的选项——「把 CC 的目录一起改名」或「告诉用户历史会丢」。都不够好：
前者要写别人的地盘（CC 可能正开着那个目录在写），后者是把问题甩给用户。

**改成记别名**：

- `projects.json` 的每个项目加一个可选字段 `pastPaths?: string[]`，改名时把**旧的绝对路径**追加进去
- `session.ts` 的 `projectDir(cwd)` 改成 `projectDirs(cwd): string[]`，返回**候选目录列表**：
  当前路径的编码名 + 该项目所有 `pastPaths` 的编码名（按 `projects.json` 查，方式和 `fsGuard` 一样现读）
- `latestJsonl` across 这几个目录找 mtime 最新的那份

于是：**一个字节都不写 Claude Code 的地盘**，历史会话照常可见，改名前后无缝。
改名之后新产生的会话落在新编码目录，旧的留在旧目录，两边都在候选列表里，不会互相盖掉。

`pastPaths` 上限 5 条，超了丢最老的——它只用来找历史会话，不是审计日志。

### 二、真改名：新加一个自带窄守卫的处理器

**不能复用 `fs:rename`**。它走 `guardPath()`，而 `fsGuard.ts:86-87` 明确拒绝项目根：

```js
// 根目录本身也不许动（改名/删除一个项目根应该走项目管理，不是文件树）
if (real === root) return { ok: false, error: '这是项目或知识库的根目录，不能在文件树里改动它' }
```

代码早就指明了这条路：**项目根改名走项目管理，不走文件树**。所以在 `projects.ts` 里新增
`projects:renameFolder`，自带一套窄守卫，**`fsGuard` 一个字不动**：

- 目标必须**恰好等于**某个已注册项目的根（realpath 比对，不是前缀匹配）
- 新名字过 `invalidNameReason()`（复用现成的，含斜杠 / 点开头 / 控制字符 / 超长都拦）
- 结果必须留在**同一个父目录**里（只改最后一段，不允许借机移动位置）
- 知识库路径若在这个项目下 → 拒绝

### 三、事务顺序

```
校验 → 弹确认 → fs.rename(盘上) → 更新 projects.json → 通知渲染层刷新
                      ↓ 失败
                  原样返回错误，projects.json 一个字节不动
```

**为什么先动盘再动配置**：盘上改失败是常见的（权限、重名、被别的程序占着），配置改失败几乎不会。
先做容易失败的那个，失败就直接返回，不留半截状态。反过来的话——配置改了盘没改——
项目在应用里就彻底找不到了，而且用户不知道去哪找。

`projects.json` 的更新是一次写：`path` 换成新路径、`pastPaths` 追加旧路径、
`name` 按下面的规则决定动不动。

### 四、展示名怎么处理

已有用户可能把 `terminal` 显示成 `Eas-Term`。改名上线后不能替他们丢东西，也不能制造新的「两个名字」：

- `name === path.basename(旧路径)`（说明用户从没自定义过）→ `name` 跟着更新成新目录名
- `name` 与旧目录名不同（用户手动设过）→ **`name` 不动**，只改 `path`

两边都不丢东西。

### 五、菜单：两项并存，不删任何现有能力

现有的项目区右键菜单里，「重命名」自己带着 `hint: '只改显示名，不动文件夹'`
（`projectMenu.ts:44-45`）——应用本来就是诚实的，用户知道它只改标签。

如果把这一项直接换成真改名，就**拿走了「设一个和文件夹不同的显示名」这个能力**。
那不是无感。所以两项并存，标签各自说清：

| 菜单项 | hint | 行为 |
|---|---|---|
| **重命名文件夹…** | `真改盘上的名字，与访达同步` | 新链路（本设计的主体） |
| 改显示名 | `只改应用内的显示，不动文件夹` | 现有的 `projects:rename`，一行不改 |

「重命名文件夹…」排在前面（那是绝大多数人想要的），省略号按惯例表示会弹确认。
`projects:rename` 这个 IPC **保持原样**，`projectsSlice.ts:106` 的调用方也不动。

### 六、① 和 ③

- **①**：`Sidebar.tsx` 的文件页签右侧，在现有的「刷新文件树」按钮**左边**加一个 `+`
  （`data-tip="新建"`），点开两项：新建文件 / 新建文件夹。
  行为复用 `FileTree` 已有的 `startCreate('file'|'dir', null)`（在根目录建），不新写逻辑。
  由于 `startCreate` 是 `FileTree` 内部状态，需要把它通过 ref 或回调暴露给 `Sidebar`
  ——两者已经通过 `filesRefresh` 计数器通信过，沿用同一条线即可。

  > ⚠️ **待确认**：需求截图里那个「∨ 文件 / 转换器」的面板**不是 Eas-Term 的界面**——
  > 全仓搜索「转换器」零命中，Eas-Term 的侧栏是「文件 / 版本」两个页签 + 一个刷新按钮。
  > 上面的落点是按 Eas-Term 实际界面定的。若截图另有所指，这一条要重定位。
- **③**：`CanvasFileNode.tsx` 头部在「复制相对路径」和「最大化」之间加一个按钮，
  `data-tip="在访达中显示"`，`onClick` 调已有的 `window.api.fs.showInFolder(absPath)`。
  只在 `absPath` 存在时显示（和旁边两个复制按钮同一个条件）。

## 明确不做

- **不搬 Claude Code 的会话目录**——改用别名解析，不写别人的地盘
- **不重写画布节点的路径**——用户定的
- **不动 `fsGuard`**——它现读配置，改名后自动正确；放宽它等于削弱沙箱
- 不做批量改名、不做撤销、不做移动项目位置（只改最后一段）

## 风险与取舍

| 风险 | 处理 |
|---|---|
| 改名时项目下有 agent 正在干活 | 确认弹窗列出正在运行的终端数，说清「进程不会死，但它记着的路径会对不上」，用户自己决定 |
| 用户改完发现不对想改回去 | 改回原名即可，`pastPaths` 会累积但不影响正确性；历史会话两边都找得到 |
| `pastPaths` 无限增长 | 上限 5 条，超了丢最老的 |
| 新加的处理器成为绕过沙箱的口子 | 守卫是「恰好等于某个已注册项目根」+「结果留在同一父目录」，比 `fsGuard` 更窄，不是更宽 |
| 分发版用户升级后语义变化 | 菜单文案改成「重命名文件夹…」；`projects.json` 结构向后兼容（`pastPaths` 可选），不需要迁移，不弹任何东西 |

## 验收

- 改名后：终端 cwd、Frame 归属、甘特图、MCP 白名单、git 面板全部指向新路径，**不需要重启**
- 改名后：对话导航里该项目的历史会话**照常可见**
- 改名后：`~/.claude/projects/` 下的目录**没有任何变化**（用改名前后的 `ls` 比对）
- 改名失败（造一个同名目录）：`projects.json` 逐字节不变
- 知识库在项目里时：拒绝，并说清原因
- 自定义过展示名的项目：改名后展示名不变
- 没自定义过的：改名后展示名跟着变
- 「文件」面板头部的 `+` 能建出文件和文件夹，与右键菜单行为一致
- 画板文件节点的新按钮能在访达里定位到那个文件
