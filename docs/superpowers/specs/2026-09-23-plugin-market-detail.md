# 插件市场详情视图 · 设计规格（2026-09-23 已确认）

## 目标与现状

用户要在安装前看懂每个插件包含什么、适合什么场景、如何使用、有哪些能力与工具。现有 `PluginMarketModal` 只有卡片中的 `<details>` 简介；`PluginRegistryEntry` 也仅有短描述、版本、权限等字段。不能把现有卡片展开冒充详情页，也不能根据插件名称猜测工具能力。

参考：VS Code 市场将 README/更新记录作为详情主体；Slack 分开展示描述、功能与权限；Atlassian 强调实际使用场景与带说明的截图。笔纵只借鉴信息架构，不复制视觉。

## 导航与交互

1. **卡片非交互区域就是详情入口**：点击图标、名称、简介、状态或卡片留白，打开该插件的完整详情；不另加“详情”按钮。既有安装、更新、连接账号、授权目录、来源选择等按钮只执行自身动作，绝不冒泡打开详情。
2. 从市场列表进入同一市场弹窗内的独立详情视图，而不是叠加第二个模态框。保留列表的分类、搜索词和滚动位置。左上有“返回插件市场”，Esc 先返回列表、再按才关闭市场；焦点返回原卡片。
3. 非交互卡片区域实现为覆盖其展示区的**语义按钮**（外观仍是完整卡片，绝非新增可见按钮），与右侧现有操作控件为兄弟节点，避免 button 嵌套。Tab、Enter、Space 可打开；焦点环和 hover 轻微高亮表明整块可点。鼠标点击卡片空白也命中详情入口。
4. 详情内的安装/更新复用原两段确认；未安装时不得启动插件或请求密钥。详情打开不触发下载插件包。更新、连接或卸载后留在当前详情并刷新状态。
5. 窄窗口详情改为单列；顶部主要操作保持可见但不遮挡正文。长工具名、权限域名均换行，无横向滚动。

## 详情内容层级

**首屏**：真实注册图标、名称、短定位、版本、来源（官方／外部）、安装状态、主行动（安装／更新／已安装）及“是否需要账号或费用”的明确标识。

**场景**：一句话说明“帮你完成什么”，然后 2–4 个“当你想……时”的具体例子。演示只描述真实已实现的能力，不把候选/规划写成可用。

**怎么用**：按“安装 → 授权/连接（如需要）→ 在软件中的入口 → 一句示例请求 → 查看结果”列出步骤。每步标出发生位置，避免新用户不知道在哪点击。无需配置的插件不显示虚构的连接步骤。

**能力与工具**：先用人话列能力，再可展开查看真实工具名、输入范围、输出以及调用/触发条件。区分“AI 可调用工具”“面板交互”“仅给建议”，不得把技能文案当作独立工具。工具清单须与对应包版本核对。

**权限与数据**：逐项解释所需目录、画布操作、事件订阅、目标域、第三方账户与可能的计费；提供“不做什么”的边界。真实权限仍以安装确认弹窗和受校验清单为准，详情不能替代授权。

**末尾**：兼容宿主版本／平台、更新记录、支持/文档入口、包大小与来源。缺失内容显示“开发者未提供”，绝不自动编造。离线缓存标注“可能不是最新版本”。

## 数据契约与发布

- v2 registry 每个插件可附加可选的 `detail` 结构化元数据（场景、步骤、能力、工具、数据说明、更新记录、支持链接）；旧客户端忽略它，v1 不新增字段。
- 详情元数据由发布方维护，绑定插件 `name + version + sha256`；发布前工具名称与该版本包、权限说明与受校验 manifest 比对。不从插件包运行时抓取，也不在打开详情时下载 zip。
- 文本按字段限制长度与条数；只渲染纯文本或受控组件，不接受任意 HTML/Markdown 脚本。外链仅 HTTPS，并经现有内部浏览器打开。外部来源的缺字段安全降级，不伪称官方审查。
- 为线上现有 8 项制作最小可信详情；每项须核对来源包/README/工具清单，不可靠内容先留“未提供”。后续插件由发布流程要求随目录提交详情资料，而非只填一句描述。
- 目录仍有总大小上限；发布器须校验详情并保留线上既有条目，不用当前默认候选列表覆盖正式市场。

## 验收

1. 卡片展示区任一点、键盘 Enter/Space 可进详情；安装/更新/配置/链接点击不进详情。
2. 返回后搜索、分类、滚动及焦点位置保留；Esc 两级退回。
3. 8 个线上插件均有经核对的场景/步骤；工具缺失时明确“未提供”。未安装也可阅读，且不下载包。
4. 权限/域名变化不会被详情文案掩盖，安装确认仍独立出现；外部来源和离线/过期目录有明确提示。
5. 亮暗主题、窄分屏、键盘与屏幕阅读器验收；隔离应用实际点击并截图。构建与全量检查通过后才可说 UI 已完成。

## 非目标

本次不实现评分、评论、远程截图上传、插件自动更新、支付或推荐排序。自动更新另行设计安全策略。
