# 可重复的未登录安装测试实例 · 设计规格

日期：2026-09-22。用户确认：每次测试从未登录、无既有 CLI 的全新电脑状态出发，完整走完 Eas-Term 与 Claude Code / Codex 安装及登录流程；一次测试内的状态可持续，下一次测试不继承。

## 目标与非目标

- 目标：在现有 Tart macOS 虚拟机之上建立可复用的**干净基线**，并有一键生成/打开新测试副本的入口。基线本身不作为日常测试机使用。
- 每次启动**新测试**时，Eas-Term、Claude Code、Codex 都不得有登录凭证或历史安装状态；首次安装引导应可从头触发。
- 同一次测试中用户安装/登录成功后允许状态变化，以便验收成功页、重试、失败恢复和后续使用；“永远未登录”仅指每次从基线生成新实例的初始状态。
- 不清空宿主 macOS 的账号/应用/CLI；不复制宿主用户目录、密钥、插件、项目或系统钥匙串到客体。
- 不以仅更换 Electron userData 代替操作系统级隔离；也不做 CI/云端部署。

## 方案比较与决定

1. **Tart 已初始化基线 + 每轮 APFS 克隆（采用）**：首次设置 macOS 本地测试账号，安装待验 Eas-Term 包但不登录/装 CLI，关机后克隆为测试副本。克隆走写时复制，副本可保留或由用户显式清理。系统与产品安装状态都能复现，且宿主独立。
2. 每轮从 Apple IPSW 重装：隔离最强但下载/安装耗时、空间成本高，日常回归不可用。
3. 宿主上多 userData：快但仍看到宿主 CLI 与登录态，不满足真实新电脑测试。

## 状态模型与组件

- `eas-install-baseline`：已完成 macOS 首次设置、仅本地测试账号、无 Apple ID/iCloud/迁移数据；Eas-Term 待验包已放入客体并可启动，但从未登录，目标 CLI 未安装。只用于克隆，不直接运行验收。基线建立前从客体检查 CLI 命令缺失、应用无登录/历史数据。
- `eas-install-test-<日期时间>`：每次“开始新测试”从基线克隆的独立副本。生成后仅启动这个副本，不修改基线或其他副本。名称带时间戳，避免覆盖。
- `start-new-test.command`：检查基线存在且停止、当前可用磁盘空间、名称未占用，克隆后 `tart run` 启动；不使用 `--dir`，关闭剪贴板共享。失败时保留日志并明确副本是否存在，不静默删除。
- `list-tests.command`：只列出专用命名前缀的测试 VM 与状态；不遍历或操作宿主其他 VM。
- `remove-test.command`：仅接受专用测试前缀且必须显式确认名称，不允许移除基线；运行中拒绝删除，绝不自动清空最近测试结果。删除是独立操作，不是“开始新测试”的副作用。

## 首次准备顺序

1. 启动现有 `eas-clean-macos-20260922`，完成 macOS 首次设置。使用本地测试账号；账号密码只在虚拟机内设置，不向聊天收集或写入项目文档/脚本。跳过 Apple ID、iCloud、Migration Assistant。
2. 选择用于验收的 Eas-Term 构建产物，单独传入客体。默认不共享整个宿主目录，不复制宿主 Eas-Term 用户数据。包安装之后仍不能登录或安装 CLI。若客体下载，需要证实是目标产物，而不是混入旧版。
3. 在客体检查 Eas-Term 首次使用页与 `claude`/`codex` 等目标命令缺失，记录版本与截图。若检查不满足，不能封基线。
4. 关机后克隆为 `eas-install-baseline`，验收基线配置与来源；原始 VM 保留作恢复源，不覆盖。
5. 从基线生成首个测试副本并实际打开，核对未登录/未安装初态。至少再创建第二个副本核对互不继承，证明“可重置”而非只做一次。

## 失败与恢复

- 空间不足：生成前停止并提示需要空间，不启动、不覆盖、不清理其他 VM。Tart 克隆使用 APFS 写时复制，但测试过程中仍会增长；保留安全余量。
- 基线不存在/运行中/未验收：拒绝开始新测试，给出明确原因。
- 克隆失败：保留 Tart 原始错误与任务日志；如果产生半成品，仅标记待人工清理，不自动删除未知内容。
- 客体安装或登录失败：这是验收样本，保留该副本供排查；用户再点“开始新测试”获得新副本，不在原副本里假装清理干净。
- 升级待验应用：创建**新版本基线**，旧基线与已有测试副本不被悄悄改写；记录包版本/哈希。

## 隔离与验收边界

- Tart 启动不带 `--dir`，使用 `--no-clipboard --no-audio`；不把宿主钥匙串/SSH/浏览器配置/CLI 配置挂进客体。
- 本地测试账号本身只是操作系统进入桌面的必要条件，不等于 Eas-Term 或 AI CLI 登录。
- 仅凭宿主检查、脚本单元测试或截图欢迎页不能声称“可完整跑安装流程”；必须在客体桌面实际启动待验包，亲眼确认未登录入口，并从**第二个新副本**重复初态。
- 真实 Claude Code / Codex 安装、登录、失败翻译、最小化/完成通知的端到端结果需另行逐项记录；本规格交付的是可重复的验收环境，而不是预先宣称产品验收通过。
