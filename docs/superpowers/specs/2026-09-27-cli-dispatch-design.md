# 多 CLI 全局错峰调度设计

状态：方向已确认，设计待确认；未改生产代码。

## 目标与边界
对软件托管的 Claude、Codex、OMP 对话轮次统一调度，避免同时发送形成突发。跨窗口、跨项目共用主进程额度。默认最多 2 个活动轮次，两次实际派发至少间隔 1000ms。参数是保守初值，不是带宽测量结论。
不代理 HTTPS、不读取密钥、不精确限制字节带宽，不覆盖普通终端自行启动的 CLI 或其他应用。CLI 内部子请求不在此层单独调度。背景下载与模型目录探测不纳入首版。

## 现有边界
主线 src/main/runtime/scheduler.ts 的 interactive 工作绕过普通 maxRunning；它是资源启动控制，不是对话网络调度。
session.ts 已有 runtimeStartupId/runtimePendingMessage、deliverMessage、interruptManagedTurn 以及 ACP 启动路径。新层必须覆盖首条消息和复用会话后续轮次，不能只限制进程启动。
不改变既有 CPU/内存门与安全授权；不得用持有父任务额度再等待同一队列子任务的方式引入死锁。

## 调度规则
- 主进程唯一调度器；按 sessionId + turn generation 去重，每会话保持消息顺序。
- 同项目 FIFO、项目间轮转；无项目会话使用稳定归属键，避免全部挤到匿名单队列。
- 有空额度且达到派发间隔才派发；重试/内部自动续轮若产生新请求也需经过统一入口，不允许绕过。
- 额度占用整个实际轮次，直到明确结束或底层取消/退出被确认。IPC 返回成功不是完成，点击停止也不是立即释放。
- 排队取消直接移除并保留可恢复的未发送内容；已派发不自动重放。重复/迟到回调不能释放新轮次额度。
- 异常退出释放自己的额度，关闭窗口/会话取消其排队项并走既有运行取消流程；调度器异常不得静默无限放行。
- 应用退出不持久自动重放任务；未发送内容沿用草稿/消息队列恢复路径，启动后由用户重新发送。
- 排队不计模型首响应与执行超时。运行中的用户授权等待首版仍占位，以避免 CLI 自行恢复导致并发超限；界面明确提示。
- 队列有界，满载明确拒绝且保留用户输入；具体容量在实施计划中结合现有消息队列确定。

## 界面与设置
沿用运行与资源页面，新增“AI 任务并发”：省网络 1、均衡 2（默认）、自定义 1–8。
更改持久化并经主进程校验；调小不强停已有任务，只暂缓新派发。1000ms 间隔首版固定。
会话显示“等待调度”，附可变排位/原因与取消，不承诺预计秒数。运行与资源页复用任务监控入口，不新增独立悬浮面板。

## 多维评估
- 完整性：三家入口、复用会话、取消/异常均必须纳入，防止只限制启动。
- 体验：默认仍可并行两项；排队可见，不伪装成模型正在思考。
- 成本：调度全本地，不新增 LLM 请求或 token。
- 局限：长任务/授权等待会延迟后续任务；无法保证整个系统网络不满载。

## 验收
确定性时钟测试：并发上限、间隔、项目公平、取消、迟到事件、释放幂等、运行调参、队列容量、资源门等待。
三路协议夹具：首轮和复用轮次均入队，排队不触发执行超时、不重复发送。
构建后隔离应用验证：多个会话同时发送、可见等待与取消、任务结束后推进、设置恢复。
真实在线端到端与 Windows 未实际执行前必须标未验证，不用夹具替代声明。
