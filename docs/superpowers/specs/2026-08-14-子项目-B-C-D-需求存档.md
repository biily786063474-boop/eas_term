## C — 待办清单模块

### 用户原话

> 待办清单功能（单独一个模块，可扩展可维护）
>
> 鼠标右键点击画板任意位置可以创建待办清单，待办清单模块右上角有 + 号，
> hover 的时候有添加一个待办，然后就会产生一个待办卡片，前面有圆形，
> 用户点击后会打勾并折叠，卡片右侧有拖拽元素可以拖拽卡片的上下排序，
> 排序的时候卡片之间要有位置移动的动态，平滑曲线速率，hover 卡片的时候
> 卡片平滑放大给反馈，卡片显示待办标题，点开后会出一个灯箱，
> 灯箱里用户可以输入详细的正文信息，灯箱在用户点击非灯箱区域的时候关闭，
> 打开关闭都需要有一些动态反馈

补充（同日）：

> 待办清单除了[右键]可以创立，也要放在矩形、箭头、批注那个菜单里，
> 共享他们的视觉层级

### 已定的设计输入

- **入口两个**：画板任意位置右键；以及画布工具条里「矩形 / 箭头 / 批注」那一组
- **视觉层级与标记同档** —— 即 `.canvas-shape-layer` 那一层（`z-index: 15`，
  见 `canvas.css` 里那段层级注释）。也就是说：压在活终端之上、压在所有画板外 chrome 之下
- **不被快照清空**。快照后的自动清空作用于 `shapes`（矩形/箭头/批注三种全清，
  这条 2026-08-14 用户确认维持现状），而待办是**独立模块不是 shape**，天然不受 `clearShapes` 影响。
  实现时注意别为了「共享层级」就把它做成第四种 shape —— 那会连清空一起继承。

### 现成的教训（**别再踩一遍**）

`src/renderer/src/features/terminal/useTerminalTodos.ts` 是已有的另一个待办
（终端输入框右键插入的那个），它顶部记着一条硬教训：

> 待办的 key **不能绑 `ptyId` / `leafId`** —— 重启后画布上「看起来还是那个终端」的节点，
> 背后已经是全新进程、全新 leafId（见 `canvasSlice.ts` 的 `materializeCanvas`：
> 重启后画布终端节点的 leafId 被剥掉重开）。**唯一扛得住重启的是画布节点自己的 id。**

新的待办模块是画布上的独立模块，有自己的节点 id，这条正好适用。

### 动手前要问清的

- 待办清单是「一个画布模块里装很多条」还是「每条待办一个画布模块」
- 跨项目还是绑项目（放在 Frame 里 vs 自由节点）
- 打勾折叠之后去哪 —— 沉到底部？收进一个「已完成」区？还是原地折叠
- 灯箱正文存哪、要不要 Markdown

## D — skill 管理面板

**四个里最大的一个**，而且它自己就含一个对外的 schema 契约。建议单独一轮完整设计讨论。

### 用户原话

> skill 管理面板（单独一个模块，可扩展可维护）
>
> 在对应的项目 frame 中可以查看不同 cli 的全局 skill 和 cli 可以通过点击 cli 按钮
> 来选择 skill 目录，当前项目的项目 skill 放到知识库抽屉中，没选中 frame 的情况下
> 显示全局 skill，点击知识库抽屉左上方名称通过下拉菜单切换，用户可点击 skill 名称
> 来查看 skill 的详细文件树，文件树可以拖拽到画布上进行编辑，skill 可以被在本软件中
> 右键复制，粘贴到 skill 的其他目录，用户也可以右键暂时禁用和恢复使用某个 skill，
> skill 面板开放一个可以被 skill 接管的口子，这个口子可以让 agent 来自动整理 skill 分类，
> 然后这个分类会在前端 GUI 中显示，并且分类可折叠，这个口子要严格规范输入输出 schema，
> 并且与其配套的 skill 要和这个模块一起维护

### 拆出来的功能点

1. **双源展示**：全局 skill（按 CLI 分）与项目 skill
   - 选中 Frame → 该项目的项目 skill 进知识库抽屉
   - 没选中 Frame → 显示全局 skill
   - 知识库抽屉左上角名称点击 → 下拉切换
2. **CLI 切换**：点 CLI 按钮选 skill 目录（不同 CLI 的 skill 目录不同）
3. **文件树**：点 skill 名称展开详细文件树；文件树可拖到画布上编辑
4. **管理操作**：右键复制 skill → 粘贴到别的 skill 目录；右键临时禁用 / 恢复
5. **agent 接管口**：给 agent 一个自动整理 skill 分类的口子
   - **严格规范输入输出 schema**
   - 分类结果在 GUI 中显示，**可折叠**
   - **配套 skill 与本模块一起维护**（不能一个改了另一个不知道）

### 现状（已查）

skill 相关的代码现在散在：`src/main/agentRules.ts`、`src/main/roles.ts`、
`src/renderer/src/features/workspace/AgentOnboarding.tsx`、
`src/renderer/src/features/canvas/agentCommands.ts`。

项目里已有一个 `.claude/skills/agent-onboarding/` skill，
它盘的正是「给 Eas-Term 接入一个新 AI CLI 要改哪五个注入面」——
D 的「多 CLI」部分与它高度相关，设计时必须一起看，否则会长出第二套并行逻辑。

### 动手前要问清的

- 「暂时禁用」怎么实现 —— 改文件名？移到 disabled 目录？还是写一份禁用清单？
  （直接动用户的 skill 文件是有风险的操作，需要明确）
- agent 接管口是 MCP 工具还是文件契约
- 分类信息存哪 —— 存在 skill 目录里（跟着 skill 走）还是存在 app 的 userData 里
- 「文件树拖到画布上编辑」编辑完怎么写回

   标记就是用来指着终端说「这块」的。
