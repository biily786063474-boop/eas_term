# 对话窗口能力补齐 — 设计

> 2026-08-20。五条需求来自一次连续反馈，前两条改的是**子 agent 的可见性模型**，
> 后三条改的是**AI 对话相对原生 CLI 的能力差距**。

## 需求原文

1. 「那这个列表中我无法通过点击打开查看它正在运行的进程」
2. 「默认是不出可以看到进程的会话框的，用户点击团队节点中的相关子进程才会显示对应的子进程」
3. 「子进程在结束一段时间不用等情况下会话面板就关掉」
4. 「AI会话窗口现在不支持显示所有的slash命令」
5. 「MCP服务在AI对话窗口进行的时候好像也没有连接」＋「AI对话中有什么和CLI能力相比缺失的地方都要补充」
6. 「子agent活没干完，但是网络连接抖动造成的终端也被判定为活干完了」

## 一、可见性模型（需求 1–3）

### 关键事实：leaf 和画布节点是**两层**

| | 是什么 | 谁建的 | 销毁会怎样 |
|---|---|---|---|
| **leaf** | 会话本体：`AgentChatView` 挂载点、`sessionId`、`resumeId`、聊天历史 | `openAgentPane` | 会话没了 |
| **画布节点** | `frame.nodes` 里的一项，纯粹是**可见性** | `placeNodeInFrame` | 只是看不见了 |

证据：
- `PaneLayer.tsx` 头注释：**所有 tab 的所有 leaf 都渲染在同一个容器里，永不换父**，
  没被 Frame 引用的只是隐藏（split 那条写得更明白：`display:none`，**保挂载**）。
  所以不挂画布节点的会话照样起得来 —— 这是「默认不显示」成立的全部前提。
- ~~`removeNode` 只 `f.nodes.filter(...)`，一行都没碰 leaf~~ ——
  **这条是错的**（只读了前 16 行就下的结论）。它的尾巴上有
  `if (tab) get().closeLeaf(tab.id, leafId)`，是「关掉这个节点」的完整语义。
  2026-08-20 真机验证抓到：照这条实现的收起会连 leaf 一起销毁，
  于是再也点不开（`leafSurvivedHide=false`）。**收起要自己 set 摘节点，别走 removeNode。**
- `mcpHandler.ts:1013` 的注释记着当初的踩坑：只 `openAgentPane` 不挂节点时
  「**会话确实起来了**，但画布上一个新节点都没有」——那个 bug 正是需求 2 想要的行为

所以三条需求不需要任何新机制，用现成的两个原语就够：**挂节点 = 显示，摘节点 = 收起**。
不涉及「接管一个已经在跑的会话」这种复杂逻辑，因为 leaf 从头到尾没被销毁过。

### 方案

- **需求 2（默认不显示）**：`team_spawn` 改成只 `openAgentPane`，不挂画布节点。
  进程照起，画布保持干净。
- **需求 1（点开）**：团队面板的行加点击 → 把那个 leaf 挂回画布并聚焦。
  节点已经在画布上时就只聚焦，不重复挂。
- **需求 3（自动收）**：会话结束（`alive=false`）且超过静默期 → `removeNode` 摘掉节点。
  **正在被聚焦/最大化的节点不收**——用户在读输出时收掉是最恼人的失败模式。
  收起只摘节点，会话和历史都留着，点面板还能再打开。

### 静默期取值

先定 **3 分钟**。太短会打断人读输出；太长则画布上一直挂着一排死节点，
违背需求 2 的初衷。这个值单独抽成常量，实际用起来不合适可以直接调。

### ⚠️ 与需求 6 的咬合（必须一起做）

需求 3 的自动收起**依赖一个判断：这活是不是真干完了**。而需求 6 说的正是这个判断会误判。
两条分开做的话，结果是「网络一抖 → 误判干完 → 自动收起 → 用户再也看不见这个没干完的活」，
比不做自动收起更糟。**所以自动收起的前提改成「正常结束 **且** 交了活」，见下节。**

## 二、别把「进程没了」当成「活干完了」（需求 6）

### 现状的判据不够

现在面板认两件事：`alive`（进程还在不在）和 `busy`（turn 进行中）。
进程一没，就归到「这轮完了」。但进程消失有两种完全不同的原因：

| | 发生了什么 | 该怎么显示 |
|---|---|---|
| **正常结束** | CLI 跑完一轮，自己优雅退出 | 这轮完了 |
| **异常终止** | 网络抖动、API 报错、进程被杀 | **活没干完，中断了** |

现在这两种在面板上长得一模一样。用户反馈的就是后者被显示成了前者。

### 判据：三样东西一起看

1. **退出码**：0 = 正常收尾；非 0 = 出事了
2. **最后一个事件**：收到过 `turn.done` 才算跑完一轮；直接断流就是中断
3. **交没交活**：`teamFindings.ts` 的 `deliveredOf` 已经在做这件事
   （`missing` / `thin` / `ok`，120 字节以下算 thin）

「正常结束」= 退出码 0 **且** 收到过 turn.done。
「干完了」= 正常结束 **且** `delivered === 'ok'`。
**只有「干完了」才自动收起。** 其余一律留在画布上，且面板要标出来。

### 中断之后能接着跑

`resumeId` 还在，花名册（`teamRoster.ts`）里留着 task 原文——
这两样正是为「重派是一条命令」准备的。中断的行给一个**「接着跑」**，
用同一个 resumeId 续上，不用从头来过。

先不做自动重试：网络抖动的恢复时机没法预判，自动重试可能在断网期间连撞几次，
每次都是完整上下文的钱。**先把「看得见 + 一键续」做对**，自动重试等有实测数据再说。

## 三、CLI 能力补齐（需求 4–5）

### MCP：确认没连，而且是有意为之

`adapters/claude.ts:79` 传了 `--strict-mcp-config` 却**没有配套的 `--mcp-config`**。
按 `claude --help`：*Only use MCP servers from --mcp-config, ignoring all other MCP
configurations* —— 等于一个 MCP server 都不加载。

`adapters.test.ts:44` 有一条测试**专门盯着这个行为**，标题就叫
「Claude 带 --strict-mcp-config 但不带 --mcp-config —— 等于零 MCP 工具」。

后果（2026-08-19 派 agent 实测发现的）：

- Claude 起的对话节点**一个 eas-term 工具都没有** ——
  `canvas_*` / `notify` / `wiki_*` / `secret_*` 全调不到，连 ToolSearch 都搜不出来
- **Codex 那侧没这个参数**，照常读全局 `~/.codex/config.toml`，能力面大得多

也就是说：同一个软件里，用户选 Claude 还是 Codex，AI 能干的事完全不同。
这不是设计，是历史遗留。

### 要连，但要带护栏

打开 MCP 等于给所有 AI 对话节点开放整个工具面（能改画布、能发通知、能碰密钥柜）。
护栏按这个分层：

| 层 | 做法 |
|---|---|
| 工具面 | 给 `--mcp-config` 一份**只含 eas-term 的**配置，不引入用户全局的其它 MCP server |
| 危险工具 | `secret_*` 一类保持现有的用户确认流程，不因为工具可见就放行 |
| 团队 agent | `team_spawn` 的 `isTeamOwnedCaller` 硬闸**必须真的生效** |

第三条尤其要紧：现在「Claude 起的团队 agent 不能再派活」靠的是
**它压根没有这个工具**（harness 层报 `No such tool available`）。
一旦接上 MCP，那道被动保护就没了，硬闸变成唯一防线。
好消息是硬闸已经按 `ctx.teamRole` 实现（读事实而非猜测），
接上 MCP 后越权尝试反而**变得可审计**——现在它只在对方自己的 transcript 里留一行，
team 侧什么都看不到。

### Slash 命令

现状：软件只在内部发 `/model`、`/effort`、`/compact` 这几条，
还专门用 `slashSilence.ts` 把回执吞掉（避免刷屏）。
**用户手输 slash 时没有任何命令列表或补全**——需求 4 说的就是这个。

要补：输入 `/` 弹出命令列表（含 CLI 内置命令与用户自定义命令），可筛选、可选中。
命令来源需要先实测 —— headless `-p --input-format stream-json` 模式下
哪些 slash 真的有效，不能照抄交互式 CLI 的清单。**这条先做调研再动手。**

### 其余能力差距

需求 5 的后半句要求系统盘点，单独派 agent 做，产出落 `.plans/cli-gap/findings.md`。
盘点范围：斜杠命令、MCP、hooks、自定义 agents、图片输入、文件引用（@）、
后台任务、权限模式、思考强度、会话恢复。

## 四、执行顺序

1. **中断判定**（需求 6）——**排在可见性前面**：自动收起要靠它才敢收
2. **可见性模型**（需求 1–3）——三条互相咬合，一起做一起验
3. **MCP 接上 + 护栏**（需求 5 前半）——独立，改动集中在 adapter
4. **CLI 能力盘点**（需求 5 后半）——派 agent 调研，与前面并行
5. **Slash 命令列表**（需求 4）——依赖第 4 步的实测结论

前两项自验用 `npm run verify`（隔离实例 + CDP），不打包。
