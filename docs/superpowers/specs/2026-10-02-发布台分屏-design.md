# 发布台分屏 · 设计（2026-10-02）

## 背景与目标

发布台 0.1.1 里点「打开发布页」，宿主走 `ui/open-link → canvas_open_url`，在项目 Frame 里散着开一个网页节点。发一次宣发要开五六个平台，节点散落、要来回切到发布台面板复制文案。

用户要的：**画布上一个专用的「发布分屏」Frame，同屏最多 6 个发布页（3 列 × 2 行）**，在插件里点哪个就把哪个放进分屏；每格顶上直接能复制文案、标记已发布。

已定的决策（2026-10-02 对话）：

| 问题 | 决定 |
|---|---|
| 分屏放哪 | 画布上一个专用 Frame（不新做全屏视图，不用现有「分屏」视图模式） |
| 满 6 格再加 | 替换**已标发布**里最早打开的那格；6 格都没发 → 替换最早打开的那格，并提示「已替换 X 的格子」 |
| 已在分屏里的平台 | 不新开，镜头移到那格并高亮约 1 秒 |
| 一键铺满 | 要。面板加「分屏打开」：按当前筛选挑前 6 个有文案、未发布、未标「不发」的平台 |
| 每格顶上 | 要。平台标识 + 复制标题 / 正文 / 标签 + 标记已发布 |

## 第一部分 · 结构

### 每格 = 网页节点 + 插件自己的头条小面板

- 插件新增一个面板 `cell`（清单 `panels` 里第二项），高约 44px，props 为 `{ batchId, platform }`。它就是一个普通插件面板：经现有面板 RPC 调 `desk_list` / `desk_mark`、用 `panel/clipboard.write` 写剪贴板。**不新增「面板之外调插件工具」的通道**，安全边界不变；发布台主面板关着，头条照样能用。
- 网页节点 `PaneState`（`kind: 'web'`）加可选字段 `companion?: { pluginId: string; panelId: string; props: Record<string, unknown>; openedAt: number }`（`openedAt` 是放进分屏的时刻，替换规则用）。渲染网页节点时，若有 `companion` 且该插件仍启用，在网页上方渲染 `<PluginPanel>`（固定高度，复用现有组件与沙箱）；插件被关掉或卸载时只显示网页、不报错。字段随画布存档，重启后恢复。
- 头条与网页是同一个节点，拖动、缩放、删除一起走。

### 宿主新增面板宿主动作 `panel/split.open`

- 与 `panel/clipboard.write`、`panel/reveal` 同类：**只能在用户在面板里真实点击的当下发起**（判定沿用 `shared/panelHostActions.ts` 的点击闸门），插件不能自己连开浏览器。
- 清单 `permissions.split: true` 才放行；宿主在 `ui/initialize` 的 `hostCapabilities.experimental.eas.split` 里声明支持（插件据此决定显示与否）。
- 参数：

```ts
{
  title: string                 // Frame 标题，如「发布分屏 · <批次名>」
  max: number                   // ≤ 6，宿主再夹一次
  cells: Array<{
    key: string                 // 平台 id，分屏内唯一
    url: string                 // 只允许 http(s)
    companion: { panelId: string; props: Record<string, unknown> } // 必须是本插件清单里的面板
  }>
  published: string[]           // 已标发布的 key（替换优先级用）
}
```

- 返回：`{ opened: string[]; reused: string[]; replaced: Array<{ out: string; in: string }> }`。
- 宿主做的事：在面板所在 Frame（`ctx.frameId`）里按「插件 + 用途」找到或新建**唯一一个**分屏子 Frame（标题随最近一次调用更新）；对每个 cell：已在 → 记 reused；有空位 → 新增网页节点；满 → 按替换规则换掉一格。最后按格数排版并把镜头对准该 Frame 铺满可视区。
- 分屏 Frame 用 `frame.owner = { pluginId, purpose: 'split' }` 标记；格子的打开顺序存在节点上（`companion.openedAt`），替换规则据此判断，重启后不丢。

### 兼容旧版本宿主

插件读 `hostCapabilities.experimental.eas.split`：没有（0.4.120–0.4.123）→ 「分屏打开」不显示，卡片上「打开发布页」退回 `ui/open-link`。插件 `minHostVersion` 仍为 0.4.120。

## 第二部分 · 交互

### 发布台面板
- 筛选行最右加主按钮「分屏打开」：按当前筛选取前 6 个「有文案 && 状态不是 published / skipped」的卡片；一个都没有时置灰，悬停提示「当前筛选下没有要发的平台」。
- 卡片上「打开发布页」改为放进分屏（文字不变）。
- 结果写进底部状态栏：「已在分屏打开 小红书」「知乎已在分屏中」「分屏已满，已替换 X 的格子」。

### 分屏 Frame
- 标题「发布分屏 · <批次名>」；同一项目 Frame 里只有一个，换批次复用。
- 排版：每格约 420 × 520。1–3 格：一行 n 列；4 格：2 × 2；5–6 格：3 列 × 2 行。格子按 `openedAt` 从左到右、从上到下排。
- 打开或新增后镜头对准分屏 Frame 并缩放到铺满可视区；之后画布照常可拖可缩。
- 已在分屏里的平台：镜头移到那格，节点标题栏强调色描边约 1 秒。

### 头条（`cell` 面板）
- 左：平台标识 + 名字；右：复制标题 / 复制正文 / 复制标签 / 标记已发布。卡片没有标题或标签时对应按钮不显示；复制成功按钮闪「已复制」。
- 标记已发布：与主面板相同的「填链接（可不填）→ 确认」；成功后头条变为已发布态。主面板与其他头条经数据文件监听（0.1.1 的 `lib/watch.mjs`）同步刷新。
- 文案由插件决定，仍只有中文（插件面板现有限制，宿主未传界面语言，本次不处理）。

### 资源
- 网页格子沿用现有离屏回收（滚出视口 120s 释放进程，回来重载，登录态保留在 `persist:browser`）。
- 一次铺满 6 个约多占 1–2 GB 内存，只在用户点「分屏打开」时发生。

## 第三部分 · 验证

- **宿主纯函数单测**：排版（1–6 格坐标与 Frame 尺寸）；替换选择（优先已发布里最早、其次最早、key 已在则 reused）；参数校验（max 夹到 6、非 http(s) 拒、companion 面板不在清单拒）。
- **插件单测**：「分屏打开」挑选规则（筛选、有文案、未发布、未标不发、最多 6）。
- **真机验收**（隔离实例、CDP 真实鼠标）：
  1. 点「分屏打开」→ 铺出 N 格，镜头对准；
  2. 再点分屏里已有的平台 → 只聚焦不新开；
  3. 满 6 格点第 7 个 → 换掉已发布的那格，状态栏有提示；
  4. 头条复制 → 剪贴板内容正确；
  5. 头条标记已发布 → 主面板同步变化；
  6. 关掉主面板 → 头条照样可用；
  7. 重启 → 分屏与头条恢复；
  8. 模拟旧宿主（不声明 split）→ 「分屏打开」隐藏、卡片退回单开网页。
- 暗 / 亮主题各一组截图。

## 不做的事
- 不新做全屏视图，不改现有「分屏」视图模式。
- 不新增面板之外调插件工具的通道。
- 不做插件面板的英文（宿主语言下发是单独的事）。
- 不在网页里自动填表、自动发帖（插件「由你本人点发布」的原则不变）。
