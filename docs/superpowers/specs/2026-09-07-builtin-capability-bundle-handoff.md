- 当前 bizone-mcp.mjs 是外部画板的启动包装器：macOS 尝试启动 /Applications/笔纵画板.app，再 import 画板包内 mcpServer.js；跨平台路径发现与恢复不能据此视为已完成。把连接器随包分发，不等于把画板应用、模型服务和登录凭证也随包提供。

## 推荐落点

用户看到一个随软件内置的“Eas-Term 扩展能力”插件；内部保留独立模块：工作台工具、笔纵画板连接器、使用指引与运行时状态。界面允许分别开关，保留用户已有禁用选择。

复用现有 Eas 插件宿主，将其扩展为支持内置基础能力和会话级能力装配。不要让新内置包占用或替换现有“用户选择的一个业务插件”位置；会话组合应为“启用的基础能力 + 用户选中的业务插件”，仍不默认加载全部第三方插件。

统一包是产品与分发单位，不要求三个 CLI 原生识别同一份 plugin.json。现有 Eas 插件清单与 Codex/Claude 原生插件清单并不相同：由宿主读取一份规范化能力定义，再分别编译成三端实际支持的配置。不得仅把文件移到 plugins/ 就宣布兼容。

建议链路：随包能力定义 → 宿主能力注册表 → 当前会话能力清单 → 三端适配器 → 同一个受控网关/插件宿主 → 实际执行体。

## 六块工作

1. **查根因和补诊断。** 对照运行包版本、CLI 版本、基础 MCP 配置来源、opt-out、角色过滤、spawn 环境的存在性、initialize/tools/list/首次调用结果。只记凭证是否存在和错误类别，不打印 token。将未安装、禁用、等待服务、握手失败、零工具、已就绪分开表示，不能把空工具当成健康成功。
2. **统一会话装配。** 三端使用同源能力清单；新建、恢复、失败重启、切换 CLI 均走同一装配入口。覆盖 AI 对话与 PTY 两类入口，分别验收。配置采用会话独立快照或等价的无竞态传递，避免共用文件被别的会话覆盖。Codex 同样显式获得启用的基础能力，不靠碰巧存在的全局配置。具体参数以随包 CLI 实测为准。
3. **宿主管理生命周期。** 等待服务真正就绪后握手；断线、应用重启、端口或 token 更新由受控连接管理器处理。支持工具刷新才刷新；不支持时在安全轮次边界重建连接或恢复会话，保存历史和待发消息，不打断正在执行的工具。不能靠固定 token、放开鉴权或跨实例猜测凭证来实现“免重连”。
4. **笔纵连接器模块化。** 优先复用画板正式工具 schema 和协议；宿主共享后端连接，避免每个会话重复维护重量进程。工具目录可轻量可见、生成后端按需启动。若采用 schema 缓存，必须带版本、校验兼容性和刷新规则。未装画板/未登录时显示具体状态，不虚报可生成。保留先报价再确认的生成流程。提交超时后的任务先查询认领，绝不自动重发付费生成。
5. **提示词程序一并改。** 插件内维护唯一说明源：短触发规则、按需读取的详细文档、实际能力状态。将包版本/功能启用、依赖可用、会话工具可见三个层次区分开；不因 SKILL.md 存在就宣称工具已可用。仅在 Eas-Term 管理的会话注入与工具状态一致的规则，追加合并现有角色/项目指引，不覆盖。详细正文不塞满每轮系统提示；动态状态变化用短更新表达。AGENTS.md/CLAUDE.md 的用户正文始终保留。
6. **分发、迁移和回退。** 内置插件及其说明随安装包版本化，支持中文空格路径、Dock 启动缺 Node/PATH、Mac/Windows 资源定位。迁移旧配置时只处理有可靠归属证据的托管段，备份、幂等、可恢复，保留第三方配置及用户禁用。先验证新链路，再移除重复旧注册/提示词，避免双加载。不要顺手重做提交钩子、statusline、知识库或审批机制；它们虽同属注入面，生命周期各自独立。

## 必须保留的边界

- 画布操作绑定发起会话的项目/Frame；多窗口、多项目并行时不串位置。既有路径白名单、密钥柜边界、角色限制和用户确认规则继续生效。
- 当前 pluginProtocol.ts 的普通插件 canvas 透传白名单很窄；如基础能力需要完整工作台工具，应设计可信内置服务绑定，不能扩大所有普通插件权限或给它们网关 token。
- 保持一个插件一个宿主管理进程的现有语义；Eas 工作台能力可直接绑定已有网关执行体，避免“插件代理自己”产生循环。
- 恢复连接不等于恢复执行：读取可安全重试；任何可能已执行的写操作需按请求 ID/任务 ID 核对，付费生成尤其不能盲重试。
- 在 Eas-Term 外启动的 CLI 不因安装过本软件就自动取得画布、知识库或凭证访问权。

## 验收定义

Claude Code、Codex、omp 分别跑相同用例，保存真实工具调用证据；不要以模型回答“我有这个工具”或参数字符串测试替代接入验证。

- 干净用户环境安装正式包：不用编辑 CLI 全局配置，新会话能列出基础工具，把同一张 PNG 打开到正确 Frame。
- 业务插件对话仍有基础画布工具；普通对话、恢复历史、切换 CLI 结果一致。两个项目同时操作不串 Frame/插件/配置。
- 重启 Eas-Term 或笔纵、模拟端口/token 变化：状态准确，恢复路径自动完成或明确显示正在恢复，无需用户输入 /mcp；历史不丢、正在进行的操作不重复。
- 画板未安装、未登录、服务故障、用户禁用：指引与工具状态一致，错误说明具体；不自动恢复用户主动禁用的模块。
- 生成请求提交后断线：恢复能查到原任务，不产生第二笔扣费；自动化测试用模拟服务，实服务付费验证另按报价确认。
- 升级、重复启动和回退：无重复工具/提示词，用户自定义规则、其它 MCP、角色与权限保持有效。
- 打包版在 Dock/精简 PATH、中文空格目录以及 Mac/Windows 实测；不只用开发环境通过替代正式包验收。
