# Codex 路由重试修复

## 已定位
正式应用0.4.114，本机CLI0.153.4。bridge最多5次是上限，不是每次必走5次。account/read必须返回chatgpt且workspaceRouting非空，但本机生成的标准GetAccountResponse schema不含workspaceRouting；预检可两次失败后在paid提交计数仍为0时结束。另现有恢复依赖thread/fork，与手动发送的新进程+thread/resume不同。当前日志没有阻断门细分，不能仅凭0次文案确认用户当次具体门。

## 实施
1. 先补协议回归复现缺workspaceRouting导致0次；恢复协调器最多5次，复用原会话、原消息、模型和沙箱，不用account/read/fork作为前置条件。
2. CLI生命周期仍由launcher独占：旧所属进程退出后才启动新进程；取消/父进程断开禁止新启。bridge单次尝试只在已确认terminal failed、ACK已知、无输出/工具/计费、无活跃goal/turn时发恢复请求。
3. 恢复中的启动阶段传输超时可以消费剩余预算继续；turn/start ACK不明、权限/认证/协议失败不盲重发。5次预算不得因换进程清零。
4. 单测覆盖五次、首次恢复启动失败、取消、迟到事件、无字段、同线程恢复和安全否决；构建并用真实隔离Electron+假CLI验证进度1/5至5/5、成功、耗尽和停止。
5. 不调用在线付费模型，不改用户配置，不替换正式应用；旧应用清理暂缓。
