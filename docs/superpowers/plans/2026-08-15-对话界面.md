# 通用 CLI 对话前端 · 子项目 B：对话界面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把子项目 A 的会话内核变成用户能看见、能用的对话界面：空态起会话、对话流、执行三行折叠、审批卡片、底部工具栏。

**Architecture:** 事件 → 视图的归约逻辑与「按能力决定渲染什么」的映射逻辑抽成**纯函数并单测**（照子项目 A 的经验：判定进纯函数，组件只渲染）。React 组件订阅 `window.api.agentChat.onEvent`，把 `ChatEvent[]` 喂给归约器，渲染产出的视图模型。**UI 里不允许出现按 CLI 名字的分支。**

**Tech Stack:** React 18 + TypeScript，`node --test` 跑纯逻辑，CDP + `Input.dispatchMouseEvent` 做真机验证。

**Spec:** `docs/superpowers/specs/2026-08-14-通用CLI对话前端-design.md` §五（**该节已按 A 的实际落地校正，读它不要读 §四的旧描述**）
**A 的裁定存档:** `docs/superpowers/rulings/2026-08-14-会话内核-裁定.md`
**接口实测:** `docs/cli-headless-接口实测.md`

## Global Constraints

- **测试命令** `npm test`（`node --test 'src/**/*.test.ts'`）。import 必须带 `.ts` 后缀。
- **UI 代码里不允许出现按 CLI 名字的分支**（`if (cli === 'claude')` 之类）。控件由 `capabilities` 声明驱动。**发现自己要按 CLI 名字分支，说明该读的能力字段没读。**
- **没有打字机效果。** `text.delta` **零生产者**（`--include-partial-messages` 已摘掉），模型文字整段到达。**不要写等待 delta 的逻辑，不要为它做加载态。**
- **不显示上下文百分比。** `Usage.contextRatio` **零处填写**（没有窗口上限作分母）。只显示 `inputTokens` / `outputTokens` / `cachedInputTokens` 与 `costUsd`（有则显示）。**宁可少显示，也不要显示一个看起来精确、实则猜的比例。**
- **`{ k:'error', fatal:false }` 必须在界面上显示出来**，不能只写 console。它唯一的用途是告诉用户「本次会话的工具调用不会弹审批卡片，将按默认权限直接执行」。这是硬验收项。
- **`capabilities.approval` 为空时，工具栏显示沙箱级别选择**（读 `sandboxLevels`）。判据是「approval 空不空」，**不是「是不是 Codex」**。
- **执行结果一律以事件为准**，绝不采信模型的文字陈述（实测：Write 被拒后模型说「已创建完成」而文件不存在）。
- 提交用精确的 `git add <文件>`，不要 `git add -A`。
- **验证 UI 必须用真实坐标事件**（`Input.dispatchMouseEvent`）。`el.click()` 绕过命中测试，测不出 `pointer-events: none` 那类问题 —— 本仓库的待办清单模块正是这么踩过的。

### Task 1: 事件归约器（纯逻辑，B 的核心）

**Files:**
- Create: `src/renderer/src/features/agentChat/reduce.ts`
- Test: `src/renderer/src/features/agentChat/reduce.test.ts`

**Interfaces:**
- Consumes: `ChatEvent`、`Usage`（`src/shared/agentChat.ts`）
- Produces:
  - `createChatReducer(): { push(e: ChatEvent): void; view(): ChatView }`
  - `interface ExecItem { execId: string; label: string; detail: string; state: 'running' | 'ok' | 'failed'; output?: string }`
  - `interface Turn { role: 'user' | 'assistant'; text: string; execs: ExecItem[] }`
  - `interface ChatView { turns: Turn[]; pending: ApprovalPending | null; notices: Notice[]; usage: Usage | null; costUsd?: number; busy: boolean }`
  - `interface ApprovalPending { approvalId: string; kind: 'exec' | 'patch' | 'tool'; title: string; detail: string; cwd: string }`
  - `interface Notice { id: string; text: string; fatal: boolean }`
  - `visibleExecs(execs: ExecItem[], expanded: boolean): ExecItem[]`

**背景**（决定这个归约器长什么样的三条硬约束）：

1. **失败项常驻可见**：`exec.done{ok:false}` 那条不能因为三行窗口滚出去而消失。理由是实测记录 —— 模型在 Write 被拒后会说「已创建完成」，失败被埋进小字里，用户看到的就是一句谎话加一片安静。
2. **审批升级**：`approval.request` 到达时它是最高优先级的东西（唯一会卡住任务、必须人动手的），不能塌进三行小字。
3. **没有打字机效果**：`text.delta` 零生产者，`text.done` 整段到达。

import { test } from 'node:test'
import assert from 'node:assert/strict'
import { createChatReducer, visibleExecs } from './reduce.ts'
import type { ChatEvent } from '../../../../shared/agentChat.ts'

/** 把一串事件喂进去，返回最终视图 */
function run(events: ChatEvent[]) {
  const r = createChatReducer()
  for (const e of events) r.push(e)
  return r.view()
}

const ready: ChatEvent = { k: 'session.ready', sessionId: 's1', model: 'sonnet', cwd: '/WORK/proj' }

test('模型文字整段到达，形成一个 assistant 轮次', () => {
  const v = run([ready, { k: 'text.done', text: '好的，我看一下' }])
  assert.equal(v.turns.length, 1)
  assert.equal(v.turns[0].role, 'assistant')
  assert.equal(v.turns[0].text, '好的，我看一下')
})

test('exec 挂在它之前那段文字下面', () => {
  const v = run([
    ready,
    { k: 'text.done', text: '我来改一下' },
    { k: 'exec.start', execId: 'e1', label: '编辑 a.ts', detail: '{}' },
    { k: 'exec.done', execId: 'e1', ok: true, output: 'done' }
  ])
  assert.equal(v.turns.length, 1)
  assert.equal(v.turns[0].execs.length, 1)
  assert.equal(v.turns[0].execs[0].state, 'ok')
})

test('exec.start 后未 done 的状态是 running', () => {
  const v = run([ready, { k: 'exec.start', execId: 'e1', label: '运行 npm test', detail: '{}' }])
  assert.equal(v.turns[0].execs[0].state, 'running')
  assert.equal(v.busy, true, '有未完成的执行项时应处于忙碌态')
})

test('exec.done{ok:false} 记为 failed 并带上输出', () => {
  const v = run([
    ready,
    { k: 'exec.start', execId: 'e1', label: '运行 ls', detail: '{}' },
    { k: 'exec.done', execId: 'e1', ok: false, output: 'No such file' }
  ])
  assert.equal(v.turns[0].execs[0].state, 'failed')
  assert.equal(v.turns[0].execs[0].output, 'No such file')
})

test('三行窗口：折叠时只留最近三条', () => {
  const execs = ['a', 'b', 'c', 'd', 'e'].map((id) => ({
    execId: id, label: 'x', detail: '', state: 'ok' as const
  }))
  const shown = visibleExecs(execs, false)
  assert.equal(shown.length, 3)
  assert.deepEqual(shown.map((e) => e.execId), ['c', 'd', 'e'])
})

test('三行窗口：失败项常驻，不会被滚出去', () => {
  // 这条是硬要求：实测过模型在操作被拒后仍会说「已创建完成」，
  // 失败被埋掉的话，用户看到的就是一句谎话加一片安静。
  const execs = [
    { execId: 'bad', label: 'x', detail: '', state: 'failed' as const, output: 'boom' },
    ...['b', 'c', 'd', 'e'].map((id) => ({ execId: id, label: 'x', detail: '', state: 'ok' as const }))
  ]
  const shown = visibleExecs(execs, false)
  assert.ok(shown.some((e) => e.execId === 'bad'), '失败项必须仍然可见')
})

test('三行窗口：展开时全部显示', () => {
  const execs = ['a', 'b', 'c', 'd', 'e'].map((id) => ({
    execId: id, label: 'x', detail: '', state: 'ok' as const
  }))
  assert.equal(visibleExecs(execs, true).length, 5)
})

test('approval.request 进 pending，resolved 后清空', () => {
  const r = createChatReducer()
  r.push(ready)
  r.push({ k: 'approval.request', approvalId: 'a1', kind: 'patch', title: '修改 a.ts', detail: '{}', cwd: '/WORK/proj' })

})

test('turn.done 带上 usage 与花费', () => {
  const v = run([
    ready,
    { k: 'turn.done', usage: { inputTokens: 10, outputTokens: 20, cachedInputTokens: 5 }, costUsd: 0.01 }
  ])
  assert.equal(v.usage?.outputTokens, 20)
  assert.equal(v.costUsd, 0.01)
  assert.equal(v.busy, false, 'turn.done 之后不再忙碌')

test('非致命 error 进 notices，不丢弃', () => {

- [ ] **Step 3: 实现归约器**

创建 `src/renderer/src/features/agentChat/reduce.ts`。要点：

- 有状态（累积轮次），所以是工厂函数返回 `{ push, view }`
- `text.done` → 新开一个 assistant 轮次
- `exec.start` → 挂到**当前最后一个** assistant 轮次；若还没有轮次，先造一个空文本的
- `exec.done` → 按 `execId` 找到那条改状态；找不到就忽略（不抛）
- `approval.request` → 写 `pending`；`approval.resolved` → 清空
- `error` → 追加进 `notices`（**任何情况都不丢弃**）
- `busy`：有 `state === 'running'` 的执行项，或收到过 `exec.start` 但还没 `turn.done`
- `visibleExecs(execs, expanded)`：展开时返回全部；折叠时返回**最近三条 ∪ 全部失败项**，保持原顺序
