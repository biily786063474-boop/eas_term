# 通用 CLI 对话前端 · 子项目 A：会话内核 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建一层不依赖 UI 的会话内核，把 Claude Code 与 Codex 两种完全不同的非交互协议，统一成同一套中间事件模型，并支撑逐次审批。

**Architecture:** 主进程侧新增 `src/main/agentChat/`。纯翻译逻辑（原生事件 → 中间事件）与纯判定逻辑（审批登记、会话状态机）独立成文件、全部单测；进程管理与 HTTP 端点作为薄胶水层。CLI 差异全部封在 adapter 内，对外只暴露 `ChatEvent` 与 `CliCapabilities`。

**Tech Stack:** TypeScript（Node 原生类型剥离，`node --test`）、Electron 主进程、既有 `src/main/mcpBridge.ts` 的 HTTP 通道。

**Spec:** `docs/superpowers/specs/2026-08-14-通用CLI对话前端-design.md`
**接口实测依据:** `docs/cli-headless-接口实测.md`（每条 CLI 行为判断都以它为准，**不要凭印象改**）

## Global Constraints

- **测试命令固定为** `npm test`（底层是 `node --test 'src/**/*.test.ts'`）。import 必须带 `.ts` 后缀（tsconfig 开了 `allowImportingTsExtensions`）。
- **中间事件模型里不允许出现任何 CLI 特有概念**：不能有 `hookEventName`、`thread_id`、`tool_use_id` 这类只有一边存在的字段。它们只能出现在 adapter 内部。
- **本子项目不写任何 UI 代码**，不碰 `src/renderer/`。
- **执行结果一律以事件为准**，绝不采信模型的文字陈述（实测：Write 被拒后模型说「已创建完成」而文件不存在）。
- **Claude 的 `--permission-mode` 一律用默认，绝不能传 `manual`**（实测它是直接拒绝而非等待审批）。
- **绝不能给 Claude 传 `--bare`**（实测会跳过认证，返回 `Not logged in`）。
- 空闲回收阈值 **15 分钟**，作为一个常量、一处定义。
- 提交用精确的 `git add <文件>`，不要 `git add -A`。
- 测试夹具在 `src/main/agentChat/__fixtures__/`，已脱敏（路径为 `/WORK/proj`、`/Users/USER`），**不要重新生成，直接读**。

```ts
// 通用 AI CLI 对话前端的中间事件模型。
// **这里不允许出现任何 CLI 特有的概念** —— 不能有 hookEventName / thread_id /
// tool_use_id 这类只有一边存在的字段。它们只属于 adapter 内部。
// 判据很简单：加第三个 CLI 时，这个文件不该需要改。

export interface Usage {
  inputTokens: number
  outputTokens: number
  cachedInputTokens?: number
  /** 上下文占用比例 0~1。**算法未定**（result 事件里没有窗口上限，见 spec §九 第 4 条）——
   *  拿到确定算法之前 adapter 一律不填这个字段，UI 只显示累计 token 数。
   *  宁可少显示，也不要显示一个看起来精确、实则猜的比例。 */
  contextRatio?: number
}

export type ChatEvent =
  | { k: 'session.ready'; sessionId: string; model: string; cwd: string }
  | { k: 'text.delta'; text: string }
  | { k: 'text.done'; text: string }
  | { k: 'thinking'; tokens: number }
  | { k: 'exec.start'; execId: string; label: string; detail: string }
  | { k: 'exec.done'; execId: string; ok: boolean; output: string }
  | {
      k: 'approval.request'
      approvalId: string
      kind: 'exec' | 'patch' | 'tool'
      title: string
      detail: string
      cwd: string
    }
  | { k: 'approval.resolved'; approvalId: string; decision: 'allow' | 'deny' }
  | { k: 'turn.done'; usage: Usage; costUsd?: number }
  | { k: 'error'; message: string; fatal: boolean }

export interface CliCapabilities {
  models?: { id: string; label: string }[]
  effortLevels?: { id: string; label: string }[]
  compact?: 'slash' | 'native' | false
  contextUsage: boolean
  /** 空数组 = 这个 CLI 做不了逐次审批，UI 退回显示沙箱级别选择 */
  approval: ('exec' | 'patch' | 'tool')[]
}

export interface StartOpts {
  cwd: string
  model?: string
  effort?: string
  resumeId?: string
}

export interface CliAdapter {
  id: string
  displayName: string
  capabilities: CliCapabilities
  detect(): Promise<boolean>
  /** 拼装启动这个 CLI 的命令行。进程由 session.ts 统一 spawn */
  buildArgs(opts: StartOpts): { bin: string; args: string[] }
}
```

创建 `src/main/agentChat/claudeEvents.ts`。要点：

- 有状态（节流计时、execId 配对），所以是工厂函数返回 `{ push }`，不是裸函数
- `push` 收一行，返回 0~N 个中间事件；**任何解析失败都返回空数组，绝不抛**
- `system:init` → `session.ready`
- `assistant` 的 `content`：`text` block → `text.done`；`thinking` block 忽略（thinking 的量走 `system:thinking_tokens`）；`tool_use` → `exec.start`，用 `b.id` 作 `execId`

- `system:hook_started` / `hook_response`：**先判 `hook_event === 'PreToolUse'`，否则丢弃**；
  `hook_response` 解析 `output` 里的 `permissionDecision` → `approval.resolved`
- `system:thinking_tokens`：按 `thinkingThrottleMs`（默认 200）节流后产出 `thinking`
- `result` → `turn.done`，`usage` 从 `j.usage` 映射，`costUsd` 取 `total_cost_usd`；**不要填 `contextRatio`**
- `label` 的拼法：`Write` → `编辑 <basename(file_path)>`；`Bash` → `运行 <command 前 40 字>`；
  `Read` → `读取 <basename>`；其余 → `工具名`。`detail` 放 `JSON.stringify(input)`

### Task 3: 审批登记表（hook 路单独驱动）

**Files:**
- Create: `src/main/agentChat/approvalRegistry.ts`
- Test: `src/main/agentChat/approvalRegistry.test.ts`

**Interfaces:**
- Consumes: `ChatEvent`（`src/shared/agentChat.ts`）
- Produces:
  - `createApprovalRegistry(): { fromHook(p: HookPayload): ChatEvent[]; resolve(approvalId: string, decision: 'allow' | 'deny'): ChatEvent[]; pendingCount(): number }`
  - `interface HookPayload { session_id: string; cwd: string; tool_name: string; tool_input: unknown; tool_use_id: string }`

**背景（这一条推翻了本计划最初的设计，2026-08-14 实测证伪）**：

原设计假设审批信息「分两路到达」、要按 `tool_use_id` 缝合。**实测证明缝不了**：

```
hook 路 payload：session_id, transcript_path, cwd, prompt_id,
                permission_mode, hook_event_name, tool_name,
                tool_input, tool_use_id        ← 有 tool_use_id
流里 hook 事件： hook_id, hook_name, hook_event  ← 只有 hook_id
```

**两路没有共同的关联键。** 所以：

- `approval.request` **只从 hook payload 产生**，`approvalId` 取 `tool_use_id`
- `approval.resolved` 在**我们自己回传决定时**产生（我们知道回了什么，不需要从流里读）
- 流里的 PreToolUse hook 事件**不产出任何中间事件**，与 SessionStart 噪音同等丢弃

这一层因此不是「缝合器」，而是一张**待处理审批的登记表**。

#!/usr/bin/env node
// Claude Code 的 PreToolUse hook：把这次工具调用交给 Eas-Term 弹卡片问人，阻塞等回答。
//
// 这个脚本是**外部进程**，Claude Code 会等它退出才继续 —— 这正是审批卡片成立的前提
// （实测阻塞 4 秒后返回 allow，文件真的被创建）。
// 端口与令牌由 Eas-Term 起会话时经 env 注入，与既有 MCP 那条通道同源。
//
// **兜底一律是拒绝**：拿不到端口、请求失败、超时，全都 deny。
// 前端崩了或用户没看见时默默放行一次写文件/跑命令，是这里最不能犯的错。
import { hookResponseBody } from './responseBody.mjs'

const deny = (why) => {
  process.stdout.write(hookResponseBody('deny', why))
  process.exit(0)
}

let raw = ''
for await (const chunk of process.stdin) raw += chunk

const port = process.env.EAS_TERM_PORT
const token = process.env.EAS_TERM_TOKEN
if (!port || !token) deny('Eas-Term 没能确认这次操作（拿不到本机通道）')

let payload
try {
  payload = JSON.parse(raw)
} catch {
  deny('Eas-Term 没能确认这次操作（hook 输入解析失败）')
}

try {
  const res = await fetch(`http://127.0.0.1:${port}/agent-approval/request`, {
    method: 'POST',
    headers: { 'content-type': 'application/json', 'x-eas-token': token },
    body: JSON.stringify(payload)
  })
  if (!res.ok) deny(`Eas-Term 没能确认这次操作（HTTP ${res.status}）`)
  const j = await res.json()
  process.stdout.write(hookResponseBody(j.decision === 'allow' ? 'allow' : 'deny', j.reason ?? ''))
} catch (e) {
  deny('Eas-Term 没能确认这次操作（' + (e?.message ?? '请求失败') + '）')
}

- [ ] **Step 1: 实现进程管理**

`session.ts` 只做调度，**不写任何判定逻辑** —— 判定全在前面几个纯函数里。骨架：

```ts
// 会话进程管理。这一层是胶水：spawn / 喂行 / 推事件 / 定时回收。
// 「什么时候该回收」「该直接发还是重启 resume」「审批两路怎么缝」
// 全部由 sessionState.ts 与 approvalRegistry.ts 的纯函数回答 —— 那些才测得了。
// **任何 if 判断如果需要写测试，就说明它放错地方了，应该挪回纯函数那边。**
import { spawn, type ChildProcess } from 'child_process'
import { getAdapter } from './adapters/index.ts'
import { createClaudeTranslator } from './claudeEvents.ts'
import { createCodexTranslator } from './codexEvents.ts'
import { createApprovalRegistry } from './approvalRegistry.ts'
import { IDLE_TIMEOUT_MS, shouldReap, planSend, applyParamChange, type SessionRecord } from './sessionState.ts'
import type { ChatEvent } from '../../shared/agentChat.ts'

interface Live {
  rec: SessionRecord
  proc?: ChildProcess
  translator: { push(line: string): ChatEvent[] }
  approvals: ReturnType<typeof createApprovalRegistry>
  stdoutBuf: string
}

const sessions = new Map<string, Live>()

/** 按行切分喂给 translator —— stdout 的 chunk 边界不等于行边界，
 *  不缓冲的话会把一行 JSON 劈成两半，解析必然失败 */
function feed(live: Live, chunk: string, emit: (e: ChatEvent) => void): void {
  live.stdoutBuf += chunk
  const lines = live.stdoutBuf.split('\n')
  live.stdoutBuf = lines.pop() ?? ''
  for (const l of lines) {
    // 审批不经过这里——它由 hook 路单独驱动（见 Task 3 背景，实测两路无共同关联键）
    for (const e of live.translator.push(l)) emit(e)
  }
}

/** 定时回收。判据来自 shouldReap，这里只负责杀进程与标记 */
setInterval(() => {
  const now = Date.now()
  for (const live of sessions.values()) {
    if (!shouldReap(live.rec, now)) continue
    live.proc?.kill()
    live.proc = undefined
    live.rec = { ...live.rec, alive: false } // resumeId 保留，下次发送时接上
  }
}, 60_000)
```

其余部分（`start` / `send` / `stop` / `resolveApproval`）照同样的形状写：
`send` 先问 `planSend`，`action === 'restart'` 就先 spawn 新进程带上 `--resume` 再写 stdin。

**注意 Codex 的 translator 与 Claude 不同**，按 `rec.cli` 从 `getAdapter` 拿 id 决定用哪个 ——
这是唯一允许按 CLI 分支的地方（选 translator），**不允许在这里写任何 CLI 特有的行为差异**。
