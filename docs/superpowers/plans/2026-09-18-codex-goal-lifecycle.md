# Codex 原生长任务生命周期修复计划

**目标：** 保留 Codex 原生 goal 的自动续轮，不在首轮结束关闭服务，不注入“继续”或自建付费轮询。
**范围：** Eas-Term 托管 AI 对话 Codex 路径；终端、Claude、OMP 不改变。
**工作区：** /tmp/eas-timeline-integrate；fix/codex-goal-lifecycle-20260918，基于 88ae4a8。

## 根因与评审
- 原始 rollout 的 active goal 下一轮被启动后约 50–160ms 中断；0.153.4 exec 首轮完成后 unsubscribe/shutdown，且过滤初始 turnId。
- 完整性：采用 app-server 原生线程与目标通知，不以文字“完成了”判断。
- 安全：保留现有配置合并、角色限制、MCP 装配、沙箱及所属进程关闭；不扩大权限，不自动恢复用户停止。
- 成本：仅本地 RPC 查看 goal 状态，不额外调用模型；沿用用户已授权的原生目标预算。
- 影响面：优先在已有受管 launcher 内增加任务生命周期桥接，外部维持现有 JSON 事件协议。每次用户提交保有原生 app-server，直到普通轮次完成/目标完成或暂停、用户停止、异常；多个 goal 原生轮次视为一次宿主任务，聚合 usage，避免中途宣布空闲。
- 替代：盲发继续不可取；直接改所有 CLI 公共会话架构风险更大。旧 exec 对原生目标不兼容，不能静默回退。
