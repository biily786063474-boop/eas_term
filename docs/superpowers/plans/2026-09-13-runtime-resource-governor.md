# Eas-Term 运行资源闸门与统一服务中心 · 实施计划

日期：2026-09-13｜状态：用户已确认，实施与验收进行中；整体未交付｜工作树：`.worktrees/voice-regression`

## 目标与范围

自动识别设备能力，普通模式以 80%、节能模式以 50% 为资源警戒上限；对 Eas-Term 发起的异步工作统一准入、排队和降载；所有由软件启动的服务可追踪项目归属、运行时长并安全停止。

**口径必须先确认：这里的 80%/50% 是整机 CPU 和内存分别计算的调度阈值，不是 CPU+内存相加，也不是单个进程各占 80%。本方案能约束自己发起的新工作，不能保证其他软件、运行中不可抢占程序或瞬时峰值不令整机超线。不得把软闸门宣传成跨平台硬上限。** 如要求任何瞬间绝不越线，需先完成平台硬隔离可行性验证；不支持的平台必须显示限制，不能假装实现。

架构：主进程单例 ResourceGovernor（采样→策略→调度）+ OwnedServiceRegistry（归属→租约→生命周期），所有入口通过适配器接入，渲染层只读快照及发出受校验操作。
技术栈：现有 Electron/TypeScript/React、现有测试框架；系统原生能力通过窄适配层接入，不新增出站服务或上传遥测。

## 方案评审

| 方案 | 完成性 | 体验与风险 | 决策 |
|---|---|---|---|
| 只加资源仪表盘 | 看得见，不能阻止卡顿 | 成本低但不满足排队 | 不单独交付 |
| 统一服务登记 + 自适应准入/排队 + 安全降载 | 能控制可管理入口并解释等待 | 保留交互；仍存在不受控子任务和瞬时峰值 | 推荐主线 |
| 超线直接暂停/杀进程 | 表面下降快，不保证数据安全 | 容易中断写盘、持锁、远端副作用；可能伤及外部服务 | 禁止作为默认策略 |

成本评审：调度应为本地确定性代码，不让模型判定是否放行，不消耗额外模型 token；等待不轮询模型、不重新发送用户提示词；远端重复生成可能产生费用，绝不能自动重试结果未知任务。

## 1. 指标与策略（首版建议参数，压测后校准）

- 启动检测 OS/架构、逻辑核心数、物理内存、可用采样能力；GPU/统一内存、热状态、电源信息按平台能力标记，不做启动跑分。
- 整机 CPU：采样窗口内所有逻辑核心平均忙碌比例，范围 0–100%；应用 CPU 按相同分母归一化，包含可证明归属的子进程，不能直接加不同工具的原始百分比。
- 整机内存：平台适配定义的不可轻易回收占用/物理内存，同时保留 available、pressure、swap/compression 指标。明确缓存和压缩口径；应用进程 RSS 汇总仅是估计，共享页可能重复，不拿它当精确物理消耗。
- 判定使用整机压力；界面另列 Eas-Term 消耗与外部占用。任一受支持关键维度越线都触发闸门，不以低 CPU 抵消高内存。GPU 不可测时显示“不支持”，不能填 0 或宣称已限额。
- 正常采样建议 1 秒；空闲 3–5 秒；UI 最多 1 秒更新一次；取 5 秒平滑窗口，并保留原始尖峰触发紧急压力判断。
- 普通/节能进入阈值分别 80%/50%，连续 3 次采样超线进入拥塞；恢复线分别 70%/40%，连续 10 秒低于恢复线且压力解除才逐项放行。预估新增资源将越线时无需等待连续超线，直接排队。
- 系统报告严重内存压力、过热或 UI 心跳明显延迟时提前进入保护；保留主窗口、取消、审批、密钥授权、写盘、心跳的最低执行预算。保留预算是调度预留，不是 OS 硬隔离承诺。
- 未知成本任务首次单个试跑并学习峰值，不一次性放行一批；预测需加误差余量。可用余量=阈值容量−当前整机使用−已准入未兑现预留−安全余量，防并发抢闸。
- 模式：普通 / 节能；可选“跟随系统”，仅在支持的平台启用。用户手动选择优先且持久化。切到节能先停止新增、逐步降载，不杀掉正在保存的任务。
- 监测失效：显示未知、告警和保守低并发；不当成空闲全面放行。支持单任务用户确认运行，但不提供隐式全局绕闸门。

## 2. 排队与拥塞处理

任务状态：created → queued → admitted → running → completed/failed/cancelled；排队不是 running。记录 enqueue/start/end 时间及原因码。

- 三类资源：本地重计算任务、轻量/远端 I/O、受保护控制面；分别设并发池，共用整机闸门。云端生成算力不计入本机 CPU，但连接数、本地传输/解码/磁盘任务照常管理。
- 优先级：安全控制面 > 用户当前直接操作 > 当前项目工作 > 后台预览/索引/预取。项目轮转+老化，防一个项目占满，也防后台永远饿死。
- 递进处理：减后台并发 → 暂停派发 → 合并可丢弃刷新/取消未开始预取 → 回收无租约闲置服务 → 对支持安全检查点的任务协作暂停。不可暂停任务显示原因，不擅自 SIGSTOP 或重启。
- 超额正在运行任务只能协作限速/降优先级或让用户停止。降低优先级不等于 CPU 硬限额。阈值超出持续存在时明确显示外部压力或不可抢占原因。
- 队列必须有总量/项目上限与等待超时；容量不足提示，不无界积压。位置可能随优先级变化，不能承诺虚假倒计时。
- 取消排队任务保证没有实际执行；发起执行与取消竞争使用原子状态转换；运行失败/退出必释放额度；释放操作幂等。等待超时不等同执行超时。
- 嵌套 agent→tool→subprocess 使用 parentTaskId/resourceLease，避免重复计费和父任务占满槽位等待子任务的死锁；长期 agent 会话服务与一次 turn 的工作额度分离。
- MCP 调用等待必须兼容协议超时：短调用不无限挂住，能返回结构化 queued/jobId 的异步协议才排长队；不可更改的客户端使用有界等待后返回可解释错误，不伪造执行成功。
- 重载/崩溃恢复只恢复队列元数据，带副作用或结果未知任务标“需确认”，不自动重复提交。服务崩溃有限退避重启，用户主动停止则关闭本次自动重启意图。

## 3. 服务统一管理

服务记录建议字段：serviceId、kind、displayName、ownerProjectIds、frameId/nodeId/agentSessionId、parentServiceId、pid+processStartIdentity、launchSource、startedAt、state、stopCapability、leaseRefs、resourceEstimate、lastErrorCode。

运行时长用单调时钟，显示墙上启动时间；排队等待单独显示，不混为运行。项目使用稳定 ID，cwd 仅辅助展示；共享 MCP/LSP 显示多个项目，不强行归到第一个项目。

- 所有 spawn/fork/exec/PTY/Electron utility/webContents 启动路径逐项清点；登记先占位，成功后绑定进程身份，失败回滚。关闭路径与启动路径配对验证。
- 复用 `hostRegistry.ts` 现有共享 host 引用计数和延迟回收；统一注册表是观测/策略入口，不能另造冲突的第二套租约。
- 复用 `mcp/owned-launcher-control.mjs` 与现有 stopAgentProcess 的所有权控制；PID 复用前验证启动身份，禁止仅按进程名称杀进程。
- CLI 自己启动的 shell/后台服务：优先 launcher/进程组跟踪，能脱离的孙进程需平台归属机制验证；不能确认归属就只读标注“无法安全控制”。本机外部共用服务不得认领。
- 共享服务“关闭”弹窗列影响项目和活动任务：默认释放当前项目租约；只有清楚授权关闭全部且确有所有权才停止整项服务。核心主进程不展示可随意关闭按钮。
- 停止序列：校验身份及依赖 → 阻止新派发 → 协议优雅取消/退出 → 有界等待 → 对可管理自有进程提供二次确认强制停止。先保存可保存内容，停止失败给原因。
- CUA 外部共用服务遵守 `docs/verification/releases/computer-use-lifecycle.md`，未接通官方会话级释放前标外部/只读，禁止全局杀服务清理。
- 不记录 env、密钥、完整命令参数或对话正文；只存脱敏类别、归属、资源、状态和原因。重启不得仅凭旧 PID 恢复杀进程权限。

## 4. UI 交付要求（沿用项目设计系统）

入口：全局状态区“运行 6 · 等待 3”；点击打开“运行中心”抽屉，另有设置→性能。复用已有抽屉、tabs、CTA 和 tooltip，不新增第三套弹窗样式。

- 顶部：普通/节能模式；整机 CPU / 内存，与 Eas-Term 自身分开；明确当前阈值与监测能力。
- 标签页：运行服务 / 等待队列 / 最近结束。默认当前项目，可切所有项目。
- 服务行：名称、类型、项目归属、运行时长、CPU/内存、状态、停止操作；共享/系统保护/只读有短标签；窄屏次要指标收进详情，名称和操作不挤成竖字。
- 队列行：任务、所属项目、等待时长、等待原因、优先级、取消；提示“内存达到 80%，等待资源释放”，外部程序导致则如实说明。
- 超线首次轻提示+状态变化，不持续弹窗打断；严重压力允许显眼警告，但取消/审批始终可用。
- 停止确认使用正常 CTA；清楚说明影响及未保存风险。点击抽屉外、Escape 返回；确认弹窗按现有安全确认规则。高低分辨率、分屏、亮暗模式均验收。

## 6. 验收清单（必须逐项有证据）

1. 设备信息自动识别且核心数归一化；CPU、内存、未知GPU口径明确。
2. 普通80/节能50分别触发队列；切换模式即生效并重启记住；恢复不抖动。
3. 外部程序造成高占用时 Eas-Term 不再加重负载，界面解释外部压力，不误杀、不假报已压至阈值以下。
4. 并发提交、嵌套工具、取消竞争不突破许可、不死锁、不重复执行；队列有界、可取消、公平。
5. 服务清单含每个可证明自有服务、项目/共享归属、正确时长；受保护/只读不可误操作。
6. 停止单项目共享服务不伤其他项目；停止全部明确影响；失败可见；用户停止后不自动拉起。
7. 会话/窗口/应用退出无已证明自有的孤儿进程；不可控外部服务如实列为未覆盖，不冒充完成。
8. 采样失效、内存压力、过热、唤醒、崩溃恢复下保持可操作，无丢稿、无副作用自动重放。
9. 构建、类型检查、单测、隔离真机 UI 验证通过；Windows/Linux 未实测必须标未验证。

## 7. 排期与发布边界

依赖顺序 P0→P1→P2→P3→P4→P5。建议分三里程碑：M1 可观测（P0/P1）、M2 软闸门闭环（P2/P3）、M3 用户可管理+完整验收（P4/P5）。M1 不宣称阈值已实现；M2 不宣称所有 CLI 内部工具均可精确排队；硬限制另立平台专项，由 P0 决定可行范围。
