画布组件协议

无限画布右侧抽屉「组件」分区里的每一项都是一个画布组件：用户从抽屉拖进画布的 Frame，就得到一个该组件的节点。本文定义组件的注册协议、渲染契约、拖拽落点规则，以及如何新增一个组件。目标：加组件 = 写一个 CanvasComponentDef 并注册，不改动任何其它文件。

01是什么

画布节点有三类来源，组件是第三类。

节点类型内容来源归属渲染
终端节点leafId 引用共享 leaf两视图同源（分屏也在）pane-layer（不断连）
文件预览节点pane 自带（code/image/web）画布独有装饰层（矢量缩放）
组件节点 ← 本文component（type 查注册表）画布独有装饰层（矢量缩放）

组件节点和文件预览节点是同一类——画布独有、不进分屏、渲染在装饰层（world）内随视口矢量缩放。区别只是内容来自「注册表里的组件」而非「某个文件」。

02数据模型

组件节点在 store/canvasSlice.ts 的 CanvasNode 上多一个 component 字段。

interface CanvasNode {
  id: string
  leafId?: string                              // 终端（共享）
  pane?: PaneState                            // 文件预览（画布独有）
  component?: { type: string; props?: Record<string, unknown> }  // 组件（画布独有）
  x: number; y: number; w: number; h: number       // 相对 Frame 局部坐标
}

component.type 是组件的 id（如 'git'），持久化时只存这个字符串 + 可选 props；组件的实现（图标、尺寸、渲染）全在注册表里按 type 查。所以 type 一旦发布就不要改名（否则旧画布里的节点失效）。

03组件协议 CanvasComponentDef

定义在 features/canvas/components/registry.tsx。

interface CanvasComponentDef {
  id: string                 // 唯一标识，存进 node.component.type，勿改名
  name: string               // 抽屉里显示的名称
  Icon: (p: { size?: number }) => JSX.Element   // 抽屉图标
  description?: string       // 一句话简介（hover 提示）
  defaultSize: { w: number; h: number }         // 拖入时默认节点尺寸
  needsProject?: boolean     // true → 必须落在绑定项目的 Frame，否则拒绝
  render: (ctx: CanvasComponentCtx) => JSX.Element  // 渲染节点 body
}

const CANVAS_COMPONENTS: CanvasComponentDef[] = [ gitComponent ]   // ← 在这里追加
const getCanvasComponent = (id) => CANVAS_COMPONENTS.find(c => c.id === id)

04渲染上下文 ctx 契约

组件的 render(ctx) 从所属 Frame 拿到运行所需的一切，不要自己去 store 找“当前项目”——画布是多项目并置的，ctx 才是唯一正确来源。

interface CanvasComponentCtx {
  nodeId: string
  frameId: string
  projectId: string | null   // 所属 Frame 绑定的项目；needsProject 组件保证非空
  cwd: string               // 项目工作目录（needsProject 组件的 cwd）
  props?: Record<string, unknown>   // 拖入时携带的额外参数
}
为什么给 ctx 而不让组件自取：同一个组件可能在画布上被拖入多个不同项目的 Frame（比如给两个项目各放一个版本管理）。每个实例必须绑定自己 Frame 的项目，靠 ctx.cwd 区分——组件内部若用全局“activeProject”会串项目。

05渲染与拖拽流程

渲染

CanvasStage 遍历 frame.nodes，n.component 的交给 CanvasComponentNode。后者按 type 查注册表 → 用 Frame 的 projectId/cwd 组出 ctx → 调 def.render(ctx) 塞进节点 body。外壳（头部/拖动/resize/删除）复用文件节点的 .cfile-* 样式与 moveNode/resizeNode/removeNode。

拖拽

CanvasDrawer 的「组件」分区遍历 CANVAS_COMPONENTS 渲染可拖项。手动拖拽（mousedown + ghost，非 HTML5）：落点 elementFromPoint 命中 .cframe → 换算 Frame 内局部坐标 → addComponentNode(frameId, type, x, y, w, h)。needsProject 组件落到无项目 Frame 会被拒绝（无操作）。

06如何新增一个组件

三步，全部发生在 registry.tsx 一个文件内。

1
写一个内容组件（或复用现成的）。它接受 props（一般是 cwd / projectId），渲染面板内容。版本管理直接复用了侧栏的 SidebarGit。
2
写 CanvasComponentDef：填 id / name / Icon / defaultSize，在 render(ctx) 里返回内容组件并把 ctx.cwd 传进去。需要项目就设 needsProject:true。
3
push 进 CANVAS_COMPONENTS。完。抽屉分区自动出现新项、可拖入、可渲染，无需改 CanvasStage / CanvasDrawer / store。 
// 例：加一个「待办清单」组件
const todoComponent: CanvasComponentDef = {
  id: 'todo',
  name: '待办清单',
  Icon: CheckIcon,
  defaultSize: { w: 280, h: 360 },
  render: (ctx) => <TodoPanel projectId={ctx.projectId} />
}
export const CANVAS_COMPONENTS = [ gitComponent, todoComponent ]

07首个组件：版本管理

复用侧栏「版本」面板 SidebarGit（Git 变更 / 暂存 / 提交 / 历史入口）。

const gitComponent: CanvasComponentDef = {
  id: 'git',
  name: '版本管理',
  Icon: GitBranchIcon,
  description: 'Git 变更 / 暂存 / 提交 / 历史',
  defaultSize: { w: 320, h: 440 },
  needsProject: true,
  render: (ctx) => <SidebarGit cwd={ctx.cwd} active />
}

拖「版本管理」到某项目的 Frame → 该 Frame 内出现一个 git 面板节点，操作的是该 Frame 绑定项目的仓库。

08约束与边界

组件节点是画布独有

不进分屏、不共享 leaf。适合无状态或自持状态的视图（git、待办、看板…）。真正的「活会话」（终端）不走组件，走 leafId 共享节点。

render 是纯展示，副作用走 ctx

组件内若要「在主区域打开 diff / 历史」这类动作，注意画布模式下它们会落到分屏。组件应尽量自包含；跨视图动作后续由协议扩展 ctx 提供回调，不要在组件里直接摸全局 activeTab。

id 稳定

id/type 是持久化键，发布后改名会让旧画布节点失效。要重命名走迁移，不要直接改。

Addendum · 2026-09-05

插件面板：唯一带运行时身份的组件

plugin-panel（features/plugins/PluginPanel.tsx）是注册表里唯一一个身份在运行时决定的组件：它的 node.component.props 记着 { pluginId, panelId }，渲染时按此向主进程要插件的 ui:// HTML，放进 sandbox="allow-scripts" 的 iframe（地址 eas-plugin://<panelSession>/）。

为什么不是「一个插件一个组件」：注册表是编译期数组，插件是运行时扫盘发现的，两者不能合并；而 component.type 一经发布不能改名，一个类型 + props 让老画布里的节点永远不受影响。入口在 Frame 双击菜单的「插件」tab（自家插件 cli==='eas' 且带 panels 的，主动作是「打开面板」，右侧小按钮才是「对话」）；从抽屉「组件」分区拖出来的是没有 props 的空壳，会提示去插件 tab 打开。

addComponentNode 为此多了可选的第 7 参 props；旧调用不传即原行为。协议细节见 docs/superpowers/specs/2026-09-05-插件面板宿主-design.md。
