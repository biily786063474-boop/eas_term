# @ 引用与斜杠命令 UI 稿

日期：2026-09-07。状态：第一版可交互设计稿，未修改应用业务代码，未实现真实端口接入。

入口：[本地 UI 稿](2026-09-07-chat-mentions.html)。已在 Eas-Term 的 terminal 项目区打开。

## 用户要求

- 现有聊天输入框 @ 与 / 无法使用；本轮先画 UI。
- @ 内容要完全对标 Codex，并额外添加「辞典」分类。
- 保留辞典词条先加载到聊天输入框候选中的使用方式。
- Codex / Claude / omp 三端通用。此三端解释已告知用户，未收到不同指示。

## 第一版设计

- 沿用现有输入框圆角、底部单行工具栏、中性色和辞典暖色图标。
- 分类：全部、辞典、文件、文件夹、技能、插件、应用、浏览器标签。辞典靠前，避免小窗口里藏到滚动区底部。
- 辞典分为已加入候选与全部辞典；支持中文、英文与关键词检索。词条详情包含摘要与插入引用入口。原型只放四条演示数据。
- 输入框上方保留备选词条。正文引用后标记「本次引用」，支持移除和发送内容预览。
- 保留 chips.ts 当前语义：有辞典引用时按正文位置展开使用的词条；没有辞典引用时附带全部备选词条，并在界面说明。未擅自修改既有行为。
- / 分为通用操作、当前端口命令与技能。通用操作由 Eas-Term 提供一致入口；原生命令需按端口、版本、headless 能力探测决定是否可执行。原型里的 model/effort/new/mention 是设计方案，不是已完成能力。
- 选择先填入，不直接发出消息；支持方向键、Enter/Tab、Escape，中文组合输入期间不拦截。输入标记按光标所在位置识别。
- 加载、空结果、失败和重试都有独立场景。应用实现时各来源需独立加载，单源失败不能挡住其他来源。原型场景切换仅演示状态。

## 必须保留的对标缺口

尚不能宣称「完全对标 Codex」。Computer Use 明确拒绝访问 com.openai.codex，未尝试绕过。向用户询问了桌面版还是 CLI 版，当前未收到回答，按桌面版先画。

需要目标 Codex 的 @ 菜单参考截图或明确版本来逐项核准：分类名称与顺序、全量候选来源、搜索和选中后的形态。当前分类是覆盖清单，不是已验证的原版菜单复刻。此限制已在 UI 稿与对话中明示。

官方文档仅支持相关能力的事实，不足以确定当前菜单布局：

- [Commands](https://learn.chatgpt.com/docs/reference/commands)：支持在新对话提示中放插件 mention，打开不会自动发送。
- [Skills & Plugins](https://learn.chatgpt.com/docs/skills-and-plugins)：Codex 技能支持 `$` 引用。共用界面里的 @ 技能必须保留实际技能身份并转换到各端支持的机制，不能盲目给所有 CLI 发送 `/skill-name`。
- [Developer commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli)：CLI 的原生命令不代表本项目 headless 传输可执行。
