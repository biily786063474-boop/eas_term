灵动岛动效 + 终端输入框

下面每一块都能真的动——鼠标移上去、点按钮，看到的就是实现后的样子。 动效参数从 139 个组件的动效库里取的手感，但实现全部是纯 CSS：灵动岛是个常驻小窗口， 为几行动效引 framer-motion 或 gsap 不划算。

日期 2026-08-03 基线 v0.4.0 参考库 ReactBits ×139 新增依赖 0

VERDICT

结论：借参数，不借组件

动效库里 95/139 个组件要 Tailwind，8 个要 React 19，而灵动岛既没 Tailwind、 跑的是 React 18、还是个常年挂在屏幕顶上的小窗口。直接搬组件是给自己找麻烦。

做法

从库里取 手感参数（缓动曲线、时长、扫光角度），用纯 CSS 复刻。 新增依赖 0，动效全部走 GPU 合成层（transform/opacity）， 不触发布局重排——这对一个常驻窗口很重要。

DEMO 1

窗口出现 / 收回

灵动岛是"从屏幕上沿垂下来"的，不是淡入。所以动效带 Y 轴位移 + 轻微的纵向压缩（scaleY .72 → 1），像一块东西被放下来。 收回比出现快（160 vs 220ms）——离开该干脆，出现该稳。

CONSTRAINT

技术约束：动画和窗口尺寸会打架

这一节是这份原型里唯一"不做就会出事"的部分。

问题

灵动岛的窗口大小是这么定的：渲染层用 ResizeObserver 量自己有多大 → IPC 报给主进程 → win.setBounds()。

如果展开动画是容器高度的 CSS 过渡，那么动画的每一帧都会触发一次 ResizeObserver → 一次 IPC → 一次 setBounds。260ms 的动画 ≈ 16 次跨进程往返 + 16 次窗口重设。 结果是窗口边缘一格一格地跳，比不做动画还难看。

// ✗ 会打架：高度自己动 → 每帧都上报
.isl-shell { transition: height 260ms; }

// ✓ 采用：容器瞬间到位，内容做动画
// 1) 展开时 React 先渲染出完整内容 → ResizeObserver 报一次终值 → 窗口一步到位
// 2) 内容自己淡入 + 上移 6px，动画期间尺寸不变，不再触发上报
.isl-body { animation: isl-body-in 260ms cubic-bezier(.22,1,.36,1) both; }
@keyframes isl-body-in {
  from { opacity: 0; transform: translateY(-6px); }
  to   { opacity: 1; transform: translateY(0);    }
}

代价：窗口边框是瞬变的，只有内容柔和进入。
实际观感很好——因为黑底窗口在黑色刘海旁边，边框变化本来就看不太出来，
眼睛跟的是内容。上面 DEMO 2 就是这个方案，你可以自己判断。

出现 / 收回不受这个约束

那一档动的是 transform（位移 + 缩放），不改变布局尺寸， ResizeObserver 不会触发。所以出现/收回可以放心做完整动画——上面 DEMO 1 就是。

无障碍：跟随系统的「减弱动态效果」

macOS 辅助功能里开了「减弱动态效果」的话， 所有动效应该退化成瞬变。这一条会一起实现：

@media (prefers-reduced-motion: reduce) {
  .isl, .isl-body, .lbl, .lbl::before, .lbl::after {
    animation: none !important;
    transition: none !important;
  }
}
