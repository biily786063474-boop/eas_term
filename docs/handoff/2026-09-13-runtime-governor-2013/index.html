项目背景和用户原始目标

Eas-Term 是当前仓库；不是笔纵画板 taptv 的源码仓库。

Eas-Term 是 Electron / TypeScript / React 桌面工作台：无限画布按项目组织 Frame，承载终端、AI 对话、浏览器、文件、代码地图、辞典、知识库等模块；可管理 CLI 会话和 MCP 插件。用户是独立开发者，中文沟通，多项目/多会话并行工作，不能影响正在跑的生产任务。

本次大任务是 运行资源闸门与统一服务中心：自动识别设备能力；普通模式 80%、节能模式 50%；对软件发起的工作统一准入/排队；服务可追溯归属、时长并安全停止。工作必须由确定性本地代码完成，不让模型判是否放行，不额外消耗模型 token。

80%/50% 分别是整机 CPU 与内存的软调度阈值，不是两者相加、不是单进程配额，也不是任何瞬间绝不越线的硬上限。外部程序、已在运行的不可抢占工作和估算误差均可能超线。未知指标不能伪装为 0；成本估计不是实测峰值。

队列等待不能自动重试带副作用或结果未知任务。停止只能操作软件确有所有权的实例，禁止按进程名全局杀服务。共享服务不能因一个项目的关闭伤及其他项目。
