VERDICT

结论先说

两个独立缺陷叠在一起：一个让消息发不出去，另一个让你连停都停不掉。

真根因

ensureAndSend 把消息推进队列之后少调了一次 pump()。 于是「会话活着、且刚好空闲」时发的消息，永远躺在队列里没人取。 而这正是「它答完话之后我再问一句」这个最普通的用法。

CORRECTION

一次误判，以及它是怎么来的

第一轮排查我给出的结论是错的。记在这里，因为出错的方式会重演。

被推翻的结论

「omp 进程死了，而按停止时 interrupt() 是空操作。」

依据是 app 日志最后一行 [omp] omp 进程已结束，时间戳恰好比用户截图早 4 分钟。 看起来严丝合缝。

错在哪

那行日志记的是另一个进程 —— 一次 2 秒的冒烟测试。 翻开它对应的会话记录，里面写着「请只回复两个字：你好」， 是我们自己那句「试一句」。真正的会话进程当时活得好好的。

教训

一台机器上同时跑着好几个 omp 进程（会话 / 冒烟 / 模型探测各起各的）。 按时间戳认进程一定会认错 —— 必须用 pid 或会话 id 对上， 再看那个进程自己的会话记录里到底有什么。

ROOT CAUSE

三条投递路径，只有一条是坏的

pump() 负责从队列取出下一条消息发给 omp。它只有两个调用点，而投递有三种情形。 

// 修复前
async function ensureAndSend(message) {
  queue.push(message)
  if (phase !== 'dead') return        // ← 排完队直接走人
  …开进程、握手…
  pump()                            // ← 只有「会话已死」这条路才泵
}

// pump 的另一个调用点在 prompt() 的 finally —— 一轮结束时泵下一条
发消息时的状态典型场景谁来泵结果
prompting（上一轮在跑） 边看它干活边打下一句 prompt() 的 finally 通
dead（会话已回收） 隔了很久再回来说话 ensureAndSend 末尾 通
ready（活着且空闲） 它答完话之后我再问一句 没有人 消息永远躺在队列里

从外面看，这个状态和「模型正在慢慢想」完全一样：消息在气泡里、转圈在转、没有任何报错。 而 omp 那侧根本不知道你说过话。

FIXES

修了两处

一处让消息真的发出去，一处让「停止」在任何状态下都能把界面收干净。

① 空闲时也要泵一次 67f7e13

if (phase !== 'dead') {
  pump()        // 无条件调是安全的：pump 自己守着
  return        // phase !== 'ready' || queue.length === 0
}

② 停止要能在任何状态收场 ee3c1f8

interrupt() 原来在「没有在飞的轮次」时直接 return， 而且没有返回值告诉调用方它什么都没做。 改成返回布尔：没接手时，由上层自己补一条 turn.done。

为什么必须是 turn.done

界面判断「还在忙」有三支判据，能一次放倒三支的只有 turn.done； error 就算标成 fatal 也只放倒一支。 这条结论 cc/codex 那支的注释里早就写着 —— ACP 这支漏了同一课。

验证

  • 新增断言：空闲时发出的消息必须立刻送出（修复前红）
  • 新增断言：上一轮在跑时仍按原样排队、结束时泵出（修复前就绿，钉住别改坏）
  • 新增断言：进程已死时 interrupt() 返回 false；正常在跑时返回 true
  • transport 28 条全绿 · 全仓 1728 条全绿 · 打包前真 ACP 握手通过

LESSONS

三条留给下次的

这次排障里，最贵的不是修复本身，是走错的那一段。

omp 自己有日志，先去读它

omp/logs/ 与 omp/agent/sessions/ 里有完整的进程日志和会话记录。 这次的决定性证据（「整段会话只有 1 条用户消息」）只有那里有 —— app 侧的日志根本看不出来。

按时间戳认进程一定会认错

会话、冒烟测试、模型探测各起各的进程，同一分钟里可能有四个。 要用 pid 或会话 id 对上，再看那个进程自己的记录。

「界面转圈」不等于「后端在忙」

乐观插入让消息立刻显示在界面上。所以「消息在气泡里 + 转圈在转」 既可能是模型在想，也可能是那条消息压根没离开过这台电脑。 两者从外面完全一样，只能靠对面的记录区分。

同类分支要一起改

「停止必须推 turn.done」在 cc/codex 那支修过、注释也写了， 但 ACP 这支是后加的，没跟上。 加新分支时要回头看老分支的注释里有没有已经付过学费的结论。
