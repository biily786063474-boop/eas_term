灵动岛提示音

三组音色候选，每组两种类型（任务完成 / 等待审批）。 戴上耳机或把音量调到平时的水平再听——提示音的好坏全在细节上， 外放小音量听不出泛音和衰减的差别。

日期 2026-08-03 实现 Web Audio 合成 音频文件 0 个 包体增加 0 KB

APPROACH

为什么不用音频文件
做法

用 Web Audio 现场合成——振荡器叠泛音、指数包络、一点点程序生成的混响。 每个音效就是十几行代码，不是资源文件。

  • 包体不增加。一个像样的 wav 提示音 30–80KB，三组六个就是小半兆，而灵动岛是个常驻小窗口
  • 参数可调。嫌高了改一个数字，不用回去重新做音频
  • "清脆"正是合成音的强项——纯正弦 + 快速指数衰减，比大多数采样都干净
  • 不依赖任何外部素材，也不涉及任何生成模型

让它"高级"的四个细节

细节做法不这么做会怎样
纯正弦，不用方波type: 'sine'方波/锯齿波富含奇次谐波，听感廉价刺耳，像老式电子表
叠非整数倍泛音钟用 2.756×、玻璃用 3.0/5.2×只有基频=电话忙音；整数倍泛音=风琴。金属和玻璃的泛音本来就不是整数倍
指数衰减，不是线性exponentialRampToValueAtTime线性衰减尾巴发"木"，不像真实物体的振动
一点点混响程序生成 0.9s 衰减噪声做 IR干音贴着耳朵响，像手机通知；有空间感才"贵"

LISTEN

三组候选

每组的两个音效互相有关系但能分辨——同一套音色规则，靠音程和节奏区分类型。 这比"两个毫不相干的声音"更像一个产品。

点任意按钮开始（浏览器要求用户手势后才能出声）

A · 玻璃 明亮

纯正弦 + 3.0/5.2 倍泛音 · 中长衰减 · 空间感强

完成是上行大三度，落定感强；审批是大三和弦琶音， 三个音让它更"要人注意"，但和弦本身是协和的，不制造焦虑。

B · 钟 金属

真实钟的泛音比 2.756/5.404 · 长衰减 · 单点

最克制的一组，完成只有一声。 审批用 F♯ 双击——F♯ 相对基调有轻微悬而未决感，双击是"敲门"的节奏。

C · 木琴 干净

基频 + 4 倍泛音 · 极短衰减 · 无拖尾

最短促的一组，响完就没了。 适合一天要响很多次的场景——衰减长的声音听多了会累。

STRESS

连发测试：三个任务陆续完成

这是最能听出问题的测试。单次听着好听的音效，连响三次可能就烦了—— 尾音重叠会糊成一片。下面按 1.2 秒间隔连响三次。

听尾音会不会互相打架
我的判断

B 组（钟）单次最好听，但 0.9s 的尾音在连发时会明显重叠。 如果你多任务并行是常态，C 组（木琴）更耐听；如果一天就响几次，B 组质感最好。 A 组是折中。不管选哪组，我都会加防连发（见下一节）。

POLICY

什么时候该响

音效比视觉更容易惹人烦——看得见的东西可以不看，听得见的躲不掉。所以规则要严。

场景建议理由
主窗口不在前台，任务完成响这正是提示音存在的意义——你在别处，需要被叫回来
主窗口在前台，任务完成待你定你就看着屏幕，画布上已有呼吸点和铃铛。再响一声是提醒还是噪声？
等待审批响（不同音色）agent 卡着不动，比"完成"更需要立刻知道
1.5 秒内连续多条只响一次三个任务同时完成不该响三声——防连发是必须的
系统「勿扰模式」开着静音可以查到系统勿扰状态，但要额外接口；先不做，用应用内开关代替
你自己点开了那条通知不响你已经在看了
保留意见

提示音必须能一键关掉，而且要好找。 我会在灵动岛的展开态放一个小喇叭图标（点一下静音/恢复），状态存 localStorage。 不放在设置深处——需要翻三层菜单才能关掉的声音，用户的解决办法通常是把整个应用静音。
