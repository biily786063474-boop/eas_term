# 代码地图 · 适配范围与局限

> 2026-09-03。判据全部来自**跑用户真实的 29 个项目**，不是推断。
> 改了入口发现、领地推导或语言支持，回来更新这份文件。

## 一句话

代码地图画的是 **模块之间的 import 关系**，认四种栈：**JS/TS · Python · C/C++ · Swift**。
认不出的（纯 HTML / 纯文档），它会**说清楚看到的是什么**，而不是报错。

**整条链零 LLM、零网络** —— 只有 `fs` / `path` / 正则 / dependency-cruiser。
同一份代码每次扫出来一模一样（环形布局而不是力导向，也是为了这个）。

## 实测覆盖：29 个项目

| | 数量 | 说明 |
|---|---|---|
| 画得出来 | **25** | 从 3 个节点的到 3101 个节点的都有 |
| 画不了 | 4 | 全部核实过：纯 Markdown / 单页 HTML，**没有可画的结构** |

改造前是 **1 个**。三个阶段：入口发现（1→16）· 多技术栈（16→25）。

改造前只有 **1 个**能画（就是开发时用的那个仓库）。三个根因：

### ① 入口只按约定猜 → 只中自己见过的布局

原来靠一张写死的候选表（`src/main/index.ts` 之类）。现在四路取并集：

1. 候选表（扩到 `.js/.jsx`、`electron/main.js` 等 26 个）
2. **`index.html` 里的 `<script src>`** —— Vite 项目的真入口写在这儿，
   package.json 的 `main` 根本不指它（taptv：只看候选表 21 个模块，加上 HTML 是 445 个）
3. `package.json` 的 `main` / `module`
4. **`entriesFromDirs`：扫所有装着源码的目录** —— 保底那层，不靠任何约定

### ② 绝对路径会被 dependency-cruiser 折坏

**入口必须传相对 `baseDir` 的路径。** 它把绝对入口先按 `process.cwd()` 折成相对，
再拿 `baseDir` join 回去：

```
cwd = /…/Projects/vibe coding/terminal      root = /…/Projects/taptv pad
relative → "../../taptv pad/electron/main.js"
join     → "/Users/biily/Biily/taptv pad/electron/main.js"   ← 少了 Projects/ → ENOENT
```

只有「cwd 恰好等于项目根」的那一个能过 —— 也就是开发时用的那个。

### ③ 领地表是本仓库专用的

`TERRITORIES` 编码的是图纸 10 的真实知识（禁区、高耦合）。换个项目一条也命中不了，
**3229 个模块全落进「未登记」**，图是一坨没有结构的灰点。

现在：命中率 < 50%（或模块少于 10 个）就转 `derived` —— 按项目自己的目录结构分组，
**颜色改成表达耦合轻重**，图例文案跟着换。对陌生项目写「安全边界」是编造。

## 多技术栈（2026-09-03 加）

JS/TS 走 dependency-cruiser；另外三种走 `src/main/multiLang.ts`（零 electron、可单测）。
提取 import 的那层在 `src/shared/langImports.ts`（纯字符串、17 条测试）。
**两条路完全并行**，混合项目（Electron 壳 + Python 脚本）两边都出结果，最后合并成一张图。

| 栈 | 粒度 | 怎么解析 |
|---|---|---|
| JS/TS | 文件 | dependency-cruiser |
| Python | 文件 | `import a.b` / `from .x import y`，相对 import 数点数；落到 `a/b.py` 或 `a/b/__init__.py` |
| C/C++ | 文件 | `#include "x.h"` 先相对包含方目录，再试 `include/` `src/` 等根 |
| **Swift** | **模块** | 见下 |

### Swift 只能画到 target 级，这是语言本身的坎

**Swift 同一个 module 内的文件互相可见、不需要 import** ——
实测「Ipad延伸」159 个 `.swift`，指向本项目内某个文件的 import **0 条**。
所以文件级依赖图在 Swift 里**不存在**，不是「这个项目耦合低」。

能画的是 target 之间：target 从 `Package.swift` 读（权威），没有就按目录推
（`Sources/<X>/` 或顶层目录名）。**系统框架撞目录名要挡** ——
「口播相机」有个 `Speech/` 目录，而 `import Speech` 是苹果的语音框架。

界面上状态栏会标黄字「**·模块级**」，hover 有完整说明。

### `.gitignore` 是「什么不是源码」的权威

硬编名单永远列不全。实测：「美颜」696 个第三方 C/C++ 在 `third_party/`、
「口播相机」产物在 `build-dev/`，两个都不在任何通用名单里，
**但两个项目的 .gitignore 里都写着**。接上之后：美颜 784→88 节点、口播相机 36→15。

实现在 `src/shared/gitignore.ts`（10 条测试）。只取「能判出目录该不该进」的子集，
判不了的一律放行 —— 多扫一个目录只是图上多点东西，漏扫一个是图不全。

## 还剩的局限

| 局限 | 表现 | 能不能修 |
|---|---|---|
| **Rust / Go / Java 等** | 画不了 | 加一个提取器 + 一套解析规则，和 Python 那条同样的量 |
| **HTML 之间没有结构可画** | 实测「设计规范」890 个页面之间只有 9 条本地 `<a href>` | 不是能不能，是**不值得** |
| **框架专有格式** | `.astro` / `.vue` / `.svelte` 里的 import 看不见（Astro 项目实测 0 模块，退回目录扫才有 49 个） | 要自己写这几种的 import 提取 |
| **大项目慢** | 3101 节点约 6.2 秒（同步阻塞主进程那一小段） | 未做：可以放 worker |
| **Swift 只到 target 级** | 一个 159 文件的项目图上只有 5 个点 | **语言本身如此**，不是实现问题 |
| **`dirs` 口径含死代码** | 没认出具名入口时扫全目录，会带上没人 import 的脚本 | 已在状态栏如实标出（「按目录」/「按入口」） |
| **动态 import 的字符串拼接** | `import('./x' + name)` 这类连不上 | 静态分析的固有边界 |

## 两条容易改回去的

- **`isLocal` 必须落到「磁盘上真有这个文件」。** 光看字符串形状拦不住裸说明符 ——
  `fs` / `util` / `@scope/pkg` 都满足「不以 node_modules 开头、不是绝对路径」，
  于是图上多出一堆不存在的节点（本仓库实测 16 个，别人的仓库几十上百个）。
- **循环依赖那块默认折叠。** 本仓库的环才 3 条边，别人的项目一个环 35 条，
  摊开会把主视图整个挤出屏幕。折叠头上仍写着「几个环 · 几条边」—— 收细节可以，藏问题不行。
