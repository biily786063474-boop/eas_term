坑

只有真机才暴露的，别再踩一遍
① 挑网卡挑中了 VPN 隧道

朴素的「取第一个非回环 IPv4」在本机挑中了 WireGuard 的 utun0（10.9.0.4）， 二维码里给的是隧道地址，同一个 Wi-Fi 下的手机压根连不上。

装了 VPN / Docker / 虚拟机的机器上这不是特例是常态。 现在 lan.ts 先按名字整类排除虚拟/隧道网卡，再按「像不像家用局域网」排 192.168 > 172.16-31 > 10。9 个单测锁住。

② 二维码「看着对，扫不出来」

自己写的编码器有两个 bug，结构测试全绿、肉眼完全看不出： 格式信息的位序整个写反了（规范是 MSB 先出）、固定暗模块一直被占位循环冲掉 （第二个一直被第一个盖着，改对位序才露出来）。

定位办法：用 macOS 自带的 CIQRCodeGenerator 生成同一段文本做参照， 反推位序。验证办法：生成图片交给 Vision 框架真扫一遍—— 结构测试证明不了可扫性，只有真扫能。这两条都留成了常驻测试。

③ 手机只能看见它自己建的会话

画布节点有两种形态：自带 pane 的，和只有 leafId （引用分屏那边的共享 leaf）的。桌面上正常开的终端和 AI 对话全是第二种， 而 collect.ts 只认了第一种。

本机实测：21 个节点走 leafId（终端 6 + AI 对话 15），走 pane 的只有 3 个 —— 日常在用的几乎全被漏掉。而我的单测一条都没抓到， 因为造数据时只用了 pane 那一种形态。这条教训写进了 collect.ts 的注释。

④ 合并冲突吃掉一个 }，整个 app 变毛坯房

CSS 解析器遇到未闭合的规则会把后面所有内容当成它的声明块吞掉， 而 Vite 把全部 CSS 拼成一个文件、base.css 恰好排在最后 —— 一条断掉的规则吞光了整份基础样式。

typecheck、1012 个测试、build 全绿，只有真打开 app 才看得出来。 现在有 scripts/check-css-balance.mjs 接在 npm run check 里， 10 毫秒的静态检查，精确报到行。

⑤ 一个被推翻的设计

新建会话原本要求「电脑上点允许」。用户一句话点破： 要求电脑确认，恰恰假设了你能碰到电脑 —— 而这功能就是为够不着电脑时用的。 连带纠正了我一处过度表述：新建对话不会拉起进程， 它只是 addFileNode 加一个空节点，CLI 要等有人发消息才起。

接下来

下一次接手从哪继续

第一步 · 局域网 + 只读 已完成

含新建会话和动态页（都超出了原计划）。

第二步 · 给 agent 发消息

白名单里 send 已经占了位、也已归到写操作，只是还没实现。 留痕已经就绪，是当初上写操作的前提。 要先想清楚审批闭环：人在外面时点不了「允许」， 而 agent 的 PreToolUse 钩子会卡在第一个工具调用上。

第三步 · 隧道（在外面也能用）

架构红线：绝不在隧道服务端终止 TLS。 用户自己这台是现成的 WireGuard peer（utun0 = 10.9.0.4）， 写服务端之前可以先靠它把协议和体验验完。
