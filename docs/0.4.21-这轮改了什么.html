Feature 1

知识库可以按你自己的分类建了

原来是写死的八个目录。做研究的想按「课题 / 文献 / 实验」分，做内容的想按「选题 / 素材 / 成稿」分， 以前只能忍着或者不用。

怎么用

跟终端里的 agent 说一句「知识库分类不合适，我想按自己的方式建」，它会走一条固定的五步流程：

步骤做什么为什么写死在流程里
先声明老库不搬、不改、不删这是第一句话，不给模型自由发挥的余地
读现状把你现在库里的分布摊出来（哪个目录堆着、哪个空着）让新分类有依据，而不是凭空想
问清怎么分问「你平时往里放的东西，大致分几类，每类一句话怎么描述」不是问「你要几个文件夹」——后者会得到一堆没有用途说明的空目录，而那句话正是要写进 agent 说明书、决定东西往哪放的唯一依据
给方案目录清单 + 每个的一句话 + 字段要求，等你点头一次一个问题，不抛表格让你填
建库建骨架、写配置、生成说明书、你手动切过去切换位置没有编程接口，必须你在抽屉里点

技术上怎么做到「老库一个字节不变」

库根放一份 .eas-wiki.json 声明目录与用途。所有耦合点改成「有这个文件按它走，没有就走今天写死的那套」：

# 没有 .eas-wiki.json 的库（你现在这个）
读到配置？ 否 ──▸ 内置八目录 ← 与改动前逐字等价，有哈希钉住

# 有 .eas-wiki.json 的库
读到配置？ 是 ──▸ 按配置的目录与用途走
              ├─ 建骨架
              ├─ CLAUDE.md / AGENTS.md   给 agent 的说明书
              ├─ index.md / START-HERE.md 给人看的
              ├─ 收件箱识别 / 原始素材区判定
              └─ 归档落点

# 配置文件被改坏了
读到配置？ 坏了 ──▸ 停手，什么都不动 + 抽屉里告诉你
              不回落到内置——回落会把你自定义的库改成内置形状，不可逆

为了保证内置那条路一个字符都没变，四段生成说明书的源代码被哈希钉住 （schemaBody / schemaText / indexMd / readmeText）， 改动前后 sha256 逐字节相等。

Feature 2

给 AI 的使用指引改成按需加载

原来是一份 301 行的说明，每次对话都要整份读一遍。在 Codex 里最明显 —— 你在那儿改一行代码，都要先付一整份画板指南的 token。

文件行数装什么什么时候读
SKILL.md97最重要的一条 · 工具速查表 · 四条触发条件各占一行 · 边界 · 分寸每会话常驻
canvas.md64完整工具表 · 具体场景 · 工具不见了怎么办要操作画布时
generate.md105生图/生视频全套：两阶段确认、六个坑、意图→该调什么用户要图/视频
secrets.md68密钥三步 + 三条不要越的线撞到缺 key / 401
wiki-architect.md165自定义知识库的完整引导流程要改知识库分类
切分判据
规则常驻，操作步骤按需。 不是按长短切，是按「不知道它会不会做错事」： 「生图只能走笔纵画板」是规则（漏了模型就会去调别的图像 API），必须常驻； 「怎么两阶段确认」是步骤，用到时读来得及。

配套改了分发代码：原来「把 SKILL.md 当单个文件处理」，现在装整个目录。 「装没装」的判据也跟着改成「每个源文件都在」——原来只查一个文件，少拷一个会被误判成已安装。

顺带修的
「扩展能力」面板里的落点清单少报了文件。那是告诉你「我们往你机器上写了什么、卸载会删哪些」的清单， ~/.eas/agent/ 整个目录从来没被列进去过。清单不全，一键卸载的承诺就是空的。 现在按盘上实际存在的每个文件动态列。官网隐私页同样的问题也一并改了（该页尚未发布）。

What review caught

整分支审查挖出的四条

计划里 7 个任务，每个都单独审查过、全部通过。但整分支审查在任务与任务的缝上 找出 4 条 —— 那是每个任务单独审时谁都不负责的地带。我逐条独立核实后确认属实，全部已修。

Critical 1 · 归档会造出配置外的目录
归档落点没接上配置。自定义库一归档，就凭空建一个配置里没有的 sources/； 因为它不在配置里，扫描逻辑判定它不是原始素材区，于是递归进去把归档的原件当成笔记扫进图谱和体检 —— 体检会报它们缺摘要、缺标签、孤儿页、内容过薄。正好打脸设计文档自己写的验收条款。

修法：归档落点改走配置里标了「原始素材」的那个目录；配置里没有的话明确报错， 不凭空造目录（造目录换个名字还是同一个 bug）。
Critical 2 · agent 拿到的目录清单还是内置那套
这条最要命，而且它是设计文档四点清单里的第一条，从来没实现过。 知识库查询工具交给 agent 的目录清单仍是硬编码的内置八个，工具说明还写着「dirs.me 是用户画像分区」—— 于是模型会往自定义库里写 me/xxx.md，把内置目录一个个造回去，正好抵消这个功能本身。

修法：查询结果加一个字段，只在库有自定义配置时出现，明确告诉模型「按它判断东西往哪放，忽略内置那套」。 类型定义、MCP 工具说明、渲染层提示、引导文档四处一起改 —— 漏一处等于没修。
Important 3 · 配置写坏了会把库改回内置形状
配置文件损坏时「回落到内置默认值」听着稳妥，实际会往你的自定义库里撒一堆内置目录、 把说明书整段重写成内置分类，不可逆。而那份配置是让 agent 手写的 —— LLM 写坏 JSON 是常规故障。 更糟的是其中两份文件只在缺失时写，首次建库就写坏的话永久停在错误内容上，你事后修好也救不回来。

修法：区分「没有配置」和「有配置但坏了」两种状态，后者停手不动并在抽屉里告诉你原因。 这条纪律后来推到了归档、查询、收件箱、逐字稿四条路径。
Important 4 · Codex 侧丢了两节
拆分之后，「边界」（终端关不了、没有替你打命令的工具、路径白名单）和 「分寸」（别刷屏、通知别滥用）两节对 Codex 变成不可达 —— 没有任何触发条件指向它们。 这不是有意的权衡：省 token 的目标只跟触发条件有关，砍掉这两节一个 token 都没省。

修法：补一条常驻指针，措辞明说「这条不是触发条件，是随时都作数的规矩」，避免模型当成可选分支。
一个衍生判据
修 Important 3 时提炼出一条通用规则，已写进新建的 agent 接入 skill： 能回落的前提是「回落不会写坏用户的东西」。 读取类回落无害；写入类（建目录、改文件、搬东西）和「告诉 agent 这东西长什么样」（会诱导它写）都不能回落。

诚实交代
没有真人跑一遍触发实测。 计划里有一步是「只给常驻那份，起一个真 claude 逐条念触发词， 看它会不会主动去读细节文件」——那步没做。渐进式披露的固有风险就是失败是静默的： 模型不会说「我没读到」，它会直接凭印象干活。代码层面能验的都验了，模型行为层面没验。

另外我自己在写验收断言时错过两次（按想当然钉了中文串的排序、假设返回值是裸字符串）， 两次都是实现对、我的测试错。
