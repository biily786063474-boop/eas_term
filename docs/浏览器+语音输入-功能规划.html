Chrome 内核迷你浏览器 + 语音输入（STT）

两路并行调研（Web 检索 2025–2026 实况）+ 主报告人核对源码后的落地规划。含方案对比、推荐、分期实现、落地锚点、坑与规避、待验证项，以及顺带诊断出的「思考/模型不记忆」bug 修法。

2026-07-24 Electron 37 · Chromium ≈126+ 目标：feat/canvas-p0 本报告只规划，未改动功能代码

三件事，一句话各一条：

  • ① Chrome 内核迷你浏览器 → 用 <webview>（不是 WebContentsView）。它是 DOM 元素、会跟随你画布的 CSS transform 缩放平移、又是真 Chromium 有完整导航能力。唯一正确解
  • ② 语音输入 → 做一个「STT provider 抽象层」+ 合理默认档。默认走本地离线 sherpa-onnx 中文流式（零 key、免费、隐私、准+快），云端 OpenAI Realtime / 火山 / 讯飞 作可切换升级档。可配置
  • ③ 顺带修 → 「思考/模型重启不记忆」是真 bug（防抖未落盘 + 旧字符串格式），小改动可根治。

1 Chrome 内核迷你浏览器 canvas-embedded mini browser

结论：在「必须作为画布节点、跟随 CSS transform: scale() 缩放平移」这个硬约束下，<webview> 是唯一同时满足「真浏览器内核 + 能被 CSS 变换的 DOM 元素」的中间态。你的预判成立。

你项目里 WebView.tsx 第 1–3 行早就写了「严禁 BrowserView/WebContentsView——原生叠加层不受 CSS transform 控制」——本次调研证实这条记录完全正确，并给出从 iframe 升级到 webview 的路径。而我刚给你做的画布缩放正是 CSS transform（PaneView.tsx 非终端节点 transform: scale(cs)），webview 作为 DOM 元素会自动跟随，和图片/代码节点走同一条路。

关键实况（决定推荐，务必知道）

  • webview 现在是 OOPIF（进程外 iframe）：本质就是一个被浏览器合成器合成的跨域 iframe，祖先的 2D transform 会像作用于任何跨域 iframe 一样作用一次并被 overflow/圆角裁剪——正是我们要的。纪律 webview 自身的 zoomFactor 必须恒为 1，缩放只交给外层 CSS transform，否则叠乘。
  • 「webview 已弃用」是软性的、且有个常见误读：网上「webview 2025 年 1 月结束支持」指的是 Google Chrome Apps 的 webview，不是 Electron 的。Electron 37 里 webview 仍存在、可用、功能完整，无移除时间表。官方只是「不推荐、自担风险、未来无保证」。规避：把 webview 收敛进一个薄封装组件，将来若真出问题好整体替换。
  • WebContentsView 连「缩放」本身都无法正确复现：只能 (a) setZoomFactor——那是页面级重排缩放（文字重新排版，非几何缩放一个矩形，还有 ~0.25x 下限）；或 (b) 只改 bounds——内容不缩放、只是透过更小的窗口看 100% 的页。都不是「节点作为可缩放矩形贴在画布上」。要让它「假装」是 DOM 节点（Electrobun 那套：移屏外 20000px + 渲染/交互层分离 + 图像遮罩打洞 + 光标 swizzling）成本极高且仍达不到真缩放跟手。单人项目不该碰。

迷你浏览器 chrome 架构（DOM 层，套在 <webview> 之上）

节点外框/头部/拖动/缩放/resize 已由 PaneView 提供，浏览器 chrome 只需在 .web-view 内做一条工具条 + 一个错误浮层：

  • 地址栏：受控 input，did-navigate 同步当前 URL；回车归一化（补 https://、非 URL 转搜索）→ webview.loadURL()。
  • 后退/前进：禁用态取自 canGoBack()/canGoForward()；刷新/停止按加载态切图标（reload()/stop()）。
  • 加载态：did-start-loading→顶部不定态进度条，did-stop-loading→收起。标题/图标：page-title-updated回填节点名、page-favicon-updated放地址栏左侧。
  • 错误页：did-fail-load（忽略 -3 ABORTED）→ 你自己的 React 错误浮层（DOM 可直接盖在 webview 上）+ 重试。
  • 新窗口/弹窗：new-window 事件 E22 已删 → 主进程 did-attach-webview + guest.setWindowOpenHandler（deny 原生窗）→ IPC 通知渲染层新开一个 web 画布节点加载目标 url。
  • 会话/安全：partition="persist:browser" 多 web 节点共享 cookie、与主应用会话隔离；guest 侧关 nodeIntegration、开 contextIsolation。

落地锚点（已核对源码）

  • 开关：src/main/index.ts 的 BrowserWindow.webPreferences 加一行 webviewTag: true（当前只有 preload）。
  • 改 WebView.tsx：<iframe> → <webview> + 上面那条 chrome bar。红利：PaneView.tsx 已给非终端节点套了 transform: scale(cs)，webview 自动跟随，无需任何特殊定位代码。
  • frame 头部新建浏览器 icon：CanvasStage.tsx:647「新建终端」按钮右侧加一个 GlobeIcon 按钮，调新 store action addBrowserNode(frameId)（照 addFileNode 建一个 {kind:'web', url:null} 节点）。
  • 所有网页文件都用它打开：现有路由 CanvasDrawer.tsx:20 已把 .html/.htm → {kind:'web', url:'file://…'}；WebView 换成 webview 后，本地 HTML 与远程站点一个组件通吃。
  • 持久化：{kind:'web', url} 够用；did-navigate 回写 url 即可「重开还原到上次页面」，沿用现有 canvas.json sanitize。
  • 崩溃自愈对齐：给 webview 加 render-process-gone → 错误浮层 + 一键重载，风格同 P0 已有的窗口自愈。

⚠️ 落地后必须在 app 内亲验（据架构推断，未实机验证）：① webview 放进 transform: scale() 画布节点后，在 0.2 / 1 / 2.2 各档是否单次缩放、清晰、平移跟手不飘（这是本方案成立前提，第一件要验的事）；② webview zoomFactor 恒 1 时缩放是否与图片/代码节点视觉一致；③ 极端缩放下点击/输入焦点命中是否准；④ 加载 Google/GitHub 等（iframe 会被 X-Frame-Options 挡）确认 webview 能开、iframe 打不开——坐实「真浏览器」价值。

2 语音转文字麦克风输入 streaming speech-to-text

结论：需求本质是「做一个可切换的 STT provider 抽象层 + 一个合理默认档」，把用户说话流式转文字追加到输入框。Web Speech API 在打包后的 Electron 里基本不可用（Chromium 语音后端走 Google 内部 API、Electron 构建不含 key，官方 issue #46143 已确认），直接排除。

把当前终端右下角的「↓ 最新」按钮替换成麦克风按钮（TerminalView.tsx 的 jumpBtn）——点击申请麦克风权限、开始识别，说的话流式回填输入框。

推荐

默认档（开箱即用）零配置

本地 sherpa-onnx + Paraformer-zh 流式。纯 Node 原生插件（npm sherpa-onnx，免 Python）、Mac 可跑、完全离线、真流式、中文一流（CER 1.95%）、零成本、隐私不外泄。契合「本地优先的开发者工具」气质。代价：随包或首次下模型（中英流式约几十~两百 MB）。

云端升级档（可切换）更准/更快

OpenAI Realtime（gpt-4o-mini-transcribe 默认，可升 gpt-4o-transcribe）——真流式、中文强、$0.003/分几乎免费、和「AI 中心」调性一致，但需一个 OpenAI API key。国内场景另给 火山豆包(1元/时)/讯飞(中文第一)，要最低延迟给 Deepgram。
决策点 你跑 Codex 是 ChatGPT 登录，未必有独立的 OpenAI API key（Realtime 转写要的是 API key，不是登录）。所以两条路线：A 默认离线 sherpa-onnx（零 key，装了就能用），云档等你填 key 再开；B 你若已有/愿意配 OpenAI 或国内厂商 key，直接上云档更准更省心。我的建议：先做「provider 抽象层 + 离线 sherpa-onnx 默认档」，云档作为设置里可选项——既满足「可配置」、又不强依赖 key、又契合软件本地优先特性。

3 顺带：「思考/模型」重启不记忆 bug bonus fix

已诊断(dev 实测确认)，两个叠加成因：

  1. 防抖未落盘：画布落盘是改动后 500ms 防抖。你改完胶囊很快退出/切走时，那次改动还没落盘就随页面卸载被取消了 → 重启读到旧值。实测铁证：设值后立刻 reload，磁盘上的改动确实丢失。
  2. 旧字符串格式读不出：我接 Codex 时把 model/effort 从「字符串」改成「按 agent 分的对象」{claude:'sonnet'}。你旧存档里部分节点 model 还是字符串 'opus'，新代码 agent.model?.[kind] 读它得 undefined → 回落默认(默认恰好也是 opus，所以"看着对"但没读你存的值)。

修法(小改动)：① 退出/失焦时 flush 待落盘的画布（beforeunload 走同步 IPC，或主进程 before-quit 让渲染层立即序列化保存）——根治防抖丢失；② loadCanvas 里迁移旧字符串：agent.model/effort 若是字符串 → 转成 {[agent.kind]: 值}，你之前的选择就回来了。新格式本身持久化+恢复已验证是好的（我实测设 Sonnet/中 → reload → 完好保留）。

✓ 需要你拍板的决策点

  • 浏览器：确认走 <webview>（软性弃用但唯一契合画布约束，我会封装成薄组件降风险）？iframe 保留作可信本地内容兜底？
  • 语音默认档：默认离线 sherpa-onnx（零 key、随包带模型约百 MB）？还是你有 OpenAI/国内厂商 API key 想直接上云档？
  • 「↓最新」：改成麦克风后，「回到最新」挪到哪（滚动条区 / 右键菜单）还是直接去掉？
  • 顺序：先修「思考/模型」bug（小、快），还是先做浏览器 / 先做语音？
