Agent 控制台 画布模式下把 Claude Code / Codex 的 CLI 包一层图形前端 · 设计评审 v1 · 2026-07-23

目标：在画布模式下，终端模块顶部可切 Claude Code / Codex，切换后出现一层 Codex 风格的控制台——模型、effort、审批等做成可鼠标交互的控件，点一下就把对应 CLI 命令喂给底层真实终端启动。 切回终端模式时这层前端消失，只剩原始终端与命令。底层始终是真实 CLI，前端只是把常用参数/命令可视化。

一、推荐架构（先讲清楚"是什么"）

它不是重写 Claude Code / Codex 的对话界面（去解析它们的输出再自绘——那是解析地狱、极脆弱、不做）。

它是：给画布终端节点加一层「控制条 + 启动器」覆盖层（canvas-only chrome）：

  • 顶部左侧：Agent 切换段控件（Claude Code / Codex）。
  • 控制条：模型下拉、effort 段控件、审批/沙箱开关、常用命令按钮（继续/恢复/清屏/新会话…）。
  • 右上：额度可视化（见第四节，有硬限制）。
  • 「启动 / 发送」按钮：把当前控件组合成一条 CLI 命令，pty.write 进真实终端执行。
  • 下方：还是那个真实终端（xterm），显示 CLI 的真实输出——这才是"CLI 命令驱动"。

数据落在终端节点上（CanvasNode 加一个可选 agent 配置：kind / model / effort / …）。 画布模式渲染控制条；分屏模式的 PaneView 不渲染这层，只显示裸终端——天然满足"切回终端模式无前端"。

四、额度可视化 —— 诚实说：有硬限制

CLI 不提供"订阅剩余额度"的干净读取接口。 Claude Code 的 /cost//status 只给当前会话的 token 用量，不是订阅周期的剩余额度；Codex 同理。想要"还剩多少 5 小时额度"这种，没有官方 API 能稳定拿到。

三个折中，按你要的"简约可视化"排序：

  • A（推荐，务实）：可视化本会话 token 用量——解析 /cost 或 stream-json 的 usage，画一根进度条+数字。真实、不吹牛，就是"这轮花了多少"。
  • B：让用户手填"周期额度上限"，我们累计本机各会话用量做近似进度条——半真半估。
  • C：先不做额度，占位留接口，等有稳定数据源再接。

五、多维评审

维度结论
可行性控制条+启动器+映射 CLI：高。额度真实剩余：低（走会话用量折中）。
体验把最常调的 model/effort/权限从"记命令"变成"点两下"，对你这种多 agent 并行盯着的场景增益大。
完成性分屏无前端、画布有前端——天然由 viewMode 分流，干净。参数持久化复用已有画布持久化。
token 成本（对你）前端本身不耗 token；反而 effort/model 可视化能帮你有意识地控成本（该用 haiku/low 时顺手降）。
风险① Codex 参数需装机核对；② 不同版本 CLI flag 会变（做成配置表、易改）；③ 额度别过度承诺。
