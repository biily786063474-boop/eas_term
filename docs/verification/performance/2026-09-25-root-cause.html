长运行卡顿与画板闪烁：阶段性根因

确认并修正两条无效渲染路径：平移时对话导航重复量布局，以及最大化后隐藏画布里的光环继续动画。持续高内存与标题栏闪烁尚未完全归因，不能把局部优化冒充全部修复。

已确认：对话提问导航重复读取布局

画板每帧只移动整个面板，但 QuestionNavigator 原来在每次几何通知后，逐条读取提问的 getBoundingClientRect()。隔离应用 4 个对话模块、每个 60 条提问、60 帧平移，测到 4560 次读取。修正后仅在滚动、缩放、正文变化或容器尺寸变化时重读，降为 120 次（约 -97.4%）；轨道仍随平移更新，滚动后的活动提问也正确改变。

本样本优化前 p95 约 9.3 ms、优化后约 9.3 ms；未测出帧率提升。优化后有 1 个 >50 ms 帧，不能以单次短样本解释为回归或收益。

已确认：最大化后隐藏动画未停

最大化仅将画布世界设为 visibility:hidden，以保持节点身份；这不会停止内部 CSS 动画。离屏观察器只看几何交叉，隐藏后仍可能认为 Frame 在视口内。隔离应用把隐藏世界里的 36 个空 Frame 光环设为运行态，确实仍持续转动；补上隐藏态暂停规则后为 0 个运行、36 个暂停。最大化的 HTML 内容仍可见，不统一暂停整个世界的动画。

真实负载与未定因

观察结论边界
正式版运行约两天；渲染进程约 1.4 GB，CPU 抽样 56–68%，GPU 36–43%确有持续高负载，但 RSS 不是泄漏证明；两处修补能否显著降低这台机器的负载仍未实测
画板存档：32 Frame、106 节点（33 对话、48 网页、13 图片）；对话面板保持挂载并读历史是长运行内存与拖拽更新量的放大因素；网页节点有懒创建和两分钟离屏回收，不能按 48 个活动进程计算
标题栏用 28px 背景模糊，Frame 也有模糊；画板移动时需合成是闪烁嫌疑，隔离空闲场景关闭模糊未形成有效动态负载对照，尚不能定罪
同期无渲染/GPU 进程崩溃或 Frame 整体反复重挂排除这段日志中的两类机制，不排除窗口合成闪烁
