# Eas-Term 0.4.85 发布验收（尚未发布）

产品源提交 `9510ff29e94b143015691715f3e0bfbe16b1caa7`，分支 `feat/builtin-capabilities`。笔纵 1.21.31 已按用户授权先行上线；Eas-Term 线上继续保留 0.4.84，尚无本版正式标签。

## 变化

- 工作台 MCP、笔纵连接器、使用指引统一为随包内置能力，复用现有插件宿主；设置中分别控制，不占用用户选中的业务插件位置。
- Claude Code、Codex、omp 的 AI 对话和受管终端入口显式装配能力，按发起会话绑定项目和 Frame。状态区分禁用、依赖不可用、未请求与握手就绪，不以零工具冒充成功。
- 笔纵连接按需建立并恢复；生成提交使用持久请求身份，未知结果先查询认领，不自动重新付费提交。实际计费断线验收仍待完成。
- 精确旧规则托管段在真实工具成功后才迁移，完整备份、校验并保留用户正文；第三方 MCP 与归属不明段保持。
- Windows 官方 npm CLI 统一解析到经过校验的原生或 JS 入口，Codex 取消/断连只清理所属启动进程和子进程，保留旧 vendor PATH 与包来源语义。

## 审查与回归

两轮 Windows 独立复核已收敛，无剩余重要审查项。本机完整套件 2742 通过、10 Windows 专用项跳过、0 失败；Windows CI 34235219068 的 CLI/control 25/25 与 contracts 7/7 通过、0 跳过；构建、类型及随包工具检查通过。

Mac arm64 的 Claude Code、Codex、omp 各在 AI/PTY 入口完成新建、恢复、应用重启后恢复，18/18 阶段有真实调用、正确 Frame 及图片解码证据。两种 Mac 架构完成签名公证、Gatekeeper、归档及源码内容检查；x64 通过 Rosetta 实际设置检查，Windows 正式包启动与设置检查通过。详情见 [冻结验收](../builtin-capabilities/reviewed-9510ff2-acceptance.md)。

迁移演练确认用户正文/修改段保留、备份哈希、重复启动幂等；所属应用进程确实退出后离线恢复通过。[迁移回退说明](../builtin-capabilities/migration-and-rollback.md)。未执行真实用户全局规则迁移。测试期间全局 `.claude.json` 发生来源未知的并发变更，OS 写保护探针通过，不宣称所有全局文件未变。

## 剩余验收与限制

- Z-Image Turbo 1K 单图 4 墨水的实服务断线、认领、无重复扣费验证尚待明确批准，未收费。
- Windows 已登录三端实际模型验收环境仍缺；CI 原生夹具不等于模型调用。
- 远程第三方业务插件不是三端统一支持：Claude 受支持的原生配置、Codex 已有原生注册保持，omp HTTP/SSE 明确不支持。未知自定义 Windows batch 入口拒绝启动，不解析执行任意脚本来绕过。
- 外部 Computer Use 指针生命周期仍开放，本版不标记修复。见 [生命周期约束](computer-use-lifecycle.md)。
