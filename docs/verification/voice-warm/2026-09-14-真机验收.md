# 语音启动：识别 worker 常驻 + 退出准入队列 · 真机验收（2026-09-14）

用户报「语音输入要等很久」并要求「语音输入不要性能的等待队列」。

## 诊断（隔离实例主进程内计时，真实模型）
| 段 | 耗时 |
|---|---|
| 流式识别 worker：WASM 实例化 | 47 ms |
| 流式识别 worker：加载 74MB int8 zipformer | **2796 ms** |
| VAD worker 就绪 | ~250 ms |
| 两者并行 | 3129 ms |

每次录音都重建 worker（第二次 3087 ms，与第一次相同）。调度器里语音是交互型，直接启动，不排队 —— 等待与准入无关。

## 改动
- `voicePreviewSession.ts`：link（常驻 worker）+ lease（每次录音）；旧 lease 迟到的 partial 按消息 id 隔离；lease.completed = 录音结束。6 测。
- `voicePreviewWorker.ts`：加 `reset` 消息（换新 stream，走同一条 FIFO）。+1 测。
- `voicePreviewPool.ts`：acquire / release（闲置 10 分钟释放）/ drop。3 测。
- `runtime/voicePreviewAdmission.ts`、`runtime/managedVad.ts`：不经 `startManagedSession`，只登记 `ownedSessions`。契约测试改写（voicePreviewAdmission / managedVad / managedPreview / voicePreviewWiring / voicePreviewLoading / managedVad.real / voicePreviewWorker.real）。
- `stt.ts`：`createPreviewWorker` 从池里拿 lease；`dropVoicePreviewWorker` 在 `will-quit` 调用。

## 证据
- `npm test` 3205 条 0 失败（15 跳过）；typecheck 0 错；build 通过。
- 真实模型测试 `voicePreviewWorker.real.test.ts`：同一 worker 第二个 lease 就绪 < 200ms，冷加载 > 5× 热。
- 隔离实例（挂真实模型目录，麦克风权限已授）连续三次 `stt:start('standard')`：**3153 / 123 / 133 ms**，全部 ok。
- 录音中运行与资源页可见「流式语音识别」「人声检测 VAD」两项，排队 0；停止后 2.5 秒内两项消失，最近结束各留一条 `exited`。

## 边界
- 常驻期间约 95 MB（隔离实例 rss 增量）；闲置 10 分钟释放；内存严重压力下不主动释放（后续可接 controller 的 critical 信号调 `dropVoicePreviewWorker`）。
- 模型重新下载后常驻 worker 仍用旧文件直到闲置释放；`stt:downloadModels` 未接 drop（模型目录同名覆盖时才有影响）。
