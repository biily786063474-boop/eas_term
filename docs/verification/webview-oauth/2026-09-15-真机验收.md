# 迷你浏览器 window.open → 受控子窗口（修 Google 登录）· 真机验收（2026-09-15）

用户报：迷你浏览器登录界面用 Google 登录，点击后没反应、不跳转、无显示。

## 根因（隔离实例实测三种弹窗方式）
主进程 `index.ts` 给每个 webview 装的 `setWindowOpenHandler` 把所有 `window.open` 拦成「当前 webview 内 `loadURL`」：
- `window.open('https://…')`（B/C）→ 当前 webview 被导航过去，顶掉原页（「有反应但错」）。
- **`window.open('about:blank')` 再设 location（A，Google Identity Services 用的方式）** → 当前登录页被导航到 `about:blank` 变空白；`deny` 让 `window.open` 返回 null，后续 `location` / `postMessage` 全落空 → 「点了没反应」。

## 改动
- 新 `src/main/webviewPopup.ts`：`webviewOpenAction`（`eas-favorites:` → 路由；其余 → 弹窗）、`popupWebPreferences`（= `hardenWebviewPreferences`，无 preload + 沙箱 + 指定 partition）。3 测。
- `src/main/index.ts`：webview 的 `window.open` 返回 `allow`（`pendingWebviewPopups++`）；`type==='window'` 分支据计数认出弹窗，给它 OAuth 策略（不装主窗口那套 `external`，让它自由导航），弹窗内再 `window.open` 才交系统浏览器。主窗口的意外弹窗仍走 `external`（S2 不动）。

## 证据（`node scripts/verify-app.mjs`，本次构建，真机 CDP）
- A（GIS）：点击后 `webview stayed on: file:///…/login.html`（**原页保住**）；`page h: A set popup location`（`window.open` 返回可用引用、`w.location` 设置成功）。
- 弹窗窗口：`BrowserWindow` id=2，`visible=true`，`url=https://example.com/` —— **自己导航到了目标**，没被 external 踢到系统浏览器。
- 安全：弹窗内 `window.api=undefined`、`require=undefined`、`process=undefined`（无 IPC/node）；`window.opener=object`（OAuth `postMessage` 回传父页面可用）。
- `npm test` 语音/守卫相关全绿；typecheck 0 错；build 通过。webviewPopup / webviewGuard / navigationGuard 6 测通过。

## 边界
- 弹窗是独立原生窗口（用户认可的 OAuth 体验）；共享 `persist:browser` 会话，cookie-based 与 postMessage 两种回传都支持。
- 普通 `target=_blank` 链接现在也开成弹窗（原来是同页导航），这是方案 1 的取舍。
