# 插件：用户装的 CLI 插件怎么用起来

用户可能在 Codex 或 Claude Code 里装过插件（Linear、Slack、Figma、GitHub、ChatCut…）。
它们**不是你自带的能力**，但一旦装了，你就能通过它们的工具真的去干活。

## 一句话判断要不要读这份

用户提到某个外部服务（Linear / Slack / Figma / Notion / GitHub / 剪辑…），
而你手上没有对应工具时 —— **先查插件装没装，别急着说「我做不到」**。

---

## 一、插件不是界面，是「工具 + 提示词」

这一条先说清楚，免得你答应用户做不到的事：

- 插件里**没有任何界面代码**（两个生态都一样）。它贡献的是 MCP 工具、skills、hooks。
- 所以**不存在「把插件打开成一个窗口」**。用户说「把 Linear 插件放到画布上」，
  他真正要的是「开一个能操作 Linear 的对话」。

**例外**：有些插件（如 ChatCut）自己配了一个 **Web 应用**。
那个界面不在插件里，是插件的工具会告诉你一个网址。
拿到网址后 → 用 `canvas_open_url` 把它开成画布节点（见 `canvas.md`），
用户就能一边看界面一边跟你说话。**这是「把插件变成画布上的模块」的唯一正确姿势。**

## 二、怎么知道装了什么

用户在画布上 **双击 Frame 空白处 → 「插件」选项卡**，能看到已装插件并直接开一个绑定它的对话。
这是给他用的路径，不是给你的。

你要查的话：

```bash
codex plugin list          # Codex 侧
claude plugin list         # Claude Code 侧
```

**只读，看看而已。**

## 三、绝对不许代跑安装命令

```
❌ codex plugin add <名字>
❌ claude plugin install <名字>
```

**理由和装 CLI 那条一样**：静默装全局软件 + 改用户配置，是恶意软件的行为特征。
正确做法是**把命令告诉用户，让他自己按回车**：

> 「你还没装 Linear 插件。在终端里跑 `codex plugin add linear@openai-curated`
> 装一下，装的时候它会让你授权登录。装完在 Frame 里双击 → 插件 → 选 Linear。」

删插件同理，`codex plugin remove` 也不许你代跑。

## 四、一次会话只带一个插件

**这是硬规矩，不是建议。**

已装插件可能有几十上百个。每个插件的工具定义都要进系统提示词，
全带上会把上下文撑爆 —— 参考量级：画板那 52 个工具让单轮输入涨了约 39k token。

所以：

- 一个对话节点只绑定**一个**插件（`pluginId`，开节点时就定了）
- 用户在同一个对话里说「顺便也用一下 Figma」→ **不能中途加**。
  MCP 配置是会话启动时定的，中途改不了。
  正确回答：「Figma 的工具不在这个会话里。要用的话在 Frame 里双击 → 插件 → 选 Figma，
  开一个新节点；这两件事也可以分开做完再对起来。」

## 五、两个 CLI 的差别（会影响你怎么回答）

| | Codex | Claude Code |
|---|---|---|
| 插件工具在对话里 | **自动就有** —— `codex exec` 不限制工具面 | 只有用户在「插件」选项卡里点选的那一个 |
| 元数据 | 齐全（图标、分类、默认提示词） | 只有名字和一句描述 |

所以：**在 Codex 会话里**，用户装过的插件工具你多半直接就能看到，
先看一眼自己的工具列表里有没有 `mcp__codex_apps__<插件名>__*` 这类，再决定说什么。

## 六、找不到工具时怎么说

**不要说「我不能」。** 按这个顺序：

1. 先看自己的工具列表里有没有相关的（名字里带插件名）
2. 没有 → 查插件装没装（`codex plugin list` / `claude plugin list`）
3. 装了但工具不在 → 说明这个会话没绑定它，让用户开一个绑定它的节点
4. 没装 → 给出安装命令，**让他自己跑**

**最忌讳的是「装了、你也说得出它的名字、但你回一句我没有这个能力」** ——
用户会以为软件坏了。
