# 生成图片 / 视频

这份文件是「要出图 / 出视频」的具体操作步骤 —— 完整生成顺序、报价确认、参考图、
改已配置节点、常见坑、模型选型、产物取回。SKILL.md 判断出用户要生成媒体后来读这份。

**它是自包含的，也是画板这条路径唯一的说明**：跟着它从头做到尾就能出图，
不需要另外去找别的文档。这是有意的 —— 它随 Eas-Term 分发、版本跟着 app 走。

## 要出图 / 出视频时

**默认走「笔纵画板」，不要去调别的图像 API，也不要自己写生成脚本。**

> ### 用户点名了别的生成 skill，就让路 —— 别抢
>
> 「默认」是指**用户没指定用什么**的时候。他明确说要用某个生成类 skill
> （`lovart-api`、或他自己装的其他生成 skill）时，**就用那个，别把他拽回画板**，
> 也别一边照做一边劝他改用画板。指定了就是指定了。
>
> **让路让的是「谁来执行」，不是「什么都能调」。** 让给的必须是用户点名的、
> 已经装好的那个 skill；「用户没点名」不等于「我可以随便找条路」——
> 没点名时的答案仍然是画板，而不是外部图像 API、也不是现装一个新的生图依赖。
>
> 两条路径都保留**生成前报价、等用户确认**这一条，谁执行都不豁免。

画板是另一个 app，它自带一个 MCP，名字叫 `bizone-canvas`（52 个工具）。
**你可以直接调它、全流程自己跑完**，不需要让用户去 app 里手动操作
（2026-08-19 核实：画板 1.21.26，直连可用）。用户装了画板的话，那些工具已经
自动配好在你的工具列表里 —— 调一次 `list_models` 就知道在不在。

| 情况 | 怎么办 |
|---|---|
| 工具列表里**没有** `bizone-canvas` 的工具 | 用户没装画板，或画板版本 < 1.21.20（更早的安装包里没带 MCP 依赖，一律连不上）。告诉他去 bzone.biily.top 装 / 更新，别自己找别的生图路子 |
| 调用报 `-32000 Connection closed` | 同上，多半是画板太旧；也可能是画板被改名或移出了 `/Applications` |
| `ECONNREFUSED 127.0.0.1:13140` | **画板没在跑**，仅此而已 —— 不代表这条路走不通。Eas-Term 配的通道会自动在后台把画板拉起来，等几秒重试一次；还不行就让用户手动打开它 |
| 报额度 / 余额相关的错 | 如实转达，让用户去画板里处理。不要试图绕过 |

### 一次生成的完整顺序

生成是**在画板的某个节点上触发**的，不是凭空出图 —— 所以要先有项目和节点：

```
get_workspace_overview         看有哪些项目、里面有什么节点（没有项目就 create_project）
list_models                    拿模型 ID。**别自己编 ID**，只能从这里挑
                               视频模型还要看 `modes[]` —— 决定参考图进不进请求的是它
add_node                       建一个节点，承载这次生成
generate                       写入参数 + **返回这次的报价**，不扣费
                               **节点连了图/视频/音频上游就必须传 `mode`**，见下面的陷阱一节
   ↓ 把价格报给用户，等他点头
generate_now                   真正开始，这一步才扣费
get_generation_status          轮询到 done（实测耗时见下）
```

**第一步别用 `open_project` 挨个切着看** —— 它会改变用户当前正在看的画布。
`get_workspace_overview` 是只读的，一次给全项目和节点，任何时候都能调。

### 报价 → 确认 → 生成（默认走这条）

`generate` 默认只写参数、节点停在 `idle`，这是画板防止 AI 擅自花用户钱的设计。
**但它会把价格一起返回**，所以报价和确认都在你这边完成，不用把用户赶回画板：

```
① generate(nodeId, modelId, prompt)  → 返回 estimate.credits，不扣费
② 你说：模型 X / 提示词大意 / 预计 686 墨水
③ 用户说「确认」
④ generate_now(nodeId)               → 开始，扣费
```

`estimate.credits` 用的是**和真实扣费同一个估价函数**，报多少扣多少（上游实测 686 → 686）。
多个节点就逐个 `generate_now`。

**实测耗时**（心里有数，别当成卡死）：

| | |
|---|---|
| `ac-gpt-image-2` high + 参考图 | 约 1–2 分钟 |
| `ac-nano-banana-pro` 4K | 约 5 分钟 |
| 视频 | 更久，4K 三五分钟很正常 |

**轮询频率没有任何限制** —— `get_generation_status` 是瞬时调用，随时可调，
**画板和 MCP 层都没有冷却或限流**。唯一要注意的是你自己怎么等：
如果你在 Claude Code 里跑，`sleep 120` 被打断**不是画板或 MCP 的限制**，
那是 Bash 工具的默认 timeout（可以传 `timeout` 参数，最大 600000ms；或者后台跑一个
`until` 循环，或者用 Monitor）。别因为它去把轮询拆成一堆短请求，
**更不要因为等得久就重新发起生成 —— 那会重复扣费。**

> **报价要画板 ≥ 1.21.26。** 更旧的版本 `generate` 返回里没有 `estimate` 这个字段 ——
> 那时别干等，退回下面「用户要在画板里核对」那条路，并提一句更新画板能在这里直接看到价格。

**`estimate` 有三种结果，含义完全不同 —— 中间那种最容易误判：**

| 返回 | 意思 | 你该怎么做 |
|---|---|---|
| `estimate.credits` 是数字 | 能报价 | 报给用户，等确认后 `generate_now` |
| `credits: null` + 带 `note` | **按用量计费，仍然可以生成** | 照实说「这个模型按实际用量计费，事先报不了价」，**别去换模型** |
| `estimate_error` 有值 | 真估不出来，`generate_now` 会拒绝 | 看它说的原因。**若是套餐过期 / 没墨水了，引导用户续费充值 —— 换模型没有用** |

> 中间那条是上游专门写出来的教训：早期版本把「配额耗尽」也归进这一类，
> 结果 agent 一路换模型换到底，其实是钱没了。现在真失败一定带 `estimate_error`。

另外两条路，各有明确的适用场景：

| 出口 | 怎么调 | 什么时候用 |
|---|---|---|
| **用户要在画板里核对** | `generate(...)` → `confirm_batch_generate()` | 他正看着画板、想在那边确认参数。**没人看着画板时别用** —— 没人去点，任务就卡死 |
| **无人值守** | `generate(..., autoConfirm: true)` | 确定没人在场。⚠️ **会真实扣费，且用户从头到尾看不到价格** |

有人在场就走上面的报价路径，让他先看到数字。

### 改已经配好的节点

想换个提示词重出，**不用重走整个流程**：

```
get_node(nodeId)        先看当前配的是什么：prompt / modelId / genParams
update_node(nodeId, prompt: '改后的提示词，可以继续用 @1')
```

`genParams.awaitingConfirm === true` = **已配置但还没触发生成**（节点停在 idle），
这时候要么 `confirm_batch_generate`，要么 `generate(autoConfirm: true)`。

对同一节点再调一次 `generate` 也行（覆盖旧参数），两种方式都不会重复扣费。
回执里那句「不要为了重试连续调用」说的是别拿它当重试机制，不是禁止改参数。

### 拿一张图当参考重新生成 —— 这里有两个必踩的陷阱

图片和视频**踩的不是同一个坑，解法也不一样**，别把一套用到另一套上：
图片是「连线 + prompt 写 `@1`」，视频在这之上**还必须显式传 `mode`**。
下面先讲两者共通的那一半，视频独有的那一半在本节末尾。

**❌ 看起来最像正确答案、实际无效的做法：**

```
upload_asset(...)  →  insert_asset_to_node(nodeId, assetId)   ← 名字百分之百像对的
```

`insert_asset_to_node` 设的是**节点自己的显示内容**，`generate` 根本不读它。
请求体会静默退化成纯文生图 —— 返回照样 `ok: true`，图也照样出，只是完全没参考你那张。
2026-08-19 连续两次栽在这上面，白花 196 + 138 墨水。

**✅ 正确做法：把参考图做成上游节点，再在 prompt 里点名它**

```
import_local_file({filePath, type})   → 得到图片节点 A
add_node(...)                          → 建生成节点 B
connect_nodes({from: A, to: B})        → A 成为 B 的上游
generate(B, modelId, prompt: '……参考 @1 的构图')   ← prompt 里必须写 @1
```

**怎么确认它真的带上了图**（三条判据，任意一条不成立就是没带上）：

1. `generate` 回执里 `targetMediaRefs` 含 `@1`
2. 回执里 `media_ref_map` 有 `@1`，且指向的确实是你那张图
3. **报价比纯文生图贵** —— 实测同一模型 138 → 179 墨水

第三条最好用：**业务侧的副作用比 API 返回值更可信**。
`ok: true` 只说明请求被接受了，说明不了语义对不对。价格没涨就是没带上图，别往下走。

> **判据 1、2 证明力比看上去弱得多。** 它们只说明**连线被认出来了**，
> 不是媒体进了请求体的证据 —— 上游 2026-08-26 专门澄清过这一点，
> 那次事故正是把「`media_ref_map` 有返回」当成了「图带上了」。
>
> **判据 3 只对图片有效，视频上直接失效**（视频漏图时价格一分不差）——
> 视频要用下面那条对照报价，别把图片这条经验搬过去。

---

#### 视频：连了线还不够，`mode` 才决定图进不进请求

**这是 2026-08-26 上游修正的一条，之前所有文档（包括本文早期版本）教的都是会丢图的做法。**

连线只让媒体成为**候选**，`mode` 才决定它进不进请求体。
**漏传 `mode` 时系统按该模型的第一个模式兜底 —— 视频模型第一个基本都是 `t2v`（纯文生），
参考图被直接丢掉，模型照着提示词凭空生成。**

**陷阱在于报价一模一样。** 2026-08-26 实测：纯文生 823 墨水、带参考图还是 823 墨水，
一分不差。**你无法从估价看出图没带上** —— 只能等成片出来，发现跟参考图毫无关系，
而那时钱已经花了。外部 agent 因此白烧了两轮。

**自检判据（唯一能证伪的）**：同节点换成纯文生模式再估一次价，
**价格没变 = 图没进请求**。

```
list_models(type: 'video')      看 modes[]，挑一个 inputs 里收 image 的
                                ⚠️ 看 modes[].inputs，不是模型级的 inputs ——
                                   模型级写着收 image，它的默认 mode 也可能只收文本
generate(nodeId, modelId, mode: 'i2v', prompt: '……')
                                    ↑ 漏了这个，图被丢掉，还照纯文生的价扣你钱
```

| mode | 收什么 | 用在哪 |
|---|---|---|
| `t2v` | 文本 | 纯文生视频 —— **完全无视所有图** |
| `i2v` | 文本 + 图 | 首帧驱动（有些模型收首帧+尾帧） |
| `ref` | 文本 + 图/视频/音频 | 参考生成，保持主体一致性 |
| `multi` | 文本 + 多个图/视频/音频 | 多模态（如 9 图 + 3 视频 + 3 音频） |

**mode 的 id 和各自收什么按模型不同，一律以 `list_models` → `modes[].inputs` 为准，
别照上表想当然。**

> **画板 ≥ 1.21.29 会硬拦这种组合**：报 `MODE_REJECTS_MEDIA_INPUT` 并列出可用的 mode；
> 成功时回传 `resolved_mode` / `mode_was_fallback` 供你自证。
> **但别指望这道闸门** —— 用户画板可能更旧，节点有媒体上游就老老实实传 `mode`。

### 八个会坑人的点

1. **上游连了媒体，prompt 里必须写 `@N` 指名**。≥2 个媒体上游而 prompt 里没有 `@N`
   会被**硬拦**（多图不指名模型会瞎猜）。`generate` 的回执里有 `media_ref_map`，
   照它对一遍 `@1` 到底是哪张图。**不要以为「上游连着就会自动当上下文」**。
   ⚠️ **视频还要再加一步 `mode`** —— 写了 `@N` 也只是让图成为候选，
   漏 `mode` 照样被丢掉，且报价看不出来。见上面「视频：连了线还不够」。
2. **`connect_nodes` 的参数名是 `from` / `to`**，不是 `sourceId`/`targetId`。写错会报
   `Cannot self-connect`（两个 `undefined` 被当成同一个节点）—— 报错方向完全是误导。
3. **改提示词用 `prompt` 字段，不是 `content`**。`update_node({content})` 会返回成功，
   但 `generate` 根本不读它 —— 改了等于没改，而且没有任何报错。
   ⚠️ **画板 1.21.21 及以前这条路整个不通**：传 `prompt` 会被静默丢弃、`get_node`
   也读不到当前提示词。症状是「改提示词总是失败」且毫无线索。**1.21.22 起才修好** ——
   撞上了先让用户更新画板，别在那儿反复试。
4. **prompt 用中文写**。不是硬拦截，但回执会带 `prompt_lang_warn`；而且用户在画板界面上
   要看得懂、能直接改。
5. **模型 ID 只能来自 `list_models`，不要凭记忆写。**
6. **有些模型对 prompt 有长度上限**（例如 MiniMax H3 是 7000 字符）。超了会被提前拦下，
   并告诉你要删多少字。
7. **`generate_now` 报 `not_configured`** = 节点参数丢了，重调一次 `generate` 即可，
   **不会重复扣费**。
8. **`blob:` URL 每次调用都可能变，不要缓存它** —— 一律以 `get_node` 的 `mediaFsPath` 为准。

### 意图 → 该调什么

上游文档里那张决策表，照抄要点（左边是你想干的事，右边是**常见的错法**）：

| 想干什么 | 调什么 | 别这么干 |
|---|---|---|
| **先摸清画板里有什么** | `get_workspace_overview()` —— 只读，一次拿全 | `open_project` 挨个切 —— **会改变用户正在看的画布** |
| 本地图片放进画板 | `import_local_file({filePath, type})` | `upload_asset({source:'path'})` 读不了任意路径 |
| 让 A 图当 B 的参考（**图片**） | `connect_nodes({from, to})` + prompt 里写 `@1` | 连了线但 prompt 不写 `@N` |
| 让 A 图当 B 的参考（**视频**） | 同上，**再加 `generate({mode:'i2v'})`** | 只连线不传 `mode` —— 图被丢掉，**报价还一模一样** |
| 挑一个收图的视频模型 | 看 `list_models` → `modes[].inputs` | 看模型级 `inputs` —— 它写着收 image，默认 mode 仍可能只收文本 |
| 改已配好的提示词 | `update_node({nodeId, prompt})` | 用 `content` —— 返回 ok 但无效 |
| 看当前配了什么 | `get_node({nodeId})` | 盲改 |
| **报价给用户** | `generate(...)` 读返回的 `estimate.credits` | 自己按模型猜价，或让用户去画板看 |
| **真的开始生成（默认）** | 报价 → 用户点头 → `generate_now({nodeId})` | 只调 `generate` 然后干等 —— 节点永远 `idle` |
| 真的开始生成（无人值守） | `generate({..., autoConfirm:true})` | 有人在场时用它 —— 用户看不到价格 |
| 真的开始生成（用户要在画板核对） | `generate(...)` → `confirm_batch_generate()` | 没人看着画板时用它 —— 没人去点，任务卡死 |
| **被拒说估不出价** | 看 `estimate_error`：套餐过期/没墨水就引导续费 | **换模型重试 —— 换哪个都一样** |
| 生成失败想重试 | 先 `get_node` 看 prompt，改完再触发 | 对同一节点连着调 `generate` |
| 想先知道用户够不够钱 | `get_user_billing_tier()` | 直接发起然后吃拒绝 |
| **`generate_now` 后秒回 `资源不存在`** | 先 `get_user_billing_tier` 看余额动没动（实测没扣）→ **直接换模型**，别动参考图 | 换 PNG/JPG、放大、换节点重试**同一个模型** —— 2026-09-03 `ac-nano-banana-pro` 连试 3 次都秒回，换 `ac-gpt-image-2` 一次就过 |
| 节点报错后想重跑 | **建新节点**，重新 connect + generate | 对 error 状态的节点 `generate_now` —— 会被 `not_idle` 拒掉 |
| 报了价、隔一会用户才点头，`generate_now` 回 `not_configured` | 对同一节点**再调一次 `generate`** 重写参数（不扣费），再 `generate_now` | 以为节点坏了去重建 |

### 挑哪个模型

`list_models` 拿到的是实时清单，**ID 只能从那里取**。选型经验（拿不准就按这个）：

| 场景 | 选它 |
|---|---|
| **改图 / 只改局部、保持原图** | `ac-gpt-image-2`（quality: low/medium/high）或 `ac-nano-banana-pro` |
| 高分辨率成品 | `ac-nano-banana-pro-ultra`（4k/8k）、`rhart-image-pro-ultra` |
| 写实人像 / 东亚面孔 | `ac-seedream-5-pro`、`seedream-v5-lite` |
| Midjourney 风味 | `youchuan-v7` / `youchuan-v6` / `youchuan-niji7`（二次元） |
| 纯文生图、快出草稿 | `z-image-turbo`、`qwen-2512` |

> 全局红线禁的是**绕开画板去调外部生图 API**。在画板内部用哪个模型
> （含 nano-banana / gpt-image 系）**是画板路径内部的事，不违规**。

**视频模型不在上表里** —— 视频选型的第一判据不是画风而是**这个模型有没有一个收图的 `mode`**，
只能现场 `list_models(type:'video')` 看 `modes[]`，没有可照抄的经验清单。

### 画板没开、又打不开时

只有在确认 `ECONNREFUSED 127.0.0.1:13140`（app 没在跑）**且用户不方便打开**时，
才退回「把提示词交给用户，让他自己在画板里贴」。格式：

```
【画板出图 · <用途>】
节点类型：image
建议模型：<按上面的表选>
画幅：<9:16 竖 / 1:1 方 / 16:9 横 / 3:4 长>

提示词：
<中文或中英混合的完整提示词>

要点：
- <构图 / 留白 / 文字位置等注意事项>
```

**这是降级不是首选。** 能直连就自己跑完 —— 把活推回给用户是最后一招。

### 生成完了做什么

**先把文件取回来。** `get_generation_status` 返回的 `mediaUrl` 是个 `blob:` 地址，
**读不了、也拷不走** —— 拿它去 `canvas_open_file` 只会卡住。真正的路径要另外取：


### 分寸

- **别替用户决定花钱。** 现在有报价路径了 —— `generate` 拿到 `estimate.credits`，
  **把数字告诉他、等他点头再 `generate_now`**。`autoConfirm: true` 跳过的正是这一步，
  只在确定没人在场时用。多轮迭代同理，每一轮都是一次扣费。
- 用户只是问「能不能生成 X」时，先回答能不能，**别直接就开始生成**。
- `list_models` 拿到一次就够，别每次生成前都列一遍。
- 画板刻意没开放 `run_shell_command` / `get_api_keys` / 联网抓取这些能力，
  那是有意为之，别去找绕路。

## 跟别的生成路径的关系

开头那条「点名了就让路」是规则，这里是**具体都有哪些路、各自谁执行**。

| 路径 | 何时走 | 谁执行 | 计费 |
|---|---|---|---|
| **笔纵画板**（本文） | 用户**没点名**别的时候的默认 | 你直接跑（画板 app 要开着） | 画板墨水，**生成前报价等确认** |
| **`lovart-api`** | 用户**明确点名** Lovart | 你直接跑 | Lovart credits，**生成前报价等确认** |
| 用户自己装的其他生成 skill | 用户明确点名它 | 按那个 skill 自己的说明 | 按它自己的 |

**两件事别搞混：**

- **画板 app 内部也有一套 Lovart 集成**（builtin `lavar` MCP 插件 + Lovart 专属 Agent，
  走 app 内对话转交）。它和 Claude Code 侧的 `lovart-api` skill **是两条独立链路，
  但共用同一个 Lovart 账号和 credits**。用户说「用 Lovart」时指的是后者。
- **让路是让「谁来执行」。** 不管走哪条，「生成前把价格讲清楚、等用户点头」都不豁免；
  而没人点名时的默认答案仍然是画板 —— 不是外部图像 API，也不是现装一个新的生图依赖。

### 提示词规范去哪查

**这一节是给画板开发机用的**：下面这些 skill 在画板的源码仓库里，
装了画板 app 的机器上**没有**。找不到就跳过，不影响出图 ——
本文的提示词写法已经够用，那些是要做整套物料时才用得上的体裁规范。

| skill | 体裁 |
|---|---|
| `bizone-poster` | 单张海报（听需求 5 问 → 主视觉简报 → 出图 → 迭代） |
| `bizone-brand` | 品牌系统（logo / 配色 / 字体，比海报大一级） |
| `bizone-storyboard` | 分镜叙事（多图连续） |
| `bizone-director` | 导演视角的整体调度 |

中文字效 / 艺术字另有一套提示词库（12 类风格），风格选型先走 `design-router` → `visual-router`。
这两样同样只在配了那些 skill 的机器上有。
