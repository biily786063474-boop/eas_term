# 过程记录 · css-dup-auditor

任务：审查 `src/renderer/src/` 全部 CSS 的重复选择器定义，判定无害/危险，只读不改。

## 做法

1. **枚举范围**：`find src/renderer/src -name "*.css"` → 23 个文件，17,825 行。
2. **写解析器**（`parse_css.py`）：不用正则硬扫，写了一个带状态机的 CSS 解析器 ——
   - 剥注释时用空格替换但保留换行，行号才不会漂
   - 跟踪 at-rule 上下文栈（`@media` / `@supports` / `@keyframes`），
     否则 `@media` 里的 `.foo` 会和顶层 `.foo` 被当成重复（那是正常的响应式覆盖）
   - 逗号分组的选择器逐个拆开归一化（`.a, .b {}` 记成两条），
     否则 `.a, .b {基础}` + `.b {特化}` 这类最常见的形态根本发现不了
   - 只取块内**顶层**声明，嵌套块的属性不算进来
   产出 `entries.json`，2,717 条记录。
3. **校验行号**：拿每条记录的选择器关键片段回源文件比对，2717 条中仅 4 条"不匹配"，
   人工确认都是跨 6 行以上的长逗号选择器列表，行号本身正确。
   > 第一版解析器行号系统性偏小（`.ac-input-send` 报 1350、实际 1354）——
   > 原因是换行符被压进了 selector 缓冲区，导致空白行没有重置起始行号。修掉后归零。
4. **三层判据**：
   - a) 同 context 同选择器 → 68 组
   - b) 后一份是否与前一份**改同一批属性**（重叠属性集）
   - c) **补的第三层**：后一份若"整块重写"（覆盖了前一份 ≥50% 属性），
     则前一份**没被重写的属性会残留** —— 这一层单独跑出了 4 个候选，
     `.ac-input-send` 事故就是这个形态，只看 b) 会整个漏掉
   - d) 值级别比对 `position/display/visibility/opacity/transform/flex-*` —— 全库只有 1 组命中
5. **逐条人工核对**：所有 P1/P2 都回源文件读了上下文注释，并回 `.tsx` 确认了实际使用点。
6. **加载顺序做了实证**：不是靠推断 —— 直接在打包产物
   `out/renderer/assets/index-DUq0jRaF.css` 里量各文件段的字节偏移，
   确认 `base.css` 在最后（366093 起），`glow.css` 在它之前（358687–366093）。

## 排除的误报

- `@keyframes` 里的 `0%` / `50%` / `from` / `to`：跨文件比对时报了 5 组、涉及 13 个文件，
  但它们分属不同动画名，按 at-rule 上下文剔除后归零。
- 顶层 `.foo` 与 `@media` 里的 `.foo`：正常的响应式覆盖，按 context 分组时天然分开。
- `@keyframes` 同名重定义：单独查过，**没有**。

## 结论

68 组里 5 条要修（2 条 P1、3 条 P2），10 条建议合并（P3），其余 ~50 组是惯用安全形态。
最重的一条 —— `.ac-bar-send` —— 与本轮 `.ac-input-send` 事故是**同一个形态**：
同一个按钮先后写了两遍，前一份留在原地，其中 `opacity: 0.4` 逃逸出来，
把 500 行外注释里写明的设计意图推翻了。
