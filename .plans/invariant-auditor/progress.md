## 判定口径（怎么算「被测试兜住」）
一条教训注释算被兜住，要求：**把这条不变量按注释警告的方式改坏，`npm test` 会变红。**
- 「同一目录有 test 文件」不算 —— 逐条比对了测试用例名与断言目标
- 「有端到端/CDP 验证记录」不算（那不是回归网，重构时不会自动跑）
- 纯说明性注释（解释为什么这么设计、不含可执行判据）不计入清单

## 可测性分级（决定建议的形态）
- **A 级**：模块 import 干净（无 electron/react/fs），写个同名 `.test.ts` 就能跑，零改动
- **B 级**：不变量本身是纯函数，但所在文件 import 了 electron —— 需要先按项目既有惯例
  把它抽到独立文件。**这个惯例项目里已有 6 处先例**：`sessionPaths.ts` / `projectPaths.ts` /
  `snapshotPaths.ts` / `wiki/paths.ts` / `legacyDshCleanup.ts` / `canvas/viewModeRestore.ts`
  —— 全都是从带 electron 依赖的大文件里抽出来的纯逻辑 + 同名 test
- **C 级**：平台行为 / 真实时序 / 真实鼠标，单测测不到 —— 清单里单独列出并明确劝退，
  避免照着补一堆假测试
