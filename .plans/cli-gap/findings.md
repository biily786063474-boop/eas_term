# AI 对话窗口相比终端里的 CLI，缺了什么

派出去的 agent 没等到确认（清单挂了 9 分钟），这份是主 agent 自己做的。
方法：`claude --help` 的 54 个参数逐条对照 `adapters/claude.ts` 实际拼的 11 个，
外加界面侧能力的代码核对。

## 已经有的

| 能力 | 怎么实现的 |
|---|---|
| 流式输出 | `--include-partial-messages` + claudeEvents 的 text.delta |
| 会话恢复 | `--resume <resumeId>`，随 canvas.json 落盘 |
| 切模型 / 思考强度 | `--model` / `--effort`，中途切走 slash |
| 图片输入 | 粘贴与拖入都支持（ChatToolbar 的 pics.takeFiles） |
| 审批保护 | hook 装载 + 「先问再做」的系统提示两条路 |
| 输出格式约定 | `--append-system-prompt`（不用 emoji、标题最多三级…） |
| MCP 工具 | `--mcp-config`（2026-08-20 才接上，之前是零工具） |
| 斜杠命令候选 | 2026-08-20 新增，含已装 skill |
| 上下文用量 | `/context` 可用；工具栏也有压缩入口 |

## 缺的，按「多常碰到 × 补起来多难」排

### 推荐先补的三条

**① 中断正在跑的回答** —— 终端里按 ESC 就停，这个窗口**只能干等**，
或者去团队面板把整个会话停掉（那会连上下文一起丢）。
一次答偏了就得等它说完，长任务里尤其难受。
现在连个「停」的按钮都没有 —— 代码里搜不到任何 interrupt / abort 路径。

**② 工具护栏用 `--disallowedTools`** —— 现在的护栏靠审批 hook（问一次），
而这两个参数是**能力面级别**的：直接不给某些工具。
用户明确要求过「用户不能影响本来软件的功能」，这是比 hook 更硬的一层，
而且刚接上 MCP，工具面比以前大了。

**③ `@` 文件引用** —— 终端里打 `@` 能补全项目文件路径，这里没有。
使用频率高，实现上和刚做的斜杠候选是同一套（SlashPicker 可以复用）。

### 其余（有价值但不急）

| 参数 / 能力 | 是什么 | 为什么可能有用 |
|---|---|---|
| `--session-id <uuid>` | 指定会话 id，而不是让 CLI 自己生成 | 比 `--resume` 更可控；接管、重连的逻辑能简化 |
| `--fork-session` | resume 时另开一个会话 id | 「从这里分个岔试试」——现在只能整个新开 |
| `--add-dir` | 额外允许访问的目录 | 跨项目引用时不用改 cwd |
| `--agents <json>` | 传入自定义 agent 定义 | 团队角色可以直接给定义，不必靠首条消息交代 |
| `--autocompact` | 自动压缩窗口大小 | 现在压缩全靠人点 |
| `--settings` | 指定 settings 文件 | 隔离配置，验证环境尤其有用 |
| `--bg` | 起成后台 agent（`claude agents` 管理） | 跟我们自己的 team 机制重叠，要想清楚再动 |
| `--plugin-dir` | 加载插件目录 | 用户装了插件的话现在用不上 |

## 边界

- **只盘了 Claude。** Codex 那侧没做同样的对照。
- 「缺」的判据是代码里搜不到对应实现；`@` 引用和中断这两条我确认过没有，
  其余是按参数没被拼进去推断的 —— **没实测每一条在 headless 下的实际行为**。
- 没有评估实现成本，只按「用户多常碰到」排序。
