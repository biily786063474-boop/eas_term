# 整理 skill 分类

这份 skill 和 Eas-Term 里的 skill 面板模块是**一起维护**的：
工具定义在 `mcp/eas-mcp.mjs`，执行在 `src/renderer/src/mcpHandler.ts`，
落盘与校验在 `src/main/skillLibrary/`。
**那边改了参数或语义，这份必须同步改**（对照表见 `src/main/skillLibrary/README.md`）。

## 只有两个工具

| 工具 | 干什么 |
|---|---|
| `skill_list` | 读全量：所有目录里的 skill，带绝对路径、简介、当前分类、有没有被临时禁用 |
| `skill_categorize` | 写回一批分类 |

没有「删除分类」的工具。要把一个 skill 从某个分类里拿出来，就把它重新分到别的分类去。

## 流程

1. **先调 `skill_list`**。不要去 shell 里 `ls ~/.claude/skills` ——
   用户可能把 skill 搬到了别的目录（这台机器上就有 `design-skills` / `motion-skills`
   两个非默认目录），面板认的目录集合只有这个工具知道。
2. **看 description 分类，别看目录名**。目录是用户的物理组织方式（有时就是按渐进式披露
   拆的），分类是他要的**语义**视图，两者不必一致。
3. **想好整批再提交**，一次 `skill_categorize` 调用带上所有 assignments。
4. 提交完用一两句话告诉用户分了哪几类、每类几个，**不要把整张表复述一遍**——
   他抬头就能在面板上看到。

## 硬规矩（违反会被整批拒绝）

- **分类是扁平一层，不能嵌套。** 没有「设计 / 品牌」这种写法，就叫「品牌」。
- **一个 skill 只属于一个分类。** 同一批里把同一个 skill 分到两个不同分类 → 整批拒绝。
- **`skill` 字段必须原样抄 `skill_list` 返回的 `path`**（skill 目录的绝对路径，
  它就是这个 skill 的唯一 id）。自己拼路径、写 skill 名字、写目录名，都会被判成
  「这个 skill 不存在」→ **整批拒绝**，不是丢掉那一条。
  被拒时错误信息里会点名是哪几条，照着改再提交。
- **分类名**：非空、不超过 40 个字、不能含换行。用中文短词。
  不能叫「未分类」——那是没分类时的默认显示，不是一个可以主动分进去的类。
- 一次最多 300 条。

## 分类怎么起名

目标是**用户扫一眼就知道该展开哪一组**，不是分类学上的严谨。

- 3-7 个分类比较舒服。分到 15 类等于没分。
- 名字用他自己的说法。他管那堆叫「影像」就别写成「视频制作」。
- 剩下三五个凑不成一类的，不用硬塞——不提交它们，它们自动留在「未分类」那一组里。
  **强行给每个 skill 都安一个分类，比留几个未分类更糟。**

## 不要做的事

- **不要改用户的 skill 文件。** 分类不是往 SKILL.md 里加 frontmatter 字段，
  是写 Eas-Term 自己的配置。你也不该为了「让分类更准」去编辑任何 SKILL.md。
- **不要动禁用状态。** `skill_list` 里的 `disabled` 只是让你知道哪些被用户划掉了
  （被禁用的 skill 照样要分类，它还显示在面板上）。没有改禁用状态的工具，
  那是用户自己在面板上右键的事。
- **不要因为某个目录读不出来就停下。** `skill_list` 会在 `unreadableDirs` 里报出来
  （比如 `~/.codex/skills` 根本不存在）。把能分的分了，末尾提一句哪个目录没读到。

## 手动分类不许覆盖（2026-08-18）

用户可以在面板里自己建分类、把 skill 拖进去。**他手动定过的 skill，你改不动** ——
`skill_categorize` 会静默跳过它们，并在返回的 `skippedLocked` 里列出被跳过的路径。

看到 `skippedLocked` 非空时，**如实告诉用户哪几个没动、为什么**，不要报成「全部整理完毕」。
用户想让你重排某个被锁的 skill，让他在面板里把它拖回「未分类」——那个动作会解锁，
之后你就能管它了。
